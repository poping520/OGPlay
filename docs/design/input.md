# 输入映射

输入子系统把宿主键鼠、触摸和手柄事件转换为一个逻辑 Android 输入流。
HAL 读取设备，input 保存映射与触点时序，session 编码 Android 事件，
WMS 负责窗口命中，ROM View 层级决定树内分发。
逻辑 surface 是 guest 看到的输入平面，它的坐标与宿主窗口像素分别管理。

玩家可以直通鼠标触摸，也可以用用户区域把键盘映射为虚拟按钮或摇杆。
[通用映射决定](../adr/session.md#adr-0133)选择用原语组合表达差异，
使映射只产生普通触摸与按键，而不读取游戏内存或绕过 View 调用。
代价是用户需要维护适合自己界面的区域和参数。

## 一次触摸怎样到达 View.onTouchEvent

```text
SDL / HAL 设备事件 ─┐
用户按键绑定 ──────┼→ ControlMapper → ControlOutput → session
MCP 外部触点 ──────┘                                      ↓
                                       WMS 命中 / 通道 / 手势捕获
                                                        ↓
                                  ROM ViewRootImpl → ViewGroup → View
```

以内容区内按下鼠标主键为例，前端先把宿主位置转换为 guest 逻辑坐标，
ControlMapper 记录物理源状态，在 guest 帧边界产生 DOWN。
session 编码 Android action，WMS 选定窗口并捕获手势，
InputEventReceiver 把通道事件交给 ROM，最终由 View 树决定是否调用某个 View 的 onTouchEvent。

后续拖动和抬起沿同一个触点身份与目标窗口交付。
ViewGroup 可以按 ROM 规则拦截并向旧目标发送 CANCEL，宿主映射器不需要知道哪一个控件被点击。
如果直接在宿主模拟 View 点击，就会绕过滚动容器、拦截和取消协议；
保留完整事件流，下层窗口与输入通道就要提供真实语义。

## 坐标与设备捕获

内容区可能被 letterbox 包围，呈现尺寸也可能与逻辑尺寸不同。
坐标变换集中处理，配置中的区域按 surface 锚点与相对偏移解析，
区域自身锚点决定其哪一点落在目标位置。
布局在启动或重配置时验证，避免首个按键才发现区域越界。

鼠标主键的手势从有效内容区起手；拖出内容区后夹紧坐标并继续交付 release。
宿主 finger 身份映射到稳定的触点编号，触点编号是 Android 区分同一手势各手指的编号。
同一次捕获不混入无关设备或悬停事件，
这样窗口外释放、多个物理来源与逻辑触屏之间不会留下按住状态。

显示旋转或 surface 尺寸变化先取消 guest 手势，再清理映射并重新解析区域。
直接把旧触点搬到新坐标会形成应用没有收到 DOWN 的位置跳变，
所以取消比继续猜测用户意图更容易保留输入协议。
窗口在 UP 前进入后台时同理：上层先向 guest 交付 CANCEL 和必要按键释放，再清空 mapper。
仅清宿主状态会让 ROM 或应用继续认为手指仍按住；
只发 CANCEL 不清物理映射，又可能在恢复时凭旧状态重新按下。
两边都闭合后，旋转、失焦或后台恢复之后需要重新按下。

## 为什么按 guest 帧输出

ControlMapper 的 Accept 只记录宿主事件，Flush 每 guest 帧生成一次 ControlOutput，
也就是与 Android 编码无关的通用触摸和按键结果。
同帧 motion 可以合并，输出按按键、MOVE、UP、DOWN 的既定顺序交付。
这让高频宿主鼠标事件与游戏按帧采样之间有稳定边界。

合成 DOWN/UP 至少相隔一个 guest 帧，避免同帧按下又抬起被游戏完全忽略。
例如一个 tap 绑定收到物理按下后，先登记待起手动作；当前 Flush 发布 DOWN，
后续 Flush 才发布 UP。即使宿主在两次 guest 帧之间已经收到物理 release，
应用仍能观察到按住阶段。

```text
宿主事件： press ─ release
Flush 1：  DOWN
Flush 2：  UP（快照仍含离开的触点编号）
Flush 3：  该身份可重新分配
```

UP 快照仍包含离开的触点，下一快照才移除身份；
触点编号从空闲集合分配，存续期间保持稳定。
hold、repeat、stick 和捏合另有各自时序，但输出都来自同一逻辑触屏：
宿主触摸、绑定与 MCP 共用同一触点预算，溢出明确拒绝而不挤掉已有手势。

按帧输出增加了可控的输入阶段，而不是承诺宿主事件到达即刻调用 guest。
这是[通用输入决定](../adr/session.md#adr-0133)对帧时序的选择，
精确容量和顺序见 [input 契约](../../src/input/MODULE.md)。
手动步进没有许可时，输入也不会偷偷推进。

Reconfigure 先用新配置完成解析和 surface 校验，成功才取消旧触点及直通按键。
错误配置因而保留旧布局。Reset 则用于上层已经取消 guest 输入后的本地清空，
两者的不同职责避免“为了换配置先破坏旧配置”的半完成状态。

## 原语怎样组成常见操作

button 将物理源映射为区域内 tap、hold 或 repeat，key 产生 Android keycode，
stick 把方向键组合变为固定原点的触摸拖动。
mode 提供 toggle 或按住叠加层，look 把相对鼠标位移变为视角拖动，
lock 控制宿主相对指针捕获。这些原语只描述输入动作，不识别游戏场景。

例如按下方向键时，stick 先在原点按下并停留，再逐帧移动到方向位置；
换向沿同一渐进曲线，而不是瞬间跳到另一侧。
按帧采样的游戏需要看见起手原点和移动过程，才能识别触屏摇杆。
settle 与 ramp 会增加起手时间，用户可按通用参数调整，精确默认值见 MODULE。

未绑定键直通，已直通按下的源其 repeat 与 UP 继续直通。
绑定在新的按下时接管，切模式停用的绑定立即释放，重新按键后才在新模式生效。
这样模式切换不会偷走一个已开始的序列，
但按住按键切模式时不会自动在新模式创建触点。

## 用户配置为什么与 Profile 分开

配置合并内置默认与用户 input.toml。
内置提供鼠标/触摸直通、Esc→Back 及相应默认手势，
用户定义区域、绑定和参数；GUI 为每个安装实例明确传入配置路径，
裸 CLI 可用 `--input-config` 或对应沙盒侧配置。

[用户数据决定](../adr/session.md#adr-0142)不把私人键位放入精确游戏 Profile，
也不提供需要项目维护的官方坐标布局。
同一 APK 可以有不同尺寸、玩家习惯与输入设备，
因此安装实例的用户配置比按游戏名写分支更适合表达这些差异。

区域与 binding 分别描述几何和物理源。
未知区域、越界与同模式源冲突在解析时失败，通配模式也参与冲突检查。
文件读取可跳过兼容范围内未知键，编辑器 JSON 请求使用 closed schema，
即只接受明确声明字段的格式。缺文件视为空用户层，保存使用原子替换。

用户层因此需要完整校验和往返格式化，而不是让 GUI 自由拼配置文本。
schema 与具体字段由 [session 契约](../../src/session/MODULE.md)维护，
本篇不重复维护一份格式规范。

## 滚轮与触控板怎样合成捏合

未被当前绑定接管的滚轮在内容区合成双指捏合。
主指位于光标处并保持位置，副指选择空间足够的一侧，
间距按 surface 比例计算并逐帧移动。
触控板 pinch 复用同样几何，begin、update、end 保留宿主手势阶段。

这样应用看到普通双指输入，而不是宿主直接修改某个缩放变量。
代价是合成捏合也占用触点身份，并要处理边界和中断：
仅在没有其他触点时起手，鼠标直通、宿主触摸或外部触点到来时先结束捏合，
已中断触控板序列的后续 update 不重新插入第三指。

到达几何限位时按抬起、后续帧重新起手处理，
当前模式只要绑定任一滚轮方向，该模式滚轮就只走绑定。
未绑定的另一方向也不同时进入内置捏合，
避免一次滚动既触发按钮又改变应用视角。

## look、交接与指针锁定

look 在区域中心起手，相对位移乘各轴灵敏度后累积为 guest 像素，可反转 Y。
每帧移动与待处理余量有上限，丢弃超出余量可让鼠标停下后一两帧内停止，
而不是继续消费长队列产生漂移；宿主输入过密时也就不会逐个保留全部位移。

到达边界后，single 先抬起再在后续帧重新按下；
handoff 用新身份先起手，在新指开始移动时移除旧指。
同帧复用触点编号容易被按帧采样引擎合并成跳回，
保留交接阶段可以表达连续拖动意图，但 handoff 会暂时使用两个触点。
具体时序来自当前 [input 契约](../../src/input/MODULE.md)。

WantsRelativePointer 汇总活跃 look 与用户锁定状态，前端据此向宿主请求捕获。
宿主拒绝会记录警告；Esc 和 release_pointer 放开指针，
放开期间暂停 look 并让出鼠标直通和内置捏合。
后台、编辑冻结和失败也释放宿主捕获，避免游戏不再推进时仍占住用户指针。

## 提示、编辑器与原子应用

F1 提示从当前已解析布局读取有效区域和源，
不另维护一份坐标计算，也不向 guest 注入输入。
指针放开时，只由鼠标驱动且当前让出的区域不显示，
使提示反映当前模式实际可用的绑定。

按键编辑器通过随机令牌保护的 loopback control.* 通道工作。
编辑页面可以在网络线程收到新区域时立即完成 JSON 解码，
但活跃 mapper 可能同时正在生成本帧输出，所以网络 worker 只排队。
freeze 由主循环取消活动输入并冻结推进，再提供最近帧；
apply 在主循环边界复用同一解析与校验，失败时保留旧配置，成功后原子保存用户层并应用。
这给“改完即试”一个明确的生效边界，编辑服务忙碌时也不能宣称已经应用。

冻结不合成 Android pause/resume，因为这只是编辑输入布局，
不应让游戏误以为 Activity 发生生命周期变化；
截图来自最近完成帧，冻结不为了取图再推进游戏。
恢复后重新按键才产生触点，用户原先按住的动作不会自动延续。
设计理由见[编辑器决定](../adr/session.md#adr-0133)。

## 与窗口、文本和验证的边界

ControlMapper 只知道逻辑触点，不知道 View 命中。
WMS 管窗口捕获，ROM 管树内分发，Java MotionEvent 与 NDK AInputQueue 使用相同样本。

触摸与文本使用不同通道。触点携带位置、动作与身份，View 树据此决定目标；
文本输入则依赖当前可编辑对象的连接与 composing 状态。
把 SDL 文本拆成键位或直接追加到某个字符串，都会绕过 ROM 输入连接的光标和编辑协议。
因此键位映射只产生普通输入，文本和 composing 由 IMMS 的活跃输入连接处理，
两条路径在 ROM 当前界面中各按原协议汇合。
当前未覆盖完整输入法会话，也不由通用 key 原语承诺。

通用映射已经实现，并不代表每个平台的手柄、触控板和相对鼠标都已实跑。
未验收范围见[已知问题](../state/KNOWN-ISSUES.md#title-validation)，
操作与复现继续使用现有 MCP 手册。
