# 03 · 界面与交互

## 1. 主窗口

单窗口、单视图，无多级导航：

```
┌────────────────────────────────────────────────┐
│  OGPlay          [ 导入游戏 ]        [ 设置 ]   │
├────────────────────────────────────────────────┤
│  ┌──────┐   ┌──────┐   ┌──────┐                │
│  │ icon │   │ icon │   │ icon │   …磁贴网格…   │
│  │      │   │  ▶   │   │  ⚠   │                │
│  └──────┘   └──────┘   └──────┘                │
│   名称A       名称B       名称C                 │
└────────────────────────────────────────────────┘
```

- 磁贴：固定尺寸图标（源图导入时归一化）+ 单行名称（超长省略号，悬停
  显示全名）。排序固定为名称字典序，无自定义排序（非目标）。
- 磁贴状态角标（互斥，优先级从高到低）：
  1. **条目损坏**（meta 不可读/包名不一致）：仅可删除。
  2. **缺 Profile**（导入时未匹配到精确 Profile）：不可启动。
  3. **缺数据包**（Profile 声明必需 external，条目无 `external_dir` 或
     路径已不存在）：不可启动。
  4. **运行中**：子进程存活期间显示。
  5. 无角标：可启动。
- 空库时网格区显示引导文案与"导入游戏"按钮，不留空白。

## 2. 启动流程

1. 点击可启动磁贴 → 模型层装配 `LaunchPlan`（argv 表见 [04 §2](04-integration.md)）
   并做启动前校验：`config.toml` 的 `system_dir` 已设置且存在、
   `game.apk` 存在、`external_dir`（若有）存在。任一失败 → 弹窗给出
   **缺什么、记录的路径是什么、去哪修**（设置页/重新导入），不启动。
2. 校验通过 → spawn 子进程，磁贴转"运行中"；主面板不冻结，可继续操作
   其他条目。stderr 重定向覆盖写 `last-run.log`。
3. 子进程退出：
   - 退出码 0 → 磁贴回到常态，无打扰。
   - 非 0 → 磁贴短暂标注失败，弹窗显示退出码、stderr 尾部若干行与
     `last-run.log` 完整路径；文案明示"这是游戏兼容性问题的证据，
     可随 issue 提交"。主面板不解析日志内容做二次判断。
4. 不可启动磁贴（缺 Profile/缺数据包）点击 → 弹窗解释原因与下一步
   （等待题库收录 / 重新导入并指认数据目录），不静默忽略点击。

## 3. 导入流程

三步向导（模态）：

1. **选 APK**：系统文件对话框（过滤 `*.apk`）。选定后后台线程执行
   只读解析：manifest 身份（package/version）、精确 Profile 匹配、
   图标与名称提取（[02 §5](02-architecture.md)）。解析期间显示进度，
   完成前不可进入下一步。APK 不可读/非 ZIP/manifest 解析失败 → 本页
   直接给出失败原因，向导不推进。
2. **摘要与数据包**：展示图标、名称、包名、版本、Profile 匹配结果。
   - 匹配 Profile 且其声明 external mount → 显示"该游戏需要数据包"
     与目录选择按钮（系统目录对话框）；用户可跳过，跳过则条目将带
     "缺数据包"角标入库。选定目录只做存在性与可读性校验并提示
     "该目录将被原地引用，请勿移动或删除"；不做内容清单校验
     （数据完整性由 `run-apk` 启动时的既有 required-input 校验兜底，
     缺失走启动失败路径，信息同样可读）。
   - 未匹配 Profile → 如实显示"暂不支持此游戏（无精确 Profile）"，
     仍允许入库（角标"缺 Profile"），文案说明入库后待题库收录即可玩。
   - 同 package 已在库 → 本页明确失败，提示先删除既有条目。
3. **确认**：复制 APK 入库、写 `meta.toml` 与 `icon.png`。写入原子性：
   先写临时目录再整体 rename 到 `library/<package>/`，中途失败不留半成品
   条目。完成后网格即时刷新。

## 4. 删除流程

磁贴右键（或选中后的删除按钮）→ 确认对话框，文案必须写明两点事实：

- 将删除：库内 APK 副本、元数据、图标缓存、`last-run.log`。
- 不会删除：原地引用的数据包目录（显示其路径，若有）。

确认后整目录删除 `library/<package>/`；运行中的条目禁止删除（先退出
游戏）。本方案期内条目尚无存档（ADR-0020 未实施）；沙盒落地后删除
流程需增加"是否连同存档删除"的决策，届时按 [05 §4 风险](05-verification.md)
预留的接口扩展，不在本期实现。

## 5. 设置页

模态页，仅两项，均为目录选择器 + 存在性校验，写回 `config.toml`：

| 项 | 对应 | 默认 |
| --- | --- | --- |
| Android 系统库目录 | `run-apk --system-dir` | 空（未设置时启动前校验拦截并引导至此） |
| Profile 目录 | `run-apk --profiles-dir` | 空 = 使用 `run-apk` 内置默认（仓库 `data/profiles/`） |

库根路径在设置页只读展示（改库根走 `--library-root`，面向测试）。

## 6. 错误呈现原则

- 每条用户可见错误 = 模型层结构化错误码 + 参数渲染，同一事实同时进
  结构化日志；禁止"打条日志就算处理了"（roadmap 09 §11 同则）。
- 每个失败弹窗必须包含**可执行的下一步**（去设置、重新导入、查看日志
  路径），不允许裸"操作失败"。
- 后台任务（导入解析、子进程等待）出错不得丢失：结果必须回到 UI 主循环
  呈现，无一次性 toast 即消失的关键错误。
