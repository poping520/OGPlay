# Launcher · 主面板（游戏启动器）方案设计

本目录是 OGPlay 主面板（GUI 游戏启动器）基础版的完整设计，写给两类读者：
**决策者**（评审方案）和**实施阶段的 AI**（作为该能力开发的长期上下文根节点）。

要解决的用户问题只有一句话：**目前只有 CLI，非技术用户无法导入并启动游戏。**

GUI 技术选型（SDL3 + Dear ImGui）已写入 roadmap
（[01 §9](../../roadmap/01-architecture.md)、[06 §3.1](../../roadmap/06-user-experience.md)），
本设计不再重复论证选型，只回答"怎么落地"。

## 效力声明

- 本方案只覆盖**基础版**：游戏库网格（图标 + 名称、点击启动）、导入
  （APK + 可选数据包）、删除、必要设置。roadmap [07 M7](../../roadmap/07-roadmap.md)
  的完整用户体验（乱结构自动归位、输入映射编辑器、兼容性徽章、存档管理）
  在本方案之后按 M7 任务推进，不属于本方案范围。
- 本方案**不改变**项目元规范：AGENTS.md 的工作流约束（WU 有界、机器可判定
  测试、能力记账、明确失败、结构化日志、`src/` 零游戏名分支）
  对 GUI 全部适用。
- 实施启动后，代码与 `MODULE.md` 契约逐步接管，本目录转为设计溯源。

## 一句话架构

> 主面板是一个独立的 SDL3 + ImGui 进程，产品入口为可双击的 `ogplay-gui`
>（macOS 为 `OGPlay.app`；`ogplay gui` 子命令供开发与测试）。它只做三件事：
> 维护"每 package 一个目录"的游戏库、把导入的 APK 交给既有的精确身份/Profile
> 匹配得出可否启动的事实、点击启动时 spawn 自身的 `run-apk` 子进程。
> 它不拥有任何内核行为——游戏的加载、校验、运行完全走已受检的 CLI 同一路径。

## 术语

| 术语 | 含义 |
| --- | --- |
| 主面板（launcher） | GUI 进程呈现的游戏库窗口，唯一面向非技术用户的入口；双击 `ogplay-gui` 启动 |
| 游戏库（library） | 宿主上"每 package 一个目录"的持久存储，键为 APK package name |
| 库条目（entry） | 一个已导入游戏：APK 副本、元数据、图标缓存、数据包引用 |
| 数据包 | 游戏外置数据目录（OBB/厂商目录等），对应 `run-apk --external-dir` |
| 模型层 | 不依赖 ImGui 的纯逻辑（库存储、导入、参数装配），全部可 CTest |
| 视图层 | ImGui 即时模式绘制代码，每帧从模型层读事实，不持有业务状态 |
| 占位图标 | 图标提取链任一环失败时使用的内置默认磁贴，失败原因进结构化日志 |
