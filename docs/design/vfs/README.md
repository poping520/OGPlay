## 1. 结论与范围

需要一次有界的结构调整：保留唯一 VFS 和现有文件语义，将“首次读取即整文件物化”
改为按来源选择 backing、按区间读取。长期目标是让 Java/native 文件读取和媒体资源
共用来源身份、寿命与预算，避免消费者各自复制一份文件系统。
同时将持久沙盒改为按安装实例隔离，采用可读短目录；同包多个副本各自保存数据和设备身份。

只组织 **两个实现单元 + 一个集中验收单元**，见 §5；本文件是本专项唯一规划与进度表。
不按来源、API 或单条报错另拆任务。实施开始时追加必要 ADR，替代旧沙盒身份与布局条款，
保留其余持久化机制；不兼容、不迁移旧布局。

保持路径规范化/alias、事务挂载、权限、独立 FD offset、目录快照、overlay/tombstone、
存活句柄、持久化落点和 SQLite rollback-journal 语义。底层资源永不反写。
不扩展完整 POSIX、mmap、WAL、跨进程锁、目录树 rename、网络文件系统或通用异步调度器；
不调整音频播放协议、视频时钟或会话推进策略。媒体改动仅限接入资源读取接口；
安装库/启动入口仅调整安装实例身份的分配与传递，不开展无关 UI 重构。

## 3. 目标设计

### 3.1 分离节点、打开状态和 backing

- 节点保留来源、权限、尺寸、内容版本和 overlay 归属；引入 VFS 内唯一、不会因路径复用
  而重复的节点身份。路径只是名字，缓存键使用节点身份 + 内容版本 + 窗口。
- 打开状态独立拥有 offset、权限和操作同步。FD 表只保存可持有的打开状态，禁止锁外
  持有表元素引用；关闭后 FD 数字复用不会使在途操作转向新文件。
- backing 提供长度、定位读取和明确错误；不认识 Java、播放器、resid 或 guest 路径。
  VFS 持有或共享拥有 backing，不能捕获会早于读取结束销毁的裸引用/span。
- 新增 `ReadAt` / `WriteAt` 语义，不移动 FD offset；普通 Read/Write/Seek 复用同一
  文件数据面。pipe/目录不作为可定位普通文件处理，按现有边界明确失败。

VFS 仍只依赖标准库。ZIP/OBB 格式解析与解压留在 loader；上层装配把受检来源注入 VFS，
禁止 VFS 反向依赖 loader/audio。媒体模块只接受自身定义的窄读取接口，由 integration
适配 VFS lease，不直接查 VFS 路径、APK 或宿主路径。不为此新增一个通用资源框架。

### 3.2 按来源采用最小后端

| 来源 | 本轮策略与边界 |
| --- | --- |
| 已有内存/小文件 | 保留内存 backing；共享已有拥有型数据，避免为了新接口再复制 |
| 宿主只读文件 | 持有打开的宿主文件身份，定位读取；不能每次按路径重新打开。打开时复核受检来源，保留拒绝符号链接/特殊文件的边界 |
| APK/OBB stored 条目 | 对受检归档 backing 建立 offset/length 窗口；不复制整条目。已有整包内存可共享，但不能把“整包已在内存”当作磁盘流式读取证据 |
| Deflate 等已支持压缩来源 | 增量解压 + 有界块缓存；后退可重启并丢弃至目标位置，明确允许线性成本。本轮不做通用随机解压索引 |
| 可写节点/持久沙盒 | 保留现有有配额的内存写入及原子文件替换策略；首次非截断写可显式转为可写内存 backing。它不属于大只读资源的低内存承诺 |

压缩格式仅限仓库已有支持面。缓存预算必须在分配/解压前预留，覆盖所有活跃来源，
不能只限每个条目。失败和取消释放预留；预算不足明确报错，不能退回无界全量读取。
可写物化也需要预检峰值内存，不能只依赖磁盘配额。预算由一处配置并允许测试注入，
实施时给出默认值和超限错误，不按游戏配置特判。

归档完整性是硬约束：[loader 契约](../../../src/loader/MODULE.md) 的 local/central、尺寸、
CRC 校验不能因区间读取被跳过。默认对尚未验证的条目先做有界内存的完整校验扫描，
成功后绑定不可变来源版本，再允许区间读取；Deflate 可需重新解压。
因此区分“没有全量内存物化”和“没有全量 I/O”：首次 CRC 扫描允许线性 I/O，必须单独记账。
要求首次小读不扫描全条目的场景，仅适用于宿主普通文件或已经验证的不可变条目。
若要改成消费到 EOF 才验证，属于另一个契约决定，本轮不默认采用。

宿主外部程序对已打开文件的原地修改不承诺快照一致性；截断/读取错误必须明确报告。
已验证归档不得在来源可变时沿用 CRC 结果；使用受控不可变来源，不能只凭路径/mtime
宣称版本未变。整个 APK 导入和 DEX 装载的内存模型不在本轮全面改造。

### 3.3 普通 FD 与只读资源 lease 的语义

普通 FD 固定节点身份，但不是不可变快照：同节点写入/截断仍按文件操作顺序可见。
unlink、rename 覆盖后，旧 FD 保持旧节点；Close 不得复活旧名字或覆盖替换后的目标。

媒体 lease 固定来源版本和窗口，独立于原 FD 的 offset 和关闭；从 FD 获取时必须原子
校验权限、节点及区间，不能先查路径再重开。只读 backing 可共享；可写来源先采用
受总预算约束的窗口快照，保证现有“捕获后仍读原窗口”的行为。大可写快照超限明确失败，
本轮不引入分页写时复制。普通 FD 不承担快照内存成本。

小音效允许显式、有预算的 ReadAll；音乐/视频使用增量读取，不能只换接口名称后仍
一次性复制完整编码源。resid 到条目、AFD 到窗口仍由现有资源适配层解析。
视频通过现有解码后端的自定义 IO 接入同一 lease；移除生产消费链对 HostPathFor 的依赖，
仅在没有剩余调用方时删除旧接口。

### 3.4 锁、取消与退出

全局锁仅保护路径/FD 表和必要元数据，耗时 backing 读取、CRC 扫描及解压在锁外进行。
先固定打开状态/节点/版本，再执行读取，最后按操作身份提交 offset 或缓存结果。
同一打开状态的 Read/Seek 串行，ReadAt 不移动它的游标；同节点写/截断与读通过节点同步
确定先后。不同节点的读取不互相等待同一全局 IO 锁。

实现必须明确唯一锁序；不能持全局锁等待节点 IO，也不能持节点锁反向等待全局锁形成环。
Close 先阻止新操作访问旧打开状态；已取得状态的操作完成或明确取消后才释放 backing。
失败未交付字节不推进 offset；短读、EOF、损坏、预算耗尽和取消分别映射，不以空数组统称。

lease 的取消是每次消费/任务的取消，不撤销其他消费者共享的 backing。按读取/解压块
检查取消，取消后的结果不得发布到已重设源的播放器。VFS 不创建线程池；沿用消费者
拥有的任务，退出按取消 → 等待在途操作 → 释放来源执行，不 detach。
普通同步宿主读不承诺可立即打断，只保证块间响应和安全回收；验收不宣称硬实时取消。

本轮不将 SandboxStore 改造成异步持久化服务。已有 fsync/Close/rename 的落盘阻塞可以
保留，但不得通过后台预读重新引入全局锁长持有；集中验收必须区分读取隔离与落盘串行。

### 3.5 安装实例身份与短目录布局

**安装 id 就是目录名**，安装库与沙盒共用同一个 id：`library/<id>/` 对应
`sandbox/<id>/`。安装身份不使用 versionCode/versionName，也不根据 APK 内容相同而
自动合并副本。版本字段仅作元数据；versionCode 写入 meta，不参与路径或身份判定。

某 package 的编号从 1 开始，1 省略后缀，其余使用 `-2`、`-3` 等规范十进制后缀。
每次新安装扫描该 package 已占用的编号，取最小空缺正整数：例如已存在裸名和 `-3`，
则分配 `-2`；裸名已空缺则复用裸名。package 不含 `-`，以完整 package 加可选数字后缀
精确匹配，不能把相似包名前缀当成同一包，也不生成 `-1` 或带前导零的编号。

占用集合取 library 与 sandbox 两侧已有目录的并集，避免安装库已删除但保留的存档被
新副本接管；旧布局目录也不能当空目录覆盖。分配与目录占位必须防并发冲突，冲突后重扫；
安装失败仅回滚本次新建内容，不删除已有目录，不发布半成品库条目。编号分配由安装层
统一拥有，SandboxStore 只接收受检 id 和 package，不自行分配另一套编号。

安装完成后 id 固定，启动/重启直接沿用；显式更新已有实例保留 id、存档和 android_id，
“再安装一份”才分配新 id。库选择、启动参数及 SandboxStore 打开链必须传递同一 id，
不得启动时重新按 package 推导或新分配。无库的持久化 CLI 入口也须明确实例选择；
多副本时不能只凭 package 猜选。临时沙盒仍可沿用其不持久化行为。

```text
OGPlay/
  library/
    com.rovio.angrybirds/
    com.rovio.angrybirds-2/
  sandbox/
    com.rovio.angrybirds/
      meta.toml
      internal/
      external/
      obb/
      sdcard/
    com.rovio.angrybirds-2/
      meta.toml
      internal/
      external/
      obb/
      sdcard/
```

`meta.toml.package` 保存真实 guest 包名，只用于 guest 路径翻译与一致性校验，不充当
沙盒选择键。安装 id 不进入 guest 包名和 guest 文件路径。新实例分别生成并持久化
android_id，两份安装按两台设备处理；重开同一实例不重新生成。实例数据、配额和
ANDROID_ID 状态不得再按 package 缓存而跨实例共享。

四个目录是固定语义根，不存在 `fs/`，也不在 internal 下重复 package：

| 规范 guest 路径 | 当前安装目录内的宿主路径 |
| --- | --- |
| `/data/data/<meta.package>/<relative>` | `internal/<relative>` |
| `/sdcard/Android/data/<meta.package>/<relative>` | `external/<relative>` |
| `/sdcard/Android/obb/<meta.package>/<relative>` | `obb/<relative>` |
| 其余 `/sdcard/<relative>` | `sdcard/<relative>` |

先做现有 VFS alias/大小写规范化，再按完整路径段匹配；专用 external/obb 根优先于
通用 sdcard，根路径本身映射到对应叶子目录。别的包如 `/sdcard/Android/data/other.pkg/x`
仍映射为本实例的 `sdcard/android/data/other.pkg/x`，绝不路由到另一个安装的沙盒。
其他包的 `/data/data/` 不因本次布局扩展为可写命名空间。

四根正向/反向映射统一归 SandboxStore，启动时从固定根恢复 guest 路径；沿用现有
文件名转义、大小写折叠、临时文件、tombstone 和防逃逸规则。拒绝反向映射重复节点
（例如同包数据同时出现在 external 与 sdcard/android/data/<pkg>），不能由枚举顺序选胜者。
guest `/sdcard` 枚举仍呈现 Android 路径，不能泄漏宿主 internal/external 等根名。

使用新的布局 schema，只接受上述结构。旧 `fs/data/data/<pkg>/`、旧 schema、缺失/冲突
的 meta 或新旧混合布局明确拒绝；不读旧数据、不自动迁移、不静默创建空沙盒掩盖问题，
也不自动删除旧目录。新建空实例与打开已有实例必须区分，不能把已有未知结构当新安装。
此处取代旧设计的 package 键、fs 镜像与旧 schema 升级要求；原子替换、flush 落点、
配额、删除/覆盖后的存活句柄规则继续保留。

## 4. 可判定验收

新增检查只覆盖新风险，其他优先复用现有测试；不以耗时猜测是否全量读取。

| 边界 | 必须提供的证据 |
| --- | --- |
| 大文件小读 | 虚拟大来源 + 宿主文件夹具，读开头/中部/末尾小窗口；统计 backing 读取量、分配/缓存高水位，确认无按文件大小分配；零长度/EOF 不触发无用物化 |
| 归档 | stored/Deflate 与原提取结果一致；首次校验扫描单独统计；元数据冲突、CRC 错、截断失败，不缓存为成功；压缩后退 seek 和预算耗尽有证据 |
| 锁隔离 | 用同步屏障阻塞来源 A，证明 B 的 Read/Stat/Open 可在 A 释放前完成；不靠固定 sleep。超时只作死锁保护 |
| FD 并发 | 同 FD Read/Seek 顺序、ReadAt 不移动 offset、关闭/复用 FD、并发截断、失败重试；无旧结果写入新打开状态 |
| lease | 关闭原 FD、unlink、rename 覆盖、同路径重建仍读取原窗口；可写源捕获后修改不改变快照；无越界、泄漏或复活路径 |
| 预算/取消 | 多消费者累计超限在分配前拒绝；取消读取/解压和退出后任务、来源引用、预算归零；取消一份 lease 不影响其他消费者 |
| 安装身份 | 首次裸名、同包 -2/-3、最小空缺复用、相似包名不混淆；版本号相同/缺失不合并；并发占位与失败回滚；单侧残留目录不被接管；启动沿用选中 id |
| 沙盒布局与隔离 | 四根正反映射、alias、根目录枚举、其他包 sdcard 回退、越界/重复映射拒绝；两个同包实例写入相同 guest 路径互不影响，android_id 独立且跨重开稳定；更新实例不换身份 |
| 旧布局拒绝 | 旧 fs/、旧 schema、新旧混合及不匹配 meta 明确失败，原文件不变；不走迁移或空沙盒降级 |
| 原有语义 | 复用 VFS/沙盒、syscall/Java 文件 IO、SQLite 定向回归，覆盖 alias 锁身份、空库/空 BLOB、journal 恢复、配额及存活句柄 |
| 真实消费链 | 音乐/视频经同一资源接口消费宿主、stored 和压缩来源；确认音乐无完整编码源复制、视频无需宿主路径。解码后端不可用则如实留缺口 |

## 6. 完成定义与保留限制

完成意味着：生产宿主和归档读取已走受控 backing；小窗口不再必然产生整文件副本；
慢资源读取不占用全局 VFS 锁；媒体复用统一寿命/窗口接口；既有文件与持久化语义不回退。
同包多安装使用一致的 library/sandbox id，存档与 android_id 按实例隔离；新沙盒仅使用
四个固定根，无 fs/ 和重复 package 层级，旧布局明确拒绝且不迁移。

完成后仍允许压缩后退/首次 CRC 校验线性扫描、受预算的小资源/可写快照、可写文件首次
物化和同步沙盒落盘；不宣称整个 APK 启动恒定内存、所有文件操作无阻塞或游戏完全兼容。
这些限制只有真实需求与测量证明不足时再独立调整，不作为本轮预留扩建任务。
