# DVM-108 · UUID 与 MessageDigest 迁入 BootDex

## 目标与依赖

依赖 DVM-107，迁入原版 UUID/JCA/Conscrypt 全部 API19 MessageDigest 算法，删除固定 UUID 旧 JNI 实现。

## 验收

- [x] core/Conscrypt 精确新增 16 类，BootDex 共 790 类，普通方法无 overlay。
- [x] 原版 UUID v1/v3/v4、解析/比较/格式化，Java/JNI 发布路径一致。
- [x] MD5、SHA-1、SHA-256、SHA-384、SHA-512 与原版别名/OID、摘要输入/输出流。
- [x] guest OpenSSL 的 7 个 digest JNI 入口、增量/reset/clone/ByteBuffer/异常与资源生命周期。
- [x] 普通 ctx 字段为 native token 唯一事实源，GC/退出回收且不释放仍被引用的 token。
- [x] readObject-only 序列化类型明确拒绝反序列化，不返回未恢复缓存的对象。
- [x] 双后端定向测试、相关 AES/证书/GC 回归、BootDex 确定性与 payload 门禁。

状态：完成。bootdex.jar 和 ROM libcrypto.so 不提交。

## 实现与边界

新增 core 9 类（UUID、MessageDigest 及两个内类、MessageDigestSpi、DigestException、ProviderException、
DigestInputStream、DigestOutputStream），Conscrypt 7 类（摘要基类、合成内类及五种摘要）。
保留统一 api19.json/build_bootdex.py 与 src/guest/crypto/crypto_jni.c，未新增工具配置或 ADR 文件。
Java 普通方法调用真实 ARM libcrypto EVP；native 单次 scratch 最多 64 KiB，不限制消息累计长度。
UUID.randomUUID 复用 OS CSPRNG；删除旧 JNI 固定对象与字符串，不再保留普通算法副本。

ctx:J 按普通对象字段读取，reset/digest/clone 的赋值仍由 Java 执行。GC 先比较所有字段 owner
存活情况，再排队清理；跨字段/浅 clone 共享 token 保留到最后 owner 死亡，teardown 清零字段。
清理失败保留队列可重试，算法与上下文均使用逻辑 token，不暴露 native 指针。
UUID.fromString 所需 String.indexOf(String,int) 补 UTF-16 原语及负起点/空串/null 边界。

原版 API19 OpenSSLProvider 未提供 SHA-224 MessageDigest；SHA-224 仍仅属于已有验签组合。
HMAC 属于 javax.crypto.Mac，SHA-3、额外摘要 provider/TLS 不在本次范围，未知算法明确失败。
对象流目前不调用任意私有 readObject；UUID 等此类反序列化明确 InvalidClassException，
Date 既有窄实现与 Externalizable 回调保持。
