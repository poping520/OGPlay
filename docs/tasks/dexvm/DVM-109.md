# DVM-109 · 原版对象流迁入 BootDex

## 目标与依赖

依赖 DVM-108（提交 0acf5ca0），ObjectInputStream/ObjectOutputStream 家族由原版 Java
执行，补齐 VM 原语，删除 C++ 对象流协议与状态副本，恢复 UUID 反序列化。

## 验收

- [x] 对象流、描述符/字段辅助类、异常及直接依赖精确选入；普通方法无 overlay。
- [x] ObjectStreamClass 六个 native、受检构造 token、父类构造语义与反射元数据。
- [x] UUID、默认 UID、共享/循环引用、数组、私有回调/GetField/PutField、Externalizable。
- [x] 同一 GC 对象图与回调异常，相关流/Cipher/证书定向回归。
- [x] 同步 MODULE、能力、ADR 和 CURRENT，确定性重建与 payload 门禁。

状态：完成。ObjectOutputStream.getFieldL 为未调用的遗留声明，显式未实现绑定，触达失败。
Proxy 动态类生成仍明确不支持；不扩展完整 Dalvik 或 Android 系统服务。
证据 `.local/review/dvm109/`；bootdex.jar 和临时 libcrypto.so 不提交。

## 实现与边界

新增 28 类，共 818 类：对象流及内类、ObjectStreamClass 及五个匿名类、EmulatedFields
家族、SerializationHandleMap、验证接口/异常、SerializablePermission，以及 SoftReference、
Proxy/InvocationHandler、Modifier、Void、VMStack。均来自 pinned core.jar，沿用统一配方。
删除 C++ 序列化协议、Date 特例、私有 readObject 拒绝和 IoRuntime 对象流 handle/状态。
UUID transient 缓存由原版私有回调恢复。普通字段/数组形成源、目标、handle 与描述符的 GC 图。

六个 ObjectStreamClass native 对照本地 libcore/luni native 与 dalvik/vm/Jni.cpp：
构造 token 受检且不暴露指针，实例只运行 Java 选定的父类无参构造；三个签名 getter 复用
唯一反射元数据，hasClinit 按 AOSP 初始化/父类查找并清除失败。另接通 VMStack.getClasses，
未使用的四个 VMStack native、两个 Proxy native 及 getFieldL 显式失败。

补齐 String.intern/startsWith(offset) 和所需 API19 serialVersionUID 常量；默认 UID 的
SHA 仍走 guest EVP。SoftReference 在普通 GC 保留，压力下清除并入队，显式 intern 的弱表
清扫后不残留复用 handle。修复反射 wide get 在初始化失败时返回 Void 的问题，类初始化
非 Error 包装 EIIE/cause、Error 保持原身份，重复访问 NCDFE。此迁移不承诺动态代理、
自定义 loader、宿主侧表对象的完整持久化或所有对象流长尾。
