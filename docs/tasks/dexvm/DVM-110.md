# DVM-110 · ScheduledThreadPoolExecutor 迁入 BootDex

## 目标与依赖

依赖 DVM-109（716206dc）、现有 Unsafe/Clock/真实 guest 线程，将原版定时执行器及
FutureTask、执行器接口/普通工厂包装类选入 BootDex，删除对应 C++ handler。

## 验收

- [x] 精确选类、全链接且普通方法无 overlay。
- [x] 双后端单次 Runnable/Callable、延时/顺序、定频/定延迟周期执行。
- [x] 取消/中断、异常、shutdown 策略、工厂、排队任务 GC 与退出。
- [x] 统一 Clock 和真实 worker，相关线程/同步器定向回归。
- [x] 确定性制品、门禁、MODULE/能力/CURRENT 同步。

状态：完成。沿用统一 recipe/build_bootdex.py，不创建宿主调度器或完整并行解释器。
privileged 工厂、动态安全上下文与高争用压力测试不属于本 WU。
证据 `.local/review/dvm110/`；bootdex.jar 和临时 libcrypto.so 不提交。

## 实现与边界

- 精确新增 26 类，共 844 类：Scheduled 家族 7 类、FutureTask/WaitNode 与四个接口共
  6 类、completion service 3 类、异常 3 类、普通 Executors 包装类 4 类、拒绝策略 3 类。
  ThreadPoolExecutor、AbstractExecutorService、DefaultThreadFactory、TimeUnit、AQS 与
  BlockingQueue 等原有依赖保持 BootDex；不增加 native 方法。
- 删除旧 FutureTask、合成 SingleThreadExecutor、Executors 工厂 overlay、相关接口和
  异常 handler。普通方法全部执行 pinned core.jar，concurrent family 仅保留 Unsafe/CS8。
- 队列、任务、结果、异常和等待者只在 Java 字段中；定时任务使用统一 Clock，周期时刻
  由原版 fixed-rate/fixed-delay 算法计算。ThreadFactory 创建真实 worker，park 释放执行锁。
- 修复 Runnable[] 到 Object[] 的接口组件协变，primitive class 仅与自身可赋值；修复
  threaded intrinsic invoke 忽略 VmJavaThrow.existing 导致异常身份丢失的问题。
- 仅承诺该已测闭包，不代表 privileged 工厂/安全上下文、高争用压力或硬实时计时；
  Clock 仍为现有毫秒精度及帧泵驱动。架构决定追加 [ADR-0041](../../adr/dexvm.md#adr-0041)。
