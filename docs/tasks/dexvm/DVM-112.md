# DVM-112 · ServiceConnection 与有界服务查询

## 目标与依赖

依赖 DVM-111（f7615b68），将 API19 ServiceConnection 原版接口迁入 BootDex，
让仅含 action、flags=0 的 resolveService 查询根据当前 APK 服务事实返回无匹配结果。
分析依据见 [DVM-111](DVM-111.md)。

## 范围与验收

- [x] Manifest 保存 service 名称、enabled、过滤器及 application enabled，注入会话。
- [x] ServiceConnection 原版双回调签名、接口实现/分派及 BootDex 全链接受检。
- [x] resolveService 无候选返回 null；候选、未知参数或缺少事实时记账并明确 Java 异常。
- [x] 双后端与解析器定向回归；原命令 PvZ 复跑并记录实际停止点。
- [x] 更新 MODULE、能力、CURRENT 与统一配方/制品清单。

不实现 Binder、跨进程/外部安装包数据库、服务绑定或支付；不按包名/action 特判。
不构造假的 ResolveInfo；positive resolution 与其他查询形态仍明确未实现。
证据 `.local/review/dvm112/`；bootdex.jar 与临时 libcrypto.so 不提交。


## 验收结果（2026-09-08，macOS Release）

状态：完成有界查询闭包；完整服务发现能力仍为 partial。设计见
[ADR-0042](../../adr/dexvm.md#adr-0042)。

- ServiceConnection 来自 pinned framework.jar，无 C++ overlay/native；已有 ComponentName/
  IBinder 身份满足两个 callback 签名。返回 ResolveInfo 的方法描述符可正常解析并执行 null
  分支，未执行的绑定分支不会提前链接。ResolveInfo/ServiceInfo 及返回类型反射未交付。
- loader 的服务列表与 Activity/alias 独立；保留 application enabled、归一化 service 名称、
  enabled、action/category/data 存在标记。服务不参与 Launcher 选择；会话显式区分
  inventory 已就绪与元数据未知。当前环境不安装外部包或平台服务目录。
- API19 action-only/flags=0 无候选返回 null，不产生绑定或回调；null Intent 抛 NPE。
  元数据未知、未知 flags/查询形态及潜在本地候选统一记账并抛 UnsupportedOperationException。
  data 条件只保存存在标记，候选需要它时明确失败，不推断匹配结果。

新增 5 个测试覆盖：Manifest 服务事实/非法名称/重复项；context 装配；双后端有界查询/
异常/记账/GC；真实 JNI bridge 下 APK 实现类链接、两个 invoke-interface callback 分派、
无匹配跳过未实现 bindService 分支且无回调。误把 AOSP buildClassName 当成完整 Java 名称
校验的测试预期已按本地 PackageParser 修正，未改变既有归一化语义。

相关回归 16 用例/7838 断言；Manifest+Intent/value 回归 35 用例/2777 断言（两组有重叠）；
staging 3 用例/17 断言及 6 项门禁通过。仅构建受影响的 ogplay_tests/ogplay 依赖，
未跑全量测试、真机或 Windows/Linux；沿用 WARNINGS_AS_ERRORS=OFF。

BootDex 845 类全链接，build/check 与源 payload 校验通过。DEX SHA-256：
`448c6e96e8669bb215090b835b3017a607eb0983f593158df036493262a1ed99`；JAR SHA-256：
`5fe9499d837e4c47ebb36b95887d118249802c1a69773aa811035ccbc436898d`。
