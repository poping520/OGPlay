# DVM-114 · Throwable 本地化消息虚分派

## 目标与依赖

依赖 DVM-113（f78c893d），按 API 19 Throwable.java 补齐 getLocalizedMessage，
修正 toString 的消息读取，使应用异常子类可沿继承链格式化错误。

## 方案与验收

AOSP luni/src/main/java/java/lang/Throwable.java 中 getLocalizedMessage 虚调用
getMessage，toString 虚调用 getLocalizedMessage。复用既有 InvokeGuest 和 Throwable
存储边界，保持 null/空串区别、返回引用及回调抛出的异常身份；无应用特判。
不迁移完整 Throwable/堆栈/打印能力。

- [x] 双后端 DEX 子类继承调用、覆盖 getMessage/getLocalizedMessage、null/空串及 GC。
- [x] callback 抛错保持原异常对象，基础 Throwable 行为不回退。
- [x] 定向回归与原命令 PvZ 探索复跑；更新契约、能力、CURRENT 并提交。

证据：`.local/review/dvm114/`；bootdex.jar 与临时 libcrypto.so 不提交。

## PvZ 探索与下一缺口分析

沿用 [DVM-111 原命令](DVM-111.md#pvz-原命令复跑)。`pvz.log` 显示错误格式化已越过
getLocalizedMessage，继续到 cause.printStackTrace(PrintWriter)，因该重载缺失退出 1；
未通过游戏 gate。调用者创建 StringWriter/PrintWriter 收集原因栈，属于进程内普通 Java IO，
不需要 framework 或服务扩展。

下一修复应把真实异常栈、消息与 cause 写入传入的 BootDex PrintWriter：

- 复用 ThrowableState.stack 的真实 VmStackEntry，先核对构造/显式 throw/JNI 异常捕获时机；
  现有无参 printStackTrace 仅记录 message，不能直接用来实现这个重载。
- 对照 AOSP Throwable.java 的 Appendable 输出顺序、父子重复帧与 cause，调用 Java writer，
  保留覆盖方法、输出副作用及异常传播；不得空操作或用当前调用栈冒充异常原始栈。
- 验证嵌套原因、真实帧/空栈、null writer、回调异常、GC 及循环原因的有界失败。
  Suppressed/完整 Throwable 迁移与 nativeFillInStackTrace/nativeGetStackTrace 需另行明确范围。

下一 WU 应先闭合栈捕获契约，再实现并验证 PrintWriter 输出。
