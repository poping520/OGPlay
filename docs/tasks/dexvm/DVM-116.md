# DVM-116 · BackupManager 无服务路径归 BootDex

## 目标与依赖

依赖 DVM-115（3961a8da），将 API 19 BackupManager/RestoreObserver 加入 BootDex，
闭合备份服务缺席的 Java 路径，并继续运行 PvZ。

## 范围

两类直接来自 pinned framework.jar；BootDex 共 900 类。只覆盖私有
checkServiceBinder() 平台查询边界，记录 dexvm.backup_service 不可用；不创建服务。
构造和 dataChanged/requestRestore/beginRestoreSession 执行原版 Java，分别不排队、
返回 -1、返回 null，不发出回调。非空服务注入明确失败。见
[ADR-0044](../../adr/dexvm.md#adr-0044)。

## 验收

- [x] 双后端覆盖实例/静态通知、恢复失败、无回调、GC 与异常服务注入。
- [x] BootDex 全类链接、确定性构建与 payload/文档门禁。
- [x] 原命令推进 PvZ 并记录下一缺口。

证据 `.local/review/dvm116/`；bootdex.jar 和临时 libcrypto.so 不提交。

## 结果（2026-09-08）

双后端与全类链接 2 用例/6557 断言、Android 定向回归 20 用例/2243 断言通过。
BootDex build/check、payload 和 6 项定向门禁通过。DEX SHA-256：
`de1702f99ae1902eb42850b8fcd032672eaf11b12568df64cfde7fd8770770c2`；JAR SHA-256：
`7fecb13a099377887416c938e290added1ad22ae70d467b65d04ff209d40eb00`。
仅构建 ogplay_tests 及依赖，未跑全量或其他平台。

原命令无诊断复跑越过备份通知，下一首错为 Intent.putExtra(String, Serializable)，
位于进程内广播对象传递链。`pvz.log` 退出 1，尚未通过游戏 gate。
