# DVM-122 · API 19 guest ICU 与统一 JNI 桥

状态：完成（2026-09-08）

## 目标

保留 crypto/ICU 源码边界，将审计所需 native 统一交付为 API 19 ARM
`libogplay_jni.so`，并删除 host ICU。

## 交付

- `src/guest/crypto` 与 `src/guest/icu` 由 NDK r25c ARMv7 API 19 clang 重复构建；
  唯一 JNI_OnLoad 注册 Cipher、Digest、Signature、ICU、NativeDecimalFormat 和 TimeZoneNames。
- ICU 只使用 ICU 51 C ABI，读取 `/system/usr/icu/icudt51l.dat`；不跨 NDK libc++/
  STLport C++ ABI，不引入 libjavacore。
- BootDex required_backend 改为 guest native；其余 native 保持 explicit_failure。
- 删除 PinnedIcu.cmake、嵌入数据生成、IcuFormatterRuntime、宿主 ICU 链接与
  `libogplay_cipher.so`。
- manifest 与 validator 校验闭集、SHA-256、ELF32 ARM/DYN、SONAME 和 DT_NEEDED。

## 验证

仅构建 Release `ogplay_tests` 及依赖；运行 DVM-105/106/108、BootDex audit/self-test、
Bionic profile 与 payload 定向校验，不运行全量 CTest。解释器-only ICU 旧夹具没有
guest-native invoker，相关行为覆盖迁移到 AndroidGuestProcess 双后端测试。

## 边界

具名时区数据库/历史 DST、BigDecimal parse、double/digit-list formatter、完整 ICU 查询、
libjavacore 及未审计 native 不在本 WU；标准字符集解码继续由宿主有界实现承担，复杂
Locale 大小写经 guest ICU，宿主不链接 ICU。

## AOSP 4.4.4 对照修正（2026-09-08）

- LocaleData 的日期 pattern、相对日与货币改读 ICU resource；裸 `zh` 保持无 country，货币为
  `XXX`/通用符号，未知货币名称遵循 libcore fallback。
- `formatLong` 写回全部数字字段和重复 grouping 区间；parse 区分 Long/Double 并保持
  ParsePosition，BigDecimal 仍明确 deferred。
- ICU common data 禁止文件回退、立即 `u_init`，卸载按 formatter→`u_cleanup`→data 释放；
  ICU 错误映射为对应 Java 异常。
- String 的复杂 Unicode/locale 大小写改走 guest `u_strToLower/Upper`；所有具名时区均明确报
  “数据库未交付”，不再把 `PST` 等有效 ID 静默伪装成 GMT。
- 双后端 guest 测试覆盖 sharp-s、裸 zh、货币 fallback、fraction/重复 grouping 字段、
  Double parse 和具名时区失败。
