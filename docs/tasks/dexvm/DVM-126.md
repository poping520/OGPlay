# DVM-126 · String.format 迁入 API 19 Formatter

目标：保留 VM 特殊 `String` 对象，只让两个 `String.format` intrinsic 按 API 19 包装逻辑
调用 BootDex `Formatter`，闭合 Locale 日期格式化首错。

状态：已完成（2026-09-08）。

## 边界

- 从固定 `core.jar` 精确选入 `Formatter`、五个嵌套类、`Formattable`/flags 与格式异常族；
  不选入 `String`，不迁整个 `java.util`。
- `String.format(String,Object[])` 先取 `Locale.getDefault()`；Locale 重载按 AOSP 创建
  `StringBuilder`/`Formatter` 并虚派 `format`、`toString`，原异常 identity 直传。
- `AbstractStringBuilder` 仅补真实继承/Appendable 边界；`IntegralToString.appendInt/Long`
  复用 VM 已有 UTF-16 builder 状态，不建立第二份字符串存储。
- 日期/区域行为继续由 BootDex LocaleData 与 guest ICU 51 决定；double/BigDecimal formatter、
  具名时区长尾不在本单扩展。

## 验收

- BootDex 948 类全链接，`Formatter.format` 为 interpreted，两个 `String.format` 为 intrinsic
  包装边界。
- switch/threaded 双后端覆盖 `%tZ`、`%02d`、默认/null Locale、API 19 格式异常及 GC 后结果。
- exact PvZ 命令越过 Locale `String.format("%tZ", Calendar)`；新首错为
  `System.getenv(String)`，不在本单扩展。
- Windows Release 只构建 `ogplay_tests` 及其依赖。BootDex build/check/audit、自测、payload
  校验通过；相关 CTest 10/10 通过。`architecture.platform_boundaries` 仍只被既有
  `frontend/gui/process_manager.cpp` 阻塞。未运行全量测试。
