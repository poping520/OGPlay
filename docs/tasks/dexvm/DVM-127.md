# DVM-127 · API 19 guest 进程环境与 `System.getenv`

## 状态

已完成（2026-09-08）。

## 目标

建立由 OGPlay 初始化、进程级共享且不泄漏宿主状态的 API 19 guest 环境，使 native
`envp`、Bionic 查询与 Java `System.getenv` 基于同一份配置工作。

## 依赖

- DVM-126 已完成，DexVM 双后端与 BootDex 生成链可继续扩展。
- AOSP 4.4.4 `java.lang.System`、`System$SystemEnvironment`、libcore `Posix` 与
  `init.environ.rc.in` 作为语义基线。
- 现有 `AndroidGuestProcess`、`Api19GuestProcess`、`AndroidGuestCallSession`、VFS
  及 `CoreIntrinsicServices` 契约。

## 问题边界

- 当前 `Api19GuestProcess` 传给 Bionic 的 `envp` 只有终止空指针。
- `java.lang.System` intrinsic 尚未实现 `getenv(String)` 和 `getenv()`。
- PvZ 的 `PATH` 查询只是暴露缺口的消费者，不得进入生产代码、能力名或分支条件。
- 禁止从宿主 `getenv`、`environ` 或启动 shell 继承 `HOME`、代理、区域等变量。
- OGPlay 不是 Android 模拟器；只配置已有兼容层资源能够兑现的环境项。

## 冻结设计

### 1. 单一配置源

新增进程级 `GuestProcessEnvironment` 值对象，由 `AndroidGuestProcess` 在启动时创建并
持有。它负责：

- 名称和值校验：拒绝空名称、名称中的 `=`、值中的 NUL、重复键和超限总量；
- 保留确定性顺序，提供精确、大小写敏感的查询和只读快照；
- 生成 native `NAME=VALUE` 列表，同时向 DexVM 暴露查询接口；
- 生命周期覆盖进程启动、Java 执行和 native 调用，进程清理时统一销毁。

首批默认值如下，后续新增项必须先证明对应 guest 资源真实存在：

| 名称 | guest 值 | 依据 |
|---|---|---|
| `PATH` | `/sbin:/vendor/bin:/system/sbin:/system/bin:/system/xbin` | API 19 init 默认值 |
| `ANDROID_ROOT` | `/system` | 已有 system/VFS 根语义 |
| `ANDROID_DATA` | `/data` | 已有应用数据路径语义 |
| `EXTERNAL_STORAGE` | 会话配置的 guest 外部存储根，当前默认 `/sdcard` | 已有存储挂载 |

本工作单不伪造 `HOME`、`USER`、`LANG`、`LC_*`、代理变量，也不提前声明尚无完整支撑的
`BOOTCLASSPATH`、`ANDROID_ASSETS`、`ANDROID_STORAGE`、ASEC/loop 路径。是否加入
`LD_LIBRARY_PATH` 必须由现有 linker 搜索契约决定，不能仅复制 AOSP 字符串。

### 2. Native 初始化

- 为环境指针表和字符串分配独立、受限的 guest 映射，不继续挤占固定 preinit 数据块。
- 按 A32 指针对齐序列化 `envp[]`，末项必须为空；`__libc_init` 获得该数组地址。
- 映射、写入或启动任一步失败时，沿现有事务回滚，不能留下半初始化进程。
- 增加条目数、单值长度和总字节上限，并对地址加法做溢出检查。
- 验收须通过 guest Bionic `getenv` 和 `environ` 读取，不能只检查宿主侧序列化结果。

Native `setenv`、`putenv`、`unsetenv` 与直接改写 `environ` 不在首批可变环境能力内。
实施时必须选择并测试一种明确契约：由边界覆盖层返回不支持，或将变更同步回统一环境对象；
禁止 native 修改成功而 Java 仍返回旧值。未完成该闭环前不得把能力标记为完整。

### 3. Java 语义

- 扩展 `CoreIntrinsicServices`，注入单值查询与全量快照回调；intrinsic 不接触宿主环境。
- 实现两个签名：
  - `System.getenv(String)`：空参数抛 `NullPointerException`；不存在返回 `null`。
  - `System.getenv()`：返回不可修改的、确定性快照，键值与 native 初始环境一致。
- 按 AOSP 行为补入 `System$SystemEnvironment` BootDex 依赖；payload、清单计数和哈希只通过
  生成工具更新，不手工改生成结果。
- compiled 与 interpreter 两条 DexVM 后端必须共用同一 intrinsic 实现并分别验收。

### 4. 不变量

- 同一 guest 进程只有一份环境来源；不同进程实例互不污染。
- Java 与 native 初始查询结果逐项一致。
- 宿主同名变量即使被投毒，也不得改变 guest 结果。
- 不支持或非法输入必须结构化报错，不得伪造成功或静默返回空字符串。
- `src/` 不出现游戏名、厂商名或包名；游戏差异仍只允许进入 profile。

## 实施切片

1. 追加 ADR，冻结环境所有权、默认项准入规则、native 变更策略和内存上限。
2. 实现 `GuestProcessEnvironment` 及单元测试，接入应用进程配置和外部存储路径。
3. 改造 API 19 preinit/native 启动，加入独立 env 映射及真实 Bionic 查询测试。
4. 扩展 DexVM 服务与 `System.getenv` 双签名，更新 BootDex 生成输入和双后端测试。
5. 增加 Java/native 一致性、宿主污染、进程隔离、异常和不可修改 Map 测试。
6. 用精确 PvZ APK 做消费者级回归，只记录是否越过该调用及下一处真实缺口。
7. 更新相关 `MODULE.md`、`capabilities.toml` 和 `docs/state/CURRENT.md`。

实施保留了工作区原有 BootDex 构建脚本与本地 AOSP 输入改动；只在其上增加
`System$SystemEnvironment` 配方并重新生成 payload。

## 预计修改面

- `include/ogplay/runtime/integration/`、`src/runtime/integration/`：环境对象与进程注入。
- `include/ogplay/runtime/dexvm/`、`src/runtime/dexvm/`：服务契约和 System intrinsic。
- `tools/bootdex/`、`data/android/19/`：AOSP 类闭包和生成清单。
- 对应目录 `MODULE.md`、定向测试、ADR、能力表与滚动状态。

具体文件名可随现有模块布局调整，但不得跨越上述所有权边界。

## 定向验收

只构建受影响测试目标，不运行全量测试：

1. 环境值对象：默认值、非法输入、容量边界、进程隔离、确定性顺序。
2. API 19 启动：A32 `envp` 布局、终止项、事务回滚、Bionic `getenv/environ`。
3. Java 双后端：两个 overload、缺失键、NPE、不可修改 Map、GC 后稳定性。
4. 端到端：Java/native 逐项一致，宿主 `PATH`/`HOME` 投毒不泄漏。
5. 架构门禁：生产源码无游戏标识、无裸日志、无宿主环境读取。
6. BootDex：执行既有闭包检查、审计、payload 生成和相关定向测试。
7. 精确 PvZ：调用不再停在 `System.getenv(String)`，且不得新增专属 quirk。

Windows 实施使用 `windows-msvc` 预设；其他平台使用项目当前开发预设。测试选择器以新增
测试的实际名称为准，禁止用全量测试代替定向证据。

## 完成标准

- 上述定向验收全部通过并留有机器可判定证据。
- Java 和 native 环境来自同一进程配置，且宿主环境不可见。
- native 可变环境不存在静默分叉。
- 精确消费者回归越过原缺口，后续缺口如实记账。
- 相关模块契约、ADR、能力表和滚动状态同步；能力状态只能前进。
