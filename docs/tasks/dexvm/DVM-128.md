# DVM-128 · API 19 `Settings.Secure` 与沙盒身份

状态：完成（2026-09-09）。

> 后续变更：schema 1→2 迁移与 package 级身份已被
> [ADR-0071](../../adr/session.md#adr-0071) 取代；当前 schema 3 旧布局拒绝、不迁移，
> `ANDROID_ID` 按 installation id 隔离。

## 目标

为每个 OGPlay 沙盒初始化独立、稳定且不读取宿主身份的 API 19 `ANDROID_ID`，并让 JNI
与 DexVM 的 `Settings.Secure.getString(ContentResolver,String)` 读取同一配置。

## AOSP 依据与缺口

- Android 4.4.4 `Settings.Secure.getString` 查询 secure name/value 表，未知键返回 `null`。
- SettingsProvider 在首次缺少 `ANDROID_ID` 时用 `SecureRandom.nextLong()` 生成十六进制值并
  持久化；恢复出厂设置后可以变化。
- OGPlay 旧 JNI registry 已声明该方法，但把 `installation_id` 同时冒充 Android ID；DexVM
  catalog 仅有 `Settings.System`，因此 dex_activity 路线在类解析处停止。
- 诊断 survey 仅命中该类及静态 `getString` 一个成员；当前实际键为 `android_id`。

## 实现

- `SandboxStore` 接受调用方提供的 8 字节 OS entropy，编码为 16 位小写十六进制并原子写入
  `meta.toml`。schema 1 沙盒在首次取身份时显式迁移到 schema 2；schema 2 严格校验值。
- 持久沙盒跨启动复用身份；ephemeral 沙盒每次创建新身份。该值与 package installation id、
  Build serial、telephony id 分离，也不读取宿主设备标识。
- `AndroidGuestPlatformConfig.android_id` 是 JNI 与 DexVM 的唯一装配输入；
  `DexVmAndroidContext.secure_settings` 是进程内只读 secure 子集。
- `android_device.cpp` 声明 `Settings$Secure.getString` 静态方法：空 resolver/name 抛 Java
  `NullPointerException`，已配置键返回字符串，未知键返回 `null`。
- 不引入 Binder、system_server、SettingsProvider、完整 ContentProvider 或完整 Settings BootDex。
  未命中的写入、整数及跨用户接口继续保持显式缺口。

## 验证

- `sandbox store migrates and preserves one API 19 ANDROID_ID`：8/8 断言。
- `DVM-128 Settings.Secure reads the injected API 19 identity`：switch/threaded、GC、未知键和
  空参数共 30/30 断言。
- legacy Android platform identity：58/58 断言，确认 JNI 读取独立 `android_id`。
- AndroidAppProcess 定向用例确认平台配置复制到 DexVM secure-settings 表。
- 关闭 survey 的 exact PvZ 运行越过 `Settings$Secure`；新首错为 fixed-font XML 非 ASCII
  文本限制。该 reached-fault 不等同游戏 gate。
