# DVM-129 · Unicode application label 与 fixed-font 边界隔离

状态：完成（2026-09-09）。

## 目标

让 API 19 `PackageManager.getApplicationLabel` 对资源型应用名返回 Unicode
`CharSequence`，不把非显示型资源查询错误送入 fixed-font 渲染限制。

## AOSP 依据与缺口

- Android 4.4.4 `ApplicationPackageManager.getApplicationLabel` 委托
  `PackageItemInfo.loadLabel`，资源型 label 经 `PackageManager.getText` 返回 Unicode
  `CharSequence`；该数据查询不进行字体测量。
- OGPlay 的资源型 label 错误复用了 `ResolveUiString`。该 helper 会按当前内建 fixed-font
  能力拒绝任意非 ASCII UTF-8 字节，因此中文 Manifest `android:label` 在后台埋点读取
  应用名时抛出误导性的 XML 文本错误。

## 实现与边界

- 资源型 label 改走 `ResolveResourceString` 与 DexVM UTF-8 字符串构造，literal label 和
  缺失 label 的既有行为不变。
- fixed-font 限制仍只约束实际 UI 文本；本次不增加字形、不替换不可显示字符，也不引入
  title/profile 分支。

## 验证

- `PackageManager P0 exposes only explicit current-package facts` 在 switch/threaded 两后端
  增加中文资源 label 往返断言。
- `UI resources resolve string color dimension and image state` 锁定 fixed-font 对真实 UI
  非 ASCII 文本仍明确失败；两项定向测试共 188 个断言通过。
- macOS dev 的 `ogplay_tests`、`ogplay` 受影响目标构建通过；no-raw-output、capabilities、
  documentation-layout、intrinsic-layout 架构门禁 4/4 通过，未运行全量测试。
- 关闭 survey 的 exact PvZ 已越过原错误，后台栈进入
  `NimbleTrackingS2SImpl.createEventRequestPostMap` 的下一条独立缺口
  `Landroid/os/Build;->BRAND:Ljava/lang/String;`；不视为游戏 gate。
