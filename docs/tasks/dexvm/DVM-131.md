# DVM-131 · 致命 invoke 参数诊断

## 目标（一句话）

DexVM 在 `invoke-*` 触发不可恢复错误时，于清栈前打印该次调用实际使用的 receiver 与有界、
类型化参数值，使缺方法阻断无需临时插桩即可看到调用现场。

## 依赖

- DVM-52：固定容量语义 trace 与栈安全点。
- DVM-76：致命错误清栈前自动附带 guest Java 栈。

## 范围与边界

- 直接读取故障帧当前 `invoke-virtual/super/direct/static/interface` 及 range 变体的原始 DEX
  method reference、prototype 和源寄存器；不能调用 `ResolveMethodIndex`，因为目标可能正是
  未解析方法。
- 输出按 `target / returns / receiver / arguments` 分区；参数以对齐的
  `[N] descriptor = value` 输出。基本类型按 descriptor 解释，`String` 转义且最多读取
  96 个 UTF-16 code unit；其他非空引用直接虚调用 `toString()` 并有界打印返回 String。对象
  实际类型与声明类型相同时不重复 descriptor；整体顺序固定为 thread context、fault
  instruction、fault invoke、guest stack。
- 最多输出 16 个参数；非法索引、寄存器 tag 或对象状态只降级参数诊断，原始 `DexVmError`
  与 guest stack 必须保留。
- 对象诊断允许调用 guest `toString()`；调用失败只降级该值并保留原始错误。不输出 host 地址，
  不保存参数副本或新增长期 GC root，不改变正常调用热路径、DVM-52 trace schema 或执行语义。
- 本 WU 只处理最内层故障 invoke；不承诺重建所有历史栈帧的入口参数。

## 验收

- switch/threaded 对普通与 range invoke 输出一致。
- virtual 缺方法包含 receiver 和转义 String；range 缺方法包含 String、float、int、long、
  double 与数组类型/长度。
- 超长 String 在 96 code unit 截断并保留原长度。
- 非空对象无需类型特判即可显示实际虚派 `toString()` 的有界返回内容。
- 既有 64 帧上限、最内层优先、清栈后 context 可用的 DVM-76 回归不退化。
- Windows `windows-msvc` Release 受影响目标构建、focused tests 与 DexVM architecture gate 通过；
  不运行全量测试或游戏 gate。

## 结果

- Windows `windows-msvc` Release `ogplay_tests` 受影响目标构建通过。
- `dexvm fatal errors*` 与 `dexvm fatal invoke diagnostics*` 2/2、100 assertions 通过，覆盖
  switch/threaded、普通/range invoke、receiver、全部 primitive、null、String 转义/截断、
  对象虚派 `toString()`、数组默认 `toString()` 及 16 参数上限。
- `architecture.capabilities_monotonic`、`architecture.documentation_layout`、
  `architecture.dexvm_intrinsic_layout` 3/3 通过。
- 本地 BootDex 输入含 DVM-130 的 SystemProperties native；诊断夹具以不执行的同签名 test
  overlay 完成链接，未改变生产平台实现。未运行游戏、全量或跨平台验收。
