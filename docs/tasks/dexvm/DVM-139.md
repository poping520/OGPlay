# DVM-139 · JNI 接口类型关系与虚派

## 目标与边界

修复 DexVM 向 JNI 发布类时丢失接口关系，导致合法的接口 `MethodID` 调用被误判为
receiver/dispatch class 不兼容的问题。

`JniClassRegistry` 保存 direct interface 图和 interface 标记；`IsAssignableFrom` 遍历父类与
接口传递闭包。`GetMethodID` 在 interface 上按接口继承图查找，后续虚调用仍从 receiver 的
实际类及父类选择实现。`GetStaticFieldID` 按 Dalvik 顺序查询当前类、新增接口再递归父类；
instance field 不跨接口查找。DexVM bridge 从 linker 原样发布这些关系，不增加 title 分支或
第二套类型事实。

## 验收

- [x] 普通、继承和菱形接口图可赋值，反向及无关类型拒绝。
- [x] interface `MethodID` 可在实现类 receiver 上虚派到实际实现。
- [x] interface 静态字段可经实现类查询，instance field 不跨接口。
- [x] DexVM `ServiceConnection` 实现类的 direct interface 关系进入会话 JNI registry。
- [x] PvZ exact 命令越过 `ITracking.setEnable(Z)V` 的 JNI class incompatibility。

Windows Release `ogplay_tests/ogplay` 受影响目标构建通过；JNI registry、invocation 与
DexVM bridge 三组定向测试 7 项、80 断言通过。PvZ 已越过原首错，新首错为
`glTexParameteri failed with GLES error 1280`。未跑全量测试、游戏 gate 或跨平台验收。
