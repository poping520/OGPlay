# DVM-141 · JNI 对象数组元素发布

## 目标与依赖

依赖 DVM-140 后续取证及 DVM-139 类型关系，实现对象跨 JNI 出口的一致类型注册。

## 交付

- JniGuestObjectRegistry.EnsureRegistered 原子幂等登记，真实类型冲突明确失败。
- GetObjectArrayElement 使用 JniObjectValue.java_class，不使用数组声明类型或 MethodID
  猜测；DexVmGuestBridge.PublishLocal 共用此接口，消除 check-then-register 竞争。
- 普通 Register 仍拒绝重复；ClassOf 仍严格；注册表不作为 GC root。

## 出口审计

- bridge 方法返回、字段读取与 native 参数均经过 PublishLocal；本次统一登记。
- NewObject 先 Allocate 登记；FindClass/GetObjectClass 使用 class registry 已有身份。
- NewString/NewPrimitiveArray/NewObjectArray 归各自 store，本次不为这些 store
  新增虚构的普通对象类型；引用复制不会创造新的对象身份。
- 数组元素已有真实 runtime class 但发布只传 object，是本次遗漏路径；已修复。

## 验证

- Release ogplay/ogplay_tests 构建成功；核心定向 5 用例、100 断言通过；
  JNI family 与 DVM-141 定向 34 用例、4552 断言通过。
  no_raw_output/capabilities_monotonic/documentation_layout 三项门禁通过。
- 低层覆盖未注册元素、重复获取、真实子类、CallIntMethodV、GetObjectClass、
  IsInstanceOf、null、冲突拒绝与原类型保持。
- 双后端真实 Java HashMap→Object[]→GetObjectArrayElement→GC→entrySet；
  清除数组后 local ref 仍保活，释放所有实例 local ref 后 GC 清理注册表。
- 原 PvZ 命令探索实跑越过原 JNI 错误到第 2 帧，新首错 shared GL capability is invalid；
  不代表完整游戏启动验收。本次未扩大图形修复范围。
- 扩展选择 JNI/字段相关用例时，40 用例中 37 通过，3 个已有解释器用例因
  BootDex SystemProperties.native_add_change_callback 未绑定而失败，未修改该无关缺口。
