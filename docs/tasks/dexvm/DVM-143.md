# DVM-143 · 反射方法定向查找

## 目标

修复 `Class.getMethod/getDeclaredMethod` 为查找一个方法却提前解析整类 metadata，导致无关方法
签名中的缺失类型阻断查询的问题。

## 交付

- 按名称和参数描述符扫描本类 own direct/virtual methods；公共查询再按 class→super→interface
  顺序递归。
- 不解析不同名方法；候选参数先用描述符比较，命中后才解析返回类型、参数类型和异常类型。
- `getMethods/getDeclaredMethods` 的完整枚举语义不变；Method wrapper 以 VM 内部方法 ID 回查不可变
  metadata，不保存 host pointer 或 guest root。

## 验证

- 构造含 `wanted()I` 与 `unrelated()Lmissing/UnavailableReturnType;` 的类；两个后端的
  `getMethod/getDeclaredMethod("wanted")` 均成功并得到同一方法。
- DVM-142/143 定向 2 用例、94 断言通过；Release `ogplay_tests` 构建成功。
- PvZ 2.3.12 原命令复跑完成 `LoadTask::FINISHED`，人工停止于 7811 个 presented frames；
  未再出现 PackageManager 反射故障，不代表三轮 Scenario gate。
- 纯 core reflection fixture 仍受既有 BootDex `SystemProperties.native_add_change_callback` 未绑定
  阻塞，因此本回归使用带 Android 平台绑定的 fixture，不将该独立缺口计作本次失败。
