# DVM-144 · BootDex-first 本地 Binder 与字节 Parcel

## 目标与范围

依赖 DVM-143，将 API 19 的 IInterface/IBinder/Binder/Parcel、ResultReceiver 与内部
IResultReceiver 迁入 BootDex。只交付同进程 Java Binder、字节 Parcel、Bundle/Intent 协议、
ResultReceiver 回调和外部服务缺席；不实现 Binder 驱动、跨进程 IPC、BinderProxy 后端、FD、
系统服务或业务特判。

## 结果

- 固定 framework/framework2 JAR 新增 20 个 class_def，BootDex 由 1021 增至 1041 类。
- 删除空 IBinder、Bundle typed atom 和 ResultReceiver 普通 C++ handler；Binder 普通事务链、
  Bundle/Intent/Parcelable/异常协议与回调执行原版 Java。
- Parcel native 使用 VM 隔离 token，统一保存对齐字节、游标和 Binder 强边；覆盖/截短/recycle
  清理引用，append 复制独立强边，含 Binder 的 marshall 与所有 FD 入口明确失败。
- Context.bindService 对确定缺席返回 false 且不回调；失败后连接仍登记，unbind 清理一次，重复/未登记 unbind 抛 IllegalArgumentException；
  ContextWrapper 通过 base Context 委托。

## 验证

Windows `windows-msvc` Release 仅增量构建 `ogplay_tests`。BootDex build/check、1041 类全链接、
Bundle 字节重建、ResultReceiver Binder 往返、DVM-112 服务缺席及 owner GC 定向测试通过；
架构/生成器 5 项门禁通过。`tools.android_payload_current` 仍被工作单前已有的 guest JNI generator
哈希不同步阻塞。组合源文件回归仅剩 CURRENT 已记录的 Typeface 与 Configuration 独立失败；

## 2026-09-11 验收修复

- 修复普通 AIDL 成功回包缺 StrictMode：仅提供禁用检测时的 hasGatheredViolations /
  clearGatheredViolations 平台边界，violation 处理明确记账并抛 UOE。补入原版
  BadParcelableException / NetworkOnMainThreadException；不 overlay Parcel 异常协议。
- 接口头写入当前 execution context mask | API19 GATHER(0x100)，enforce 保留 mask。
  非法长度先按剩余字节/OGPlay 上限检查，不以 guest 长度直接申请宿主内存。
- bind 与 resolve 共用缺席判定；API19 dispatcher 登记先于结果，连接是 Context 强边，
  unbind/sweep 清理。潜在本地匹配与未知 inventory 明确失败，不冒充外部服务缺席。
- application.dexasm 增加真实 EchoBinder/ForcedProxyBinder/EchoProxy；验证本地接口身份、
  强制 Proxy 事务回包、本地 oneway、未知 code、INTERFACE_TRANSACTION、直接异常及 reply 复位。
  另测 Java 异常类型/消息、违规头拒绝、长度负向、线程 mask/身份、Binder append 后 GC、
  部分记录拒绝、覆盖释放和 ContextWrapper 失败绑定后的解绑。
