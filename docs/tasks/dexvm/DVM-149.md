# DVM-149 · Terms 交互一致性与回归收口（进行中）

目标：保留 DVM-148 的 Terms 绘制结果，修复滚动点击冲突、后台故障传播、Drawable
替换、文本事务和 API 19 资源配置选择，并核实完整交互流程。

## 已验证

- ScrollView 仅在存在滚动范围且累计位移超过 API 19 `8dp` touch slop 后接管；接管时
  原 View 收到 `ACTION_CANCEL`，点击资格和旧 capture 同时撤销。无滚动范围的 MOVE
  继续交给子 View；独立轻触仍只产生一次 click。
- `RunAsyncWorker` 不再捕获任意 `DexVmError` 并伪造 null 结果；worker 故障保留线程、
  guest 栈和原 cause，且不会排队 `onPostExecute(null)`。
- 背景替换和清空解除旧 Drawable callback；Drawable mutation 还会反查 View 当前绑定，
  旧实例的 alpha/bounds 不再使新背景失效或改变其状态。
- 宿主按键、`TextView.setText`、`Editable.clear/replace` 共用 `ApplyTextEdit`。该入口执行
  数字/长度过滤，按真实区间依次通知 watcher 快照，并由 guest 回调决定后续 UI 状态。
- ARSC 保留 screenLayout size；候选按 API 19 的 sw、w/h、screen size、方向、density、
  SDK 顺序选择，同组候选反序不改变结果。drawable 缓存随 surface/density 配置变化失效。
- 纯 View 软件基帧只在没有 renderer、active SurfaceHolder、VideoView 和 holder Canvas
  producer 时发布；既有 ANGLE、VideoView 与软件 golden 定向回归通过。
- Windows VS 2026 `cmake --preset windows-msvc` Configure 成功；缺少 LibUSB 只关闭 SDL
  可选 HIDAPI libusb backend，没有阻塞生成。

## 有界支持与明确缺口

- 外部 `ACTION_VIEW` Intent 继续明确抛出 `UnsupportedOperationException`，不伪造 URI
  已打开；WebView `loadUrl` 也由“记录后丢弃”改为明确异常。
- AlertDialog Builder 已补 Terms 命中的方法签名并恢复 `AlertDialog extends Dialog`；实际
  Dialog presentation 尚未实现，`show()` 记录 `runtime.ui.dialog.presentation` 后明确失败。
- 移除 AsyncTask 降级后，真实 APK 在 Terms 页面运行到后台 Restlet 请求时，按预期暴露
  缺失的 `Lorg/apache/http/params/BasicHttpParams;`。当前固定 API 19 输入 JAR 不含该类，
  因此本批不能生成新的初始/输入/清空/提示截图，也不能宣称 Accept/Decline/Activity
  切换已完成实跑验收。日志：`.local/pvz-terms-review-run.log`。

## 定向验证

- `cmake --build build/windows-msvc --config Release --target ogplay_tests`
- `ogplay_tests.exe --test-case="Scroll interception cancels a child click after touch slop"`
- AsyncTask failure、Editable transaction、Drawable replacement、resource qualifier、
