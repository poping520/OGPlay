# DVM-154 · 文件 IO 家族 BootDex 迁移

目标：在一个 WU 内把 API 19 普通文件 IO 类迁入 BootDex，删除重复的类级 intrinsic，
并让原版 Java 经 `Libcore.os` 文件 native 边界共享唯一 VFS open-file-description。
依赖：DVM-79、DVM-82、DVM-99、DVM-104、DVM-152。状态：规划完成，待实施。

## 完成定义

- `File`、`FileDescriptor`、`FileInputStream`、`FileOutputStream`、`FileReader`、
  `FileWriter`、`RandomAccessFile`、NIO channel 接口、`FileChannel`、`FileChannelImpl`、
  `NioUtils`、`IoBridge`、`IoUtils`、`CloseGuard` 及精确依赖闭包来自固定 API 19 BootDex。
- 上述类不再由 `AppendJavaIoFiles`/`AppendJavaNio` 声明普通字段、构造器或普通方法；catalog
  只保留 `Posix`/必要 VM 原语的 native overlay。机器门禁要求 BootDex 类与整类 intrinsic
  交集为空。
- Java `FileDescriptor` 对象映射 `IoRuntime::OpenFileDescription`；FIS/FOS/RAF/channel
  通过同一描述共享 offset、访问模式、append、flush、close 和 errno。不得保存宿主 fd，
  不得恢复按 stream owner 分裂的文件状态。
- 删除仅服务旧 FIS/FOS/RAF/FileChannel handle 的 handler、字段绑定和侧表；内存流、ZIP、
  Reader decoder 等仍在使用的 IoRuntime 状态不顺带删除。

## 实现范围

1. 配方：用依赖 survey 生成并审查 core.jar 精确 class_def 闭包，更新
   `tools/bootdex/api19.json`，确定性重建本地 BootDex 与 manifest；不提交生成的 JAR。
2. 描述符与 errno：实现 `open/close/readBytes/writeBytes/lseek/fstat/stat/lstat/ftruncate/`
   `fsync/fdatasync/access/mkdir/remove/rename/chmod/ioctlInt/statvfs/strerror`；解码 API 19
   open flags，失败构造真实 `ErrnoException(function, errno)`，不合并 ENOENT/EACCES/EBADF。
3. NIO：接通 FileChannelImpl 的 ByteBuffer 顺序/定位 read/write、readv/writev、size、truncate、
   force、sendfile；定位 IO 恢复 offset。为 file-to-file `transferTo` 提供受检 VFS-backed
   只读 mmap/munmap，使用真实 guest 地址与明确生命周期。共享可写映射与文件锁继续明确失败。
4. 删除：移除 `DeclareFile*`、`DeclareRandomAccessFile`、临时 `DeclareFileChannel`、Channel
   interface shell 及 `getChannel/transferTo` 普通方法 overlay；清理不再可达的 stream-owner
   handle，禁止 BootDex 与 C++ 普通算法双事实源。

## 机器验收

- 双后端覆盖原版类来源、构造/异常、共享 FD offset、append、借用/拥有关闭、errno、RAF、
  唯一 channel、ByteBuffer 顺序/定位读写、force、file-to-file transferTo、GC 与 close 幂等。
- inventory 门禁保证迁移 owner 无类级 intrinsic，Posix 已实现项与 explicit-failure 清单互斥。
- 运行文件 IO、BootDex 全链接、NIO、GC 定向组，BootDex check、
  `architecture.dexvm_intrinsic_layout` 与 `git diff --check`；禁止全量测试。
- 真实 PvZ 关闭 survey 后完成配置文件复制，并至少到达迁移前的 `Context.getObbDir()`；
  不新增游戏名或包名分支。

## 提交与回退

- WU 内可分“配方→Posix→NIO→删除→验收”五个本地提交，但仅在全部门禁通过后标完成，
  不允许以混合 owner 状态结束。
- 若只读 mmap 不能满足真实地址与生命周期要求，则 WU 保持未完成并回退 FileChannel 的
  BootDex 选择，不能用临时普通方法 overlay 宣称完成。
- 完成时同步 `MODULE.md`、`capabilities.toml`、`CURRENT.md` 和本任务验证记录。
