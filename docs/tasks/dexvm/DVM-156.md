# DVM-156 · 无位置源的 API 19 location 薄层

目标：补齐游戏进程链接和探测所需的 `android.location` 最小契约，不接入宿主位置、
Binder 或 system_server。依赖：DVM-18、DVM-71、DVM-99、BND-39。状态：完成。

## 实现范围

- `LocationListener` 按 API 19 发布四个 abstract callback，使应用实现类可正常链接和分派。
- `Criteria`、`Location` 只提供当前边界需要的类型与构造形状；不保存或生成位置事实。
- `Context.getSystemService("location")` 返回会话内稳定 `LocationManager` 身份。
- `getBestProvider` 与 `getLastKnownLocation` 分别返回 `null`，表达无 provider、无历史位置。
- `requestLocationUpdates` 与 `removeUpdates` 不登记 listener、不触发回调，记录
  `dexvm.location_updates` 后抛 `UnsupportedOperationException`。
- 不把 AOSP `LocationManager` 放入 BootDex，避免引入 `ILocationManager`/Binder 服务闭包。

## 验证记录

- Windows Release 受影响目标构建通过。
- location facade 定向用例在 switch/threaded 双后端 1/1 通过，共 62 条断言；intrinsic
  architecture gate 通过。
- Angry Birds 实跑越过 `LocationListener` 类层级错误并进入 Flurry session，下一独立首错为
  `Context.getFileStreamPath(String)` 缺失。
