# DVM-157 · Context.getFileStreamPath VFS 对齐

目标：按 API 19 语义补齐 `Context.getFileStreamPath(String)`，复用现有 BootDex File 与
应用私有 VFS，不建立第二套文件状态。依赖：DVM-81、DVM-154。状态：完成。

## 实现

- `Context` 复用 `ContextFilePath` 的名称校验与 `/data/data/<package>/files` 路径事实，
  调用 BootDex `File(String)` 构造器返回新对象，不创建目标文件。
- `ContextWrapper` 只向 base Context 委托，Application/Activity 不复制路径状态。
- null 名称抛 `NullPointerException`，包含 guest 分隔符 `/` 的名称抛
  `IllegalArgumentException`；VFS 不可用时沿现有文件 API 明确失败。

## 验证

- Windows Release `ogplay_tests`、`ogplay` 构建通过。
- Context private-file 定向用例在 switch/threaded 双后端 1/1 通过，共 104 条断言；
  intrinsic architecture gate 通过。
- Angry Birds 实跑越过 `getFileStreamPath`，后续 JNI 返回族问题由 DVM-158 修复。
