# DVM-161 · Settings API 迁入 BootDex

目标：让 API 19 `Settings.System/Secure/Global` 执行 AOSP Java 语义，只在底层保留有界设置存储。
依赖：DVM-128、DVM-160。状态：完成。

## 实现

- 将 AOSP 4.4.4 `Settings` 全家族及 `BaseColumns` 纳入 BootDex；公开 getter/setter、数值转换、
  `SettingNotFoundException` 和 moved-key 路由均执行原版 Java 字节码。
- 删除 `Settings.System`、`Settings.Secure` 的公开方法 intrinsic，仅 overlay 私有
  `Settings.NameValueCache.getStringForUser/putStringForUser`，作为无 Binder/SettingsProvider 的
  有界存储边界。
- `Secure` 读取沙盒稳定身份；`System` 使用进程内隔离表并支持字符串写入/删除；未知键返回
  `null`。`Secure/Global` 特权写入返回 `false` 并记账，不伪造成功。
- 不引入 Binder、system_server、跨用户、观察者、宿主设置或游戏/Profile 分支。

## 验证

- Windows Release `ogplay_tests` 与 `ogplay` 构建通过。
- BootDex 全链接 8517 assertions；Settings 双后端 38 assertions；旧 Secure 身份回归
  30 assertions；intrinsic 架构门禁通过；BootDex 配方检查为 1511 classes。
- Angry Birds 无 Profile 实跑已由 AOSP `Settings.System` 把 `android_id` 路由到 `Secure`，
  原缺口消失；下一独立缺口为 `Context.checkCallingOrSelfPermission(String)`。
