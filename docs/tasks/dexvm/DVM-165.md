# DVM-165 · 旧 targetSdk JNI direct-reference 兼容

目标：按 Android 4.4.4 兼容旧 APK 跨 native call 保留 local reference 的错误用法。
依赖：DVM-164。状态：完成。

## 实现

- 严格模式仍为默认；仅 Manifest `targetSdkVersion` 为 1..13 时启用进程级兼容。
- 同一 Java 对象获得稳定的 32-bit direct-style JNI handle，local frame 仍正常弹出；失效
  direct handle 可再次解析，但不计入 GC roots。
- 旧 handle 第一次跨 frame 重新发放时输出 `runtime.jni.legacy_reference` 警告，明确指出 APK
  可能跨 native call 保留 local reference，并记录 target SDK、reference、object 和线程。
- 不使用 Profile/title 分支，不取消 `PopLocalFrame`，不把全部 local reference 提升为 global。

## 验证

- Windows Release `ogplay_tests`、`ogplay` 构建通过；JNI 定向 54 cases / 1608 assertions。
- 严格模式仍拒绝失效引用；旧模式稳定复用 handle、允许 Dalvik 风格跨线程 direct reference，
  且失效 direct handle 不成为强根。
- Angry Birds 无 Profile 运行到 1258 presented frames，原 `JNI reference is invalid for this
  thread` 消失，警告实际输出，之后游戏以 `nativeUpdate=false` 自行正常结束。
