# DVM-169 · API 19 Mac 与 HmacSHA1

目标：按 API 19 JCA/provider 语义补齐游戏直接使用的 `Mac.getInstance("HmacSHA1")`。
依赖：DVM-108、DVM-147、DVM-168。状态：完成。

## 实现

- AOSP 4.4.4 原版 `javax.crypto.Mac`、`MacSpi` 进入 BootDex，公开状态机、参数校验、
  ByteBuffer 与异常语义不在 C++ 重写。
- AndroidOpenSSL provider 仅增加 `HmacSHA1` 及 API 19 的 OID、`HMAC-SHA1`、`HMAC/SHA1`
  别名；其他 Mac 算法继续明确不可用。
- 有界 SPI 通过 guest ARM `libcrypto` 的 SHA-1 EVP 实现增量 HMAC；native token、互斥、
  GC/teardown 清理与现有加密边界一致，单次临时输入最多 4 KiB，不累计完整消息。

## 验证

- NDK r25c 确定性构建 guest JNI；BootDex 1533 类 build/check 通过。
- Windows Release `ogplay_tests`/`ogplay` 构建通过；双解释器 RFC HMAC-SHA1 向量、
  分段 update、doFinal 自动复位、reset、别名和 provider 身份通过：1 case / 1640 assertions。
- Angry Birds 无 Profile 实跑越过 `javax.crypto.Mac`，进入支付初始化；下一独立问题是
  GLThread 调用 `runOnUiThread` 时没有 Looper，随后残留 pending exception。
