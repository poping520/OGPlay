# DVM-169 · 当前加密能力迁入原版 Conscrypt

目标：按 API 19 JCA/provider 语义补齐游戏直接使用的 `Mac.getInstance("HmacSHA1")`。
依赖：DVM-108、DVM-147、DVM-168。状态：完成。

## 实现

- AOSP 4.4.4 原版 `javax.crypto.Mac`、`MacSpi` 进入 BootDex，公开状态机、参数校验、
  ByteBuffer 与异常语义不在 C++ 重写。
- 当前 AES、SHA1PRNG 与五种 MessageDigest 继续执行已有原版 Conscrypt Java 类；新增
  `OpenSSLMac$HmacSHA1`、`OpenSSLDigestContext`、`OpenSSLKey` 等精确依赖闭包，删除临时
  `org.ogplay.security.HmacSha1` SPI。
- AndroidOpenSSL provider 只发布当前已接通的算法及 API 19 原版别名；未实现服务不提前公布。
- `NativeCrypto` 按 AOSP 签名补齐 HMAC 所需 EVP context/PKEY/DigestSign 入口，通过 guest ARM
  `libcrypto` 增量计算；逻辑 token、互斥、GC/teardown 与现有边界一致，不累计完整消息。
- BKS/KeyStore、BouncyCastle、TLS 与 Android keystore 不在本 WU。

## 验证

- NDK r25c 确定性构建 guest JNI；BootDex 1539 类 build/check 通过。
- Windows Release `ogplay_tests`/`ogplay` 构建通过；双解释器 RFC HMAC-SHA1 向量、
  分段 update、doFinal 自动复位、reset、别名和原版 SPI 身份通过：1 case / 1646 assertions。
- Angry Birds 无 Profile 实跑越过 `javax.crypto.Mac`，进入支付初始化；下一独立问题是
  GLThread 调用 `runOnUiThread` 时没有 Looper，随后残留 pending exception。
