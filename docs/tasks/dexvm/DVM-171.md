# DVM-171 · API 19 原版 NativeCrypto 迁入 BootDex

目标：以固定 `conscrypt.jar` 的 `NativeCrypto` 为唯一正式类定义，删除 C++ 手工成员壳，
并保持当前 AES、摘要、HmacSHA1、随机数和证书验签能力。依赖：DVM-105、106、108、122、169。
状态：完成。

## 实现与审计

- `NativeCrypto` 与 `SSLHandshakeCallbacks`、`java.lang.Package` 精确进入 BootDex；原版类有
  41 个静态字段、232 个方法，其中 217 个 native。普通方法、TLS 名称表和完整 `<clinit>`
  Java 逻辑均来自固定 JAR；`EVP_DigestFinal` 保持 `(J[BI)I`。
- linker 只按类登记“原版 native 声明可进入 guest JNI”，不在 C++ 重列 217 个成员。
  `build_bootdex.py build/check` 从最终 DEX 生成 `.local/nativecrypto-api19-audit.json`：
  26 个既有后端、1 个初始化适配、190 个未实现并由 native 缺口机制明确失败。
- `javacrypto` 在 API 19 系统库加载边界显式解析到唯一 `libogplay_jni.so`。原版 `clinit()`
  继续执行；JNI 适配只验证 `JNI_OnLoad` 已完成当前 crypto 所需的 OpenSSL 线程回调和摘要
  注册，支持重复初始化并传播失败，不装入 libjavacrypto/libssl，不发布 TLS。
- digest、HMAC context 与 `OpenSSLKey` 字段资源登记移到 Interpreter 的统一 guest-native
  资源装配；逻辑 token、别名保活、GC、清理重试、teardown 和锁机制不变。
- OGPlay 自定义验签 native 移至 `org.ogplay.security.NativeVerification.verify`；原版
  `NativeCrypto` 不再含私有扩展。验签仍复用同一 JNI SO 与 guest libcrypto。
