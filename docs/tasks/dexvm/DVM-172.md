# DVM-172 · 通用 KeyStore/BKS（KS-01..09）

目标：在 DexVM/BootDex 中交付 API 19 兼容的通用 KeyStore/BKS，实现真实格式、密钥保护、
持久化与独立 Provider 发布，不引入生产 BC、宿主 JVM或第二套密码库。

依赖：DVM-105、DVM-106、DVM-147、DVM-169、DVM-171、ADR-0064。
状态：KS-01..09 已闭合；完成范围限于下述 API 19 软件 KeyStore/BKS 与算法集合。

## 范围与架构

- API 19 原版 `KeyStore`、`KeyStoreSpi` 及公开嵌套类进入 BootDex。
- 自有 `OGPlayKeyStore` Provider、SPI、条目状态、BKS codec 与 PKCS#12 KDF 使用 guest Java。
- AES、HMAC-SHA1、SHA-1、3DES、RSA/EC 编码调用既有 guest `libcrypto.so`；BC 仅作隔离 oracle。
- 条目与普通状态只存在于 guest Java 对象图；C++ 仅管理带类型和引用计数的 EVP token。
- 文件访问复用调用方流与既有 VFS；日期、随机盐和 IV 复用统一 Clock/CSPRNG。

## 格式与算法边界

- store：最大 16 MiB；单 blob/key/certificate 最大 1 MiB；最多 4096 条目；证书链最多 64；
  salt 最大 1024 bytes；KDF iterations 为 1..1,000,000。
- 写出版本：BKS v2；读取版本：v0/v1/v2。
- 密钥：AES RAW secret、RSA/EC PKCS#8 private key。
- 明确不支持：DSA、X.509 public-key entry、其他未知 key 算法、UBER/Twofish。
- 不包含：PKIX、系统 CA、TLS、AndroidKeyStore、Binder、硬件密钥和签名生成。

## 发布结论

本轮已修复跨 session 测试误置于证书用例、重复挂载同一 VFS 的问题，并补齐真实
CallbackHandler、共享 store 双线程及应用沙盒隔离回归。KS-01..09 在上述格式与算法边界内
闭合；并发回归不承诺复合调用或枚举的原子性。私钥恢复不表示已经支持签名生成或
TLS 客户端认证，范围外能力保持可查询并明确失败。
