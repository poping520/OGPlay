# DVM-173 · 证书信任与客户端 TLS

目标：以 AOSP 公开 API、自有 Java Provider 与 guest libssl 实现真实信任验证和客户端 HTTPS。
状态：TLS-01/02 已验收；TLS-03 未完成（公开 CA / OpenSSL 1.0.1 维护仍阻塞在线发布）。
依赖：DVM-106、DVM-164、DVM-171、DVM-172、libssl payload b71e9b10。

设计与逐项验收唯一来源：[14 · 信任验证与 TLS](../../design/dexvm/14-tls-trust.md)。
架构：[ADR-0066](../../adr/dexvm.md#adr-0066)。

## 执行顺序

1. TLS-01：真实信任服务。一次闭合 API/策略、路径验证、TrustManagerFactory 和默认 CA。
2. TLS-02：客户端 TLS/HTTPS。一次闭合 Java 状态、raw transport、BIO、回调、mTLS 与 HTTPS。
3. TLS-03：受控在线发布。闭合后端/CA 维护、产物、平台验证和最终能力记账。

仅设以上三个开发单元，单元内检查项不再拆成独立任务；实施细节、依赖和全部验收要求
见完整规划第 9、10 节。每个单元交付真实可验收能力，测试与文档随实现一并完成。
AndroidKeyStore 软件服务、通用 PKIX、SSLEngine、server TLS 不计入本任务完成范围。
记录 TLS-03 阻塞不等于将该单元闭合。

## 验收记录

平台：Windows Debug `windows-msvc`，`ogplay_tests`，双解释器。
命令：`cmake --build build/windows-msvc --config Debug --target ogplay_tests -- /m`
然后 `.\build\windows-msvc\Debug\ogplay_tests.exe --test-case="TLS*"`。
配套：`ctest --test-dir build/windows-msvc -C Debug -R "^(architecture.dexvm_intrinsic_layout|tools.android_payload_current)$"`。

- TLS-01：`TLS-01 path validation uses guest libcrypto` 通过。Direct `verifyPath`、
  显式 BKS 与 `init(null)` 默认 CA、AndroidCAStore 只读、正反证书矩阵、交叉签名、
  pathLen 与 authType 均走 guest libcrypto `X509_verify_cert`。校验时间取
  `System.currentTimeMillis()` 统一 Clock（JNI `X509_STORE_CTX_set_time` 与 Java
  `checkValidity`）；将 AndroidAppProcess 墙钟推到 2037-01-01 时，2010–2036 夹具叶证书
  抛 `CertificateExpiredException`。Harmony 证书 DER 在 `encodedCopy` 边界钉死独立副本。
- TLS-02：`TLS-02 client handshake HTTPS layered autoClose`、
  `TLS-02 SSLContext init does not replace the HTTPS factory`、
  `TLS-02 enabled protocols and SNI apply to the handshake`、
  `TLS-02 mutual TLS installs a BKS client certificate`、
  `TLS-02 network stays offline by default` 通过。仅 `DefaultContext` 写入全局 HTTPS
  工厂；任意 `SSLContext.init` 不再覆盖。`setEnabledProtocols` 经 `SSL_ctrl` 作用到
  native SSL；无参 `createSocket()` 后 `connect()` 更新 `peerHost` 并发送 SNI（oracle
  拒绝空 SNI）。`SSL_VERIFY_PEER` 在 `SSL_do_handshake` 内调用 TrustManager，失败则不
  完成握手。loopback TLS 1.2、HTTPS GET `200`/`tls-ok`、layered `autoClose=false`、
  RSA 与 EC mTLS 均双解释器通过。session id 来自 `SSL_SESSION_get_id`；session 超时
  生效；`setEnableSessionCreation(false)` 拒绝新握手。未实现 `SSL_set_session` 会话恢复。
  API 19 `SSLParameters` 无 `endpointIdentificationAlgorithm`；HTTPS 主机名走
  `HostnameVerifier`。SSLEngine 与 server TLS 明确失败。
- TLS-03：测试 CA 包 `tests/fixtures/tls/cacerts.ogplay` 不是公开信任列表；payload
  `libssl.so` 来自已停止维护的 OpenSSL 1.0.1（AOSP 4.4.4_r2.0.1）。本地握手/HTTPS 成功
  不能发布在线 HTTPS。公开 CA 来源/更新责任与后端补丁审计仍阻塞；本单元保持未完成，
  不以记录该阻塞视为闭环。

BootDex 1636 类；DEX `528a64870e0c39ca378bb30e9a7d61eeb056d4ca3c398a989233de540f1ff2a6`。
guest JNI `bac86f19624245c7d80537f489a30e2af5a423031ead26843f3d48ebf07e7aae`（DT_NEEDED 含
`libssl.so`）。`architecture.dexvm_intrinsic_layout` 与 `tools.android_payload_current` 2/2。
`TLS*` 7 cases / 1688 assertions。
oracle：`tests/fixtures/tls/loopback_https.py`（TLS 1.2 only，要求 SNI）。
未支持：SSLEngine、server TLS、通用 CertPathValidator.PKIX、AndroidKeyStore、公开互联网 CA、
`SSL_set_session` 恢复。
