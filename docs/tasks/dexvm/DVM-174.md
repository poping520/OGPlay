# DVM-174 · Angry Birds 插屏路径（DVM-174..179）

目标：沿无 Profile Angry Birds 插屏构造链，按 API 19 补齐通用 View/Log 缺口，使应用类可链接、
程序化构造容器、登记可覆盖点击并按真实 clip/clickable 状态继续执行。不引入完整动画框架、
XML 主题构造、ViewGroup 或手势系统。依赖：DVM-99、DVM-136、DVM-173。状态：DVM-174..179
完成；下一独立首错为 `PackageManager.getPackageInfo` flags=4097。

DVM-174..179 统一归档于此。编号不重排；各单元仍保留独立验收结果。

## 路径

| 单元 | 缺口 | 结果 |
| --- | --- | --- |
| DVM-174 | `Animation$AnimationListener` 类型缺失 | BootDex 精确选入嵌套接口；应用实现类可链接并分派三个回调。 |
| DVM-175 | `View.setOnClickListener` 误为 `FinalMethod` | 改为可覆盖 `VirtualMethod`；子类 `super` 进入现有 listener 登记。 |
| DVM-176 | `Log.getStackTraceString` 缺失，离线 catch 变线程故障 | 按 API 19 返回空串或 `printStackTrace` 文本；不开启网络。 |
| DVM-177 | LinearLayout 缺 `(Context, AttributeSet)` | `attrs==null` 程序化构造复用 UiTree；非空 AttributeSet 记账失败。 |
| DVM-178 | ViewGroup clip 方法缺失 | 两个独立默认 true 的开关写入 UiNode，并接入绘制链。 |
| DVM-179 | `View.setClickable` 未闭环 | 与 UiNode.clickable 共用状态；触摸点击受 clickable 约束。 |

Angry Birds 2.3.0 无 Profile、关闭 survey：兼容链越过 `AnimationListener`、
`setOnClickListener`、`getStackTraceString`、LinearLayout 空 AttributeSet、ViewGroup clip 与
`BurstlyView.setClickable`。插屏路径为 `InterstitialAdWrapper$3.run` → `BurstlyView`。不宣称
可玩、广告展示或广告联网。

## DVM-174 · AnimationListener 类型兼容

应用类实现该接口时，类加载即需要接口类型；构造器本身不创建动画。`show`/`hide` 仅在广告
View 非空时才创建 `TranslateAnimation` 并启动；当前日志只证明类层级缺失，不证明动画执行链
已触发。`onAnimationEnd` 会清理状态、移除 View 并通知 native，因此不能伪造完成回调。

- 从固定 API 19 `framework.jar` 精确选入原版
  `Landroid/view/animation/Animation$AnimationListener;`。
- 制品为 `public abstract interface`（class_def `0x601`），超类 `Object`，无父接口；InnerClass
  `accessFlags=0x609`、name `AnimationListener`；三个抽象方法 `onAnimationStart` /
  `onAnimationEnd` / `onAnimationRepeat`，签名均引用 `Animation`。
- 嵌套接口可独立纳入：baksmali 单类抽出后，方法签名与 EnclosingClass 只引入 `Animation` 的
  type_id，不要求其 class_def。未导入整个 `android.view.animation` 包，也未建立 C++ 类型/行为
  副本。

验证：BootDex 1638 类，DEX
`506da0c2323946e53852affe2bfb9b3b585ae3d1c2a20cb345093f6296fe97bd`。双解释器
`DVM-174 AnimationListener type compatibility links and dispatches` 1 case / 62 assertions。
`tools.bootdex_builder_self_test` 通过。原 hierarchy 缺失已消失；当时下一首错为
`BurstlyView` 覆盖不可覆盖的 `View.setOnClickListener`。

## DVM-175 · View.setOnClickListener 可覆盖契约

AOSP 该方法为 `public`、非 `final`。OGPlay 误用 `FinalMethod`，合法子类覆盖在链接期失败。
`BurstlyView.getSDKVersion` 触发所属类链接，因此报错点看起来像版本查询。

- 声明改为 `VirtualMethod`，保留现有 node 级 listener 登记与 `null` 解除。
- 不放宽链接器非法覆盖检查，不加入包名/游戏分支，不把 View 迁入 BootDex。
- AOSP 还会在登记时 `setClickable(true)`；该副作用由 DVM-179 补齐。本单元不宣称完整点击语义。

验证：双解释器
`DVM-175 View.setOnClickListener is overridable and super registers the listener`
1 case / 56 assertions。既有 `visible button with a listener receives the click` 1/18。
`architecture.dexvm_intrinsic_layout` 通过。当时下一首错为 `Log.getStackTraceString`。

## DVM-176 · Log.getStackTraceString API 19 语义

应用已处理网络不可用（下载失败 → catch IOException → 记录异常 → 返回 null）。记录时调用
缺失的 `Log.getStackTraceString`，把可恢复的离线流程变成线程故障。返回空字符串是 AOSP 对
`UnknownHostException` cause 链的明确语义，不是域名绕过。

- 注册 `public static String getStackTraceString(Throwable)`。
- `null` 与自身/cause 链中的 `UnknownHostException`（含子类）返回空字符串。
- 其余异常经 guest `printStackTrace(PrintWriter)`，flush 后取 `StringWriter` 文本。
- 与 d/e/w Throwable 重载共用格式化辅助函数；跨 guest 调用保护 GC 引用。不按消息/域名判断，
  不对所有异常一律返回空串。不迁入整个 Log，不开启网络。

验证：双解释器 `DVM-176 Log.getStackTraceString follows API 19 throwable rules`
1 case / 164 assertions。既有 `Log debug throwable overload` 1/12。当时跑满 600 presented
frames，本窗口未出现新的独立 DexVM 首错。

## DVM-177 · LinearLayout 空 AttributeSet 程序化构造

构造器不继承。应用子类 `super(context, null)` 需要 LinearLayout 自身的双参数构造器。单参数
构造器与其他 View 类的同签名都不能补上这个缺口。

- 有效 Context 且 `attrs == null`：进入 `ViewInitHandler`，按 `UiClassForObject` 建立唯一
  LinearLayout UiNode。
- `context == null` 抛 `NullPointerException`。
- 非空 AttributeSet 记账 `dexvm.view_xml_attributes` 并抛 `UnsupportedOperationException`，
  不静默忽略。
- 范围为现有默认样式内的程序化构造，不宣称完整 XML/主题构造兼容。

验证：双解释器 `DVM-177 LinearLayout programmatic AttributeSet constructor`
1 case / 118 assertions。既有 `guest View subclass resolves the platform kind by inheritance`
1/13。插屏路径越过 LinearLayout 构造器缺口；当时下一首错为 `ViewGroup.setClipChildren`。
诊断字段 `<toString returned non-String>` 不是终止原因。

## DVM-178 · ViewGroup clipChildren / clipToPadding

方法不继承。应用子类 `BurstlyView → LinearLayout → ViewGroup` 调用的是 ViewGroup 实例方法。
只保存 false 或把现有 `PushClip(screen_frame)` 改成“当前节点开关为 true 才执行”，都会与两个
开关作用对象不一致。

- ViewGroup 声明可覆盖 `setClipChildren(Z)V`、`setClipToPadding(Z)V`、`getClipChildren()Z`。
- UiNode 保存两个独立默认 true 的布尔值，作为唯一事实源；值变化只标 draw dirty。
- 父容器 `clipChildren` 裁子 View 到其 bounds；容器 `clipToPadding` 在绘制子孙前裁到 padding
  box。祖先裁剪、输出边界与默认控件裁剪保留。不修改触摸命中。
- 不引入完整 AOSP ViewGroup，不把方法放到 LinearLayout 或游戏类。

验证：`ViewGroup clipChildren and clipToPadding change descendant pixels` 1 case / 42
assertions。双解释器
`DVM-178 ViewGroup clipChildren and clipToPadding are overridable state`
1 case / 144 assertions。既有 ImageView CENTER_CROP golden 1/21。当时下一首错为
`View.setClickable`。

## DVM-179 · View clickable 状态闭环

方法不继承。`BurstlyView → LinearLayout → ViewGroup → View.setClickable(true)` 需要 View
自身的虚方法。仅登记 setter 能越过解析错误，但 hit-test 仍只看监听器是否存在，基础
`onTouchEvent` 也固定返回 false。

- `setClickable`/`isClickable` 读写 `UiTree::SetClickable` / `UiNode.clickable`。
- `setOnClickListener` 在登记前虚派 `isClickable`/`setClickable(true)`，传入 null 同样如此；
  解除监听器不清除 clickable。`setClickable(false)` 不删除监听器。
- 触摸点击要求 clickable；`InvokeViewOnClick` 不检查该标志。
- 基础 `onTouchEvent` 在 clickable 时消费事件且不伪造 onClick。OnTouchListener 与子类
  `onTouchEvent` 不被 clickable=false 禁用。
- 不扩展长按、无障碍或完整 dispatchTouchEvent。

验证：双解释器 `DVM-179 View clickable state is overridable and shared with UiNode`
1 case / 138 assertions。定向输入
`DVM-179 clickable gates touch clicks and still consumes without a listener`
1 case / 90 assertions。既有 button listener 1/18、enabled 1/31、gesture independence 1/139、
deep override 1/61、DVM-175 1/56。插屏路径越过 `BurstlyView.setClickable`；下一独立首错为
`PackageManager.getPackageInfo` flags=4097。
