# DVM-180 · 当前包 Activity 元数据查询

目标：按 API 19 让 `PackageManager.getPackageInfo` 支持 `GET_ACTIVITIES`，从当前 APK
已解析 Manifest 发布 Activity/activity-alias 元数据。不实现完整 PackageManager 或
组件启动。依赖：DVM-77、DVM-142、DVM-174。状态：完成。

## 根因

`4097 = GET_ACTIVITIES | GET_PERMISSIONS`。既有实现只允许 `GET_META_DATA` 与
`GET_PERMISSIONS`，因此主动抛 `UnsupportedOperationException`。应用只捕获
`NameNotFoundException`，用该异常检查当前包是否声明所需权限与 Activity。

## 实现

- PackageManager 发布 `GET_ACTIVITIES = 1`，允许与既有 flags 组合，不特判
  `flags == 4097`。
- `PackageInfo.activities` 为 `ActivityInfo[]`；未请求 `GET_ACTIVITIES` 时保持
  null。请求后若 Manifest 无组件则为 null；若有组件但按 API 19 全部被过滤则为
  空数组。
- 结果来自 `context->activity_components`：规范化组件名、保留声明顺序、区分
  Activity 与 alias（alias 保留自身 name 与 `targetActivity`）。默认跳过
  `enabled == false` 的组件。
- 范围内字段：`name/packageName/applicationInfo/enabled/exported/targetActivity`。
  `exported` 由 Manifest 显式属性或「有 intent-filter 则 true」的 API 19 缺省补齐。
- 当前包边界与未知 flags 检查保留。`requestedPermissions` 仍是 Manifest 声明列表，
  不等于 granted set。

## 验证

- Windows Release `windows-msvc`：`ogplay_tests` / `ogplay` 受影响目标构建通过。
- 双解释器夹具 `DVM-180 getPackageInfo returns current-package Activity metadata`。
- Manifest 夹具 `DVM-180 Manifest resolves Activity exported from attribute or intent-filters`。
- `architecture.dexvm_intrinsic_layout` 通过。
- Angry Birds 2.3.0 无 Profile、关闭 survey：插屏路径越过
  `PackageManager.getPackageInfo` flags=4097。下一独立首错为
  `Class.getAnnotation`，出现在 Burstly `Utils.isSdkAvailable` 初始化 Jackson
  `VisibilityChecker$Std` 时。不宣称完整 PackageManager、组件启动或广告可用。
