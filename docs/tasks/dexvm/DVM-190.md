# DVM-190 · 当前包 receiver 元数据查询

目标：在不接入包服务的前提下，按 API 19 当前 APK Manifest 回答
`PackageManager.getReceiverInfo(ComponentName,int)`。依赖 DVM-77、DVM-142、DVM-180。
状态：完成。

## 边界

- loader 保留 receiver 规范类名、enabled/exported、process、permission 与自身
  `meta-data`。`android:value` 和 `android:resource` 仍分开；应用与 receiver 元数据
  不合并。session 将同一 sealed Manifest 注入 DexVM context。
- 只按完整 ComponentName 查当前包 receiver。支持 flags 0、GET_META_DATA、
  GET_DISABLED_COMPONENTS 及其组合；默认过滤禁用 application/component。缺失抛
  NameNotFoundException，未知 flags 或未装配 inventory 记账并明确失败。
- 返回原版 BootDex ActivityInfo，复用当前包 ApplicationInfo 和 Bundle 构造机制。
  不查询 DEX 类存在性，不从 activity 列表猜 receiver，不引入 Binder、广播投递或系统包目录。

## 验证

- Windows Release `ogplay`/`ogplay_tests` 构建通过。
- Manifest fixture 检查字段、exported 缺省与五种元数据形式。
- 双解释器 fixture 检查存在/缺失、跨包、禁用、元数据归属与类型、重复查询隔离及 GC。
- Dead Trigger APK/OBB、无 Profile、关闭 survey 的相同启动路径越过 getReceiverInfo；
  下一首错为 `PackageManager.getServiceInfo(ComponentName,int)`，属独立后续缺口。
- `architecture.dexvm_intrinsic_layout` 仍因清单未包含既有
  `android_media_bootdex.cpp`/`encoded_audio_window.cpp` 失败；本工作单未改变这些文件。
