# DVM-191 · 当前包 service 元数据查询

目标：按当前 APK Manifest 回答 `PackageManager.getServiceInfo(ComponentName,int)`，
返回 BootDex 原版 `ServiceInfo`。依赖 DVM-112、DVM-142、DVM-190。状态：完成。

## 边界

- loader 保存 service 规范类名、enabled/exported、继承或覆盖的 process/permission、
  stopWithTask/isolatedProcess/singleUser flags 和自身 `meta-data`；保留 `value`/`resource`
  区别。session 注入唯一 Manifest 事实源。
- 只按当前包完整 ComponentName 查询。支持 0、GET_META_DATA、GET_DISABLED_COMPONENTS
  及组合，按 application/component 启用状态过滤。缺失抛 NameNotFoundException；
  未知 flags 或未装配 inventory 记账并明确失败。service/application 元数据各归其对象。
- 不查 DEX 类是否存在，不创建独立 service 进程，不引入包服务、Binder 或广播投递。

## 验证

- Windows Release `ogplay`/`ogplay_tests` 构建通过；相关 Manifest 与双解释器定向测试
  共 6 项、1099 个断言通过，覆盖字段、元数据类型、禁用、重复查询与 GC。
- Dead Trigger APK/OBB、无 Profile、关闭 survey 的相同启动路径越过
  `getServiceInfo`；下一首错为 `PackageManager.getPermissionInfo(String,int)`。
  这不代表游戏兼容验收。
