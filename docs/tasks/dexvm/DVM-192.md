# DVM-192 · 当前包权限定义查询

目标：按 Manifest `<permission>` 定义回答 `PackageManager.getPermissionInfo(String,int)`。
依赖 DVM-77、DVM-142、DVM-191。状态：完成。

## 边界

- BootDex 从固定 API 19 framework 纳入 `PermissionInfo`、`PermissionInfo$1`；
  普通构造、复制与 Parcelable 保持原版 Java。
- loader 保存定义的名称/所属包、protectionLevel、group、flags、description 和自身
  `meta-data`；session 将定义独立注入。`uses-permission` 请求与现有简化 granted 集合
  均不作为定义来源。
- 查询仅覆盖当前 APK，支持 flags 0、GET_META_DATA。未定义抛
  NameNotFoundException；未知 flags 或未装配事实记账失败。暂不提供外部包、
  固定平台权限目录或系统包服务。

## 验证

- BootDex build/check、Windows Release `ogplay`/`ogplay_tests` 构建通过；
  Manifest 与双解释器定向测试通过，并复跑 receiver/service 邻接回归。
- 本机 `.local/aosp` 五个来源 JAR 的 SHA 与旧 manifest 记录不同；生成 manifest 已按
  本机指定来源更新，不能据此宣称与旧 BootDex 除新增类外字节等价。
- Dead Trigger 无 Profile、关闭 survey 的相同 APK/OBB 启动路径越过原首错：
  未定义的 Google 权限抛 NameNotFoundException 并由游戏记录；随后到达
  `PackageManager.queryBroadcastReceivers(Intent,int)` 方法解析错误。
  这只是 reached-fault，不代表游戏兼容验收。
