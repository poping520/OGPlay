# DVM-194 · BootDex 同源系统资源映射

目标：修复原版 SQLite Java 栈消费的 framework 资源 ID 与宿主映射不一致。
依赖 DVM-186。状态：完成。

## 实现与边界

- `tools/bootdex/api19-system-resources.json` 为受审事实源，记录资源名、类型、ID、
  AOSP 默认值、消费者及 framework/config.xml 的 SHA-256 身份。
  CursorWindow 配置也来自当前 framework 的实际调用点；无旧 ID 别名。
- builder 从 framework.jar 反汇编 SQLiteGlobal/CursorWindow，核对每个配置方法内
  Resources 调用的常量寄存器、ID 与类型，并检查消费者覆盖完整。来源哈希、默认值或
  映射不一致均明确失败。build 生成宿主头文件及 manifest 绑定元数据；check 拒绝过期产物。
  原版 BootDex Java 字节未改变，也未把 SQLiteGlobal 方法改为 intrinsic。
- Resources.getString/getInteger 共用生成表；未知 ID/类型仍抛 NotFoundException。
  只提供受审配置，不引入完整 framework-res 或系统资源服务。
- 显式保留 OGPlay 的 journal mode `DELETE`，覆盖本地 AOSP 默认 `PERSIST`。
  后续恢复 PERSIST 需独立验证事务、重开和 journal 恢复；读取 WAL 配置不代表支持 WAL，
  数据库 backend 仍明确拒绝 WAL。

## 验证

- BootDex builder self-test 通过：变异覆盖来源哈希、ID、默认值、类型、方法、常量寄存器、
  重复声明、缺失覆盖理由及未审计的新资源查询。BootDex build/check 通过。
- macOS arm64 Release `ogplay`/`ogplay_tests` 构建通过；4 项定向测试、246 条断言通过。
  双解释器调用原版 SQLiteGlobal 六个配置方法并确认 interpreted/code 身份；
  CursorWindow 构造、旧 ID/错误类型拒绝、真实文件库建表/写入/关闭重开与 DELETE 模式受检。
  复用既有 ContentValues 持久化与 WAL 拒绝测试；未跑全量测试。
- Dead Trigger 相同 APK/OBB、无 Profile、空临时沙盒、关闭 survey 启动越过数据库首错。
  下一阻塞：`android.app.NativeActivity` 层级缺失导致 UnityPlayerNativeActivity 加载失败，
  被游戏捕获后最终报 `onCreate did not install a content view`。仅为 reached-fault，
  未作游戏兼容验收，不继续修下一独立问题。
- manifest 原有来源记录变更保留，本次只增添系统资源表/生成头文件的哈希绑定。
