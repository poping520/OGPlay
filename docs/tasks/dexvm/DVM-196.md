# DVM-196 · 进程逻辑输入设备查询

范围：游戏直接调用的 InputDevice 枚举、基本信息和轴范围。沿用当前桌面输入映射，
不引入 Android 输入服务。依赖现有 session 输入投递、DVM-195 NativeActivity 与 BootDex。

- 原版 InputDevice、MotionRange、CREATOR 纳入 BootDex；普通 getter、范围查找及 getRange
  执行原算法。getDeviceIds/getDevice overlay 读取进程目录，返回独立数组/对象快照。
- app process 启动前建立键盘 id=-1、映射触摸 id=0；QueueInput 对 Java/native 两条投递
  路径统一 id。触摸只有逻辑窗口 X/Y 轴，不发布 SOURCE_TOUCHPAD。
- 未知 id/轴返回 null。键盘映射、hasKeys、震动与 Parcel 写入明确记账失败；Parcel 读取、
  完整反射依赖、热插拔与 NDK 未发布符号不在本轮支持范围。

验证：BootDex build/check、受影响 release 目标构建通过；双解释器查询、未知 id/轴、
数据隔离、source 筛选、范围算法及生产键盘事件 identity 回归，共 11 用例/445 断言通过。
新增三类无 native，依赖与 overlay 核对记录于 `.local/input-device-dependencies.json`；
运行目录 BootDex 与生成物哈希一致。原 APK 首错复现见 CURRENT。

证据：`.local/input-device-{boot-build,boot-check,build,tests,startup}.log`。
