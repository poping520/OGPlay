# DVM-197 · intrinsic Renderer 的 EGL 初始化与资源归属

范围：沿用现有 lifecycle 渲染线程，为 intrinsic GLSurfaceView 消费游戏配置的
EGLConfigChooser/EGLContextFactory 或默认 config/client version；通过现有 Java EGL10
facade 和 Native EGL registry 创建、绑定、交换及释放真实 ANGLE 资源。不引入新的 GLThread
或 GLES 转译器；guest 自带 GLSurfaceView 的 EGL 驱动路径不变。

- 初始化 current context 后排空 queueEvent，再调用 onSurfaceCreated/onSurfaceChanged；
  回调传真实 GL/config wrapper，每帧由同一 EGL surface swap 发布。
- EGL wrapper 加入进程 GC roots；切换 Activity 和退出时先解除 current，再释放拥有的
  Surface/Context，自定义 factory 收到 destroyContext。创建失败明确终止，不调用 renderer。
- eglDestroySurface 成功时清除对应 window wrapper，允许后续建立新 Surface。
- 暂停保留策略、context-loss 恢复和多 GLSurfaceView 并存不在本轮支持范围。

验证：受影响 release 目标构建通过；双解释器、默认/自定义 factory、创建失败、事件与
回调次序、真实 GLES2 current、红色像素 swap、GC 后引用、资源释放及既有 proc 分发回归，
合计 6 用例/414 断言通过。证据：`.local/renderer-{build,test-build,tests}.log`。

原 APK/OBB 同路径运行（仅加 `--exit-after-frames 3` 上限）现在在 unityAndroidInit
主动 exit_group(1)，前置日志为 `Mono requires /proc to be mounted`；本次未出现原
GL_VERTEX_ARRAY 报错，但提前退出阻止了同一次 nativeRender 的端到端复验，不能据此
宣称游戏渲染通过。证据：`.local/renderer-startup.log`。
