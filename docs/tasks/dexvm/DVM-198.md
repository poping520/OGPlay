# DVM-198 · BootDex 系统资源随 ROM 自动绑定

状态：完成（有界 ROM 资源绑定）。依赖 DVM-194；决策见 [ADR-0077](../../adr/dexvm.md#adr-0077)。

## 工作范围

- 配方维护语义、消费方法和 OGPlay 配置值，移除固定 ROM ID 与来源哈希门禁。
- 从最终 DEX 提取资源 ID，验证类型、覆盖和冲突；支持常量/move/invoke-range，
  跨控制流无法证明的值明确失败，不猜测资源、不修改原版 Java。
- schema 1 映射内嵌 BootDex，运行时每 context 从封存归档读取；移除编译期生成头。
  无 APK/宿主回退，缺失/畸形映射显式失败；换 ROM 无需重编译宿主。
- 复用既有归档和 core JSON，不引入 framework-res、系统服务或新依赖。

## 验收

- builder 自测：两组 ID、寄存器传递/range、未知值/分支、类型/冲突/覆盖失败。
- 当前 ROM BootDex build/check，制品映射与最终 DEX 同源。
- Windows 受影响目标及 DVM-198/DVM-194、DVM-186 双解释器建表/写入/重开验证。
- ROM 厂商新增类/native 与真实游戏兼容不属于本任务验收。

## 证据

- builder self-test、当前 ROM build/check、Android runtime payload 校验通过。
- Windows `ogplay_tests`、`ogplay` 构建通过。测试目标已有 C4996/C4834 警告被视为错误；
  本次验证构建以进程环境 `_CL_=/wd4996 /wd4834` 屏蔽这两类警告，未修改相关源码。
- 定向 5 用例/319 断言通过：DVM-198 两组 ID/错类型/旧 ID 拒绝及缺失/畸形表无 APK 回退；
  DVM-194 原版配置与 CursorWindow；DVM-186 双解释器建表/写入/重开；DVM-88 ContentValues。
- 两组 ID 使用合成映射和调用片段验证；实际只构建本机这一套 ROM，未宣称多套完整 ROM 或游戏验收。
- builder 文件变化使 JNI generator 记录过期，已运行 build-guest-jni；输出库哈希未变，载荷校验通过。
- 日志：`.local/rom-resources-{check,build,build-verified,tests,jni,payload}.log`。

以后更换配套输入 JAR，运行 `python tools/bootdex/build_bootdex.py build` 和 `check` 即可。
宿主首次升级需本次 C++ 构建；后续仅资源 ID 变化无需重新编译宿主。
