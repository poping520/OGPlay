# DVM-204 · JNI 字符串正文预算与长字符串往返

状态：字符串修复及强制结束后的保存重载已验证；正常退出仍阻塞。
决策：[ADR-0087](../../adr/runtime.md#adr-0087)。

- `NewStringUTF` 正文逐页扫描使用独立预算，保留 guest 地址、权限、溢出与 Modified UTF-8 校验。
- 分别报告扫描预算、内存故障、编码与分配失败，保留调用帧；只观察长度，不转储正文。
- 两种 chars 按需映射 guest 页并共用临时副本预算，释放/失败回滚，不再使用固定 64 KiB 区。
- 不修改游戏、BootDex、加密算法或支付服务。

## 验证

- Windows `windows-msvc` Release `ogplay` / `ogplay_tests` 构建通过。
- 定向 44 用例/4565 断言通过：ARM JNI 1023/1024/1025 字节及预算端点、跨页、编码
  空字符/代理对、非法编码/未映射/权限/地址溢出、UTF-16 与共享副本预算、release 回收，
  以及 70000 字符的两种副本与 NewString 往返。旧“1024 非零字节即未终止”测试已修正。
- 原 APK/OBB、无 Profile、独立持久沙盒，自由运行 MCP/diag：第 858 帧关闭剧情弹框，
  后续帧持续推进、无 guestFault。NewStringUTF 实际输入为 2352 bytes / 2352 UTF-16 units，
  LR=0x6142cca8；此长度与落盘 DeadTriggerGameData 一致，不根据长度宣称已捕获完整正文。
  游戏/玩家数据分别为 2352/2448 字符，已写入 shared_prefs。
- shutdown 后第 2492 帧停在 Profile lifecycle 清理，有限等待仍未退出；保存诊断后强制
  结束。相同沙盒重启，第 606 帧进入任务地图，开场剧情没有重现；两项加密数据 SHA-256
  与重启前完全一致。证明落盘进度被重载，不能宣称正常退出或完整游戏兼容验收。
