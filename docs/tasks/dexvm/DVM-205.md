# DVM-205 · DEX 注解缓存与分层资源预算

状态：完成。依赖：DVM-69、DVM-181。关联：ADR-0089。

## 范围与决定

修复整个 DEX 固定 65536 节点上限误拒绝正常大输入的问题。
annotation item/set 按当前 ParseDex 调用内的偏移缓存，引用共享受检、不可变解析结果；
保留 DexImage 既有拥有型元数据接口，输出复制单独记账。
单项复杂度、整体解析/引用/投影工作量、容器存储预算分开；整体随受检输入规模增长，
同时有通用硬上限。所有分配前检查范围和预算；超限保留类型、偏移、用量及上限。
不调整 APK、BootDex 配方、guest 堆或游戏 Profile，不扩展反射查询面。

## 验收

- 通用合成 DEX 覆盖超过旧节点预算、共享 item/set、输出元数据身份与内容。
- 定向覆盖工作量/存储/单项上限、非法索引、截断/巨大数量、深层嵌套。
- 复用 DEX parser 与 Class/Field 注解反射回归。
- 相同 APK 无 Profile、无 survey、隔离沙盒启动一次；记录原错消失及下一首错。
  此证据只代表 reached-fault，不代表游戏兼容验收。

## 实测

- macOS Release 的 ogplay/ogplay_tests 受影响目标构建通过；loader 源码独立
  `-Wall -Wextra -Wconversion -Wsign-conversion -Werror` 编译通过。
- parser 定向 23 用例/130 断言；两条 Class/Field 注解回归覆盖 switch/threaded，
  加来源诊断共 3 用例/388 断言，全部通过。未运行全量测试。
- 现有畸形注解测试的定位器错误选择了只有字段注解的目录，已作必要维护；原版独立
  编译也复现该定位失败（`baseline-test.log`）。公共 BootDex 测试夹具按当前制品的
  Android native owner 集合补绑定真实既有 handler，未伪造 native 成功或修改制品。
- 目标 APK 和当前 BootDex 均通过解析；唯一节点数由 `parse-fixed.log` 提供，
  可与前轮 `counts.json` 核对；去重后仍超过旧总上限的输入受检。
- 原 APK、无 Profile/无 survey、独立持久沙盒、1 帧上限启动，进入 TermsActivity，
  完成 1 presented frame 后正常退出（0）；原 prepare 错消失，本轮无新致命首错。
  后续帧、交互及 title gate 尚未验收。
- 证据均在 `.local/annotation-budget-analysis/`：`build-verified.log`、
  `test-build-diagnostics.log`、`parser-tests-final.log`、`reflection-tests-final.log`、
  `parse-fixed.log`、`startup-fixed.log`。最初测试筛选意外匹配无关 DexVM 用例，
  已收窄到上述定向测试；初次输出不作为验收证据。
