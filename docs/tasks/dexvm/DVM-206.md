# DVM-206 · 进程虚拟键盘字符映射

范围：API19 KeyCharacterMap/KeyEvent 普通算法与内嵌值类来自 BootDex；
load 与 InputDevice 消费已有进程输入目录，未知设备回退虚拟键盘，缺失目录明确失败。
native 字符、标签、数字、匹配与 fallback 查询使用 AOSP Virtual.kcm 的受检生成数据；
Java KeyEvent 字符查询复用同一映射，修饰键归一化与组合重音标记保留原版 Java。
不引入 InputManager/Binder、动态宿主布局或游戏专属分支。

边界：虚拟 FULL 键盘与空 SPECIAL_FUNCTION 映射使用不可变 selector，不持宿主指针或
guest 引用；Parcel、事件合成、物理键能力、Unicode 分类/重音合成与 KeyEvent system-key policy 明确记账失败。

验收：BootDex build/check、数据重生成校验，双解释器键盘/设备/元数据回归，实际 JNI
查类及 load/get，原 APK/OBB 无 Profile/无 survey 的按键触发路径复跑。

验证：macOS Release 受影响目标构建通过，BootDex build/check 与生成表 --check 通过；
双解释器定向回归 6 用例、1662 断言通过（含 JNI 查类、load/get）。证据在
`.local/key-character-map-fix/`。

原 APK/OBB 默认存档在 f=6 先触发独立 `Dialog(Context)` 评分弹窗缺口。独立空沙盒
进入第一关，发送 W/A/Shift+D/空格后原 KeyCharacterMap 缺类错误消失；f=3954
下一首错为已记录的 `string constructor receiver is not an unbound string instance`。
CLI 窗口无法被 CUA 识别，临时 .app 包装相同 SHA-256 的 Release 可执行文件完成操作。
这是 reached-fault 证据，完整游戏与 Windows/Linux 实跑未验收。
