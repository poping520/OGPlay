# DVM-209：进程内 Wi-Fi 锁状态与租约

状态：两类锁实现及 macOS 定向验证完成；title/跨平台未验收。设计：[ADR-0092](../../adr/runtime.md#adr-0092)、[ADR-0093](../../adr/runtime.md#adr-0093)。

范围：API19 WifiManager 离线查询、createWifiLock 与 createMulticastLock；两类锁的 AOSP 客户端
引用计数、独立 held、模式切换、isHeld/toString 和过量 release 异常归 BootDex Java。
C++ 只维护 owner-attached 租约，分别检查 WAKE_LOCK/mode 1/2/3 与
CHANGE_WIFI_MULTICAST_STATE；两类锁合计每 manager 50 个活跃租约，逐对象释放并经
GC/退出清理。MulticastLock finalize 沿原版切换非计数再 release，原服务端同 UID 清理
副作用不纳入。租约不代表连接/组播接收；WorkSource、组播传输、Binder/system_server、
宿主网卡/电源管理不在范围内。

验收：双解释器测试必须验证普通方法仍为 Java；计数/非计数、模式切换不重置计数、
权限拒绝、混合数量上限、多锁释放/不同 manager 隔离、GC strong edge/清理；BootDex build/check、
payload 校验与受影响目标构建；原 APK reached-fault，只记录原错消失与下一阻塞。

第一阶段（WifiLock）验证：Release ogplay/ogplay_tests 构建、BootDex build/check、API19 payload 校验通过；
双解释器 WifiLock 与既有 value/GC/WifiInfo 回归 6 用例/801 断言通过。
原 APK 无 Profile/survey、隔离沙盒 8.2 秒退出 1，无超时；setReferenceCounted 首错消失，
下一首错为 WifiManager.createMulticastLock(String) 缺口。只作为 reached-fault，黑屏未验收。
证据 `.local/wifi-lock-fix/`；no_raw_output、capabilities_monotonic、documentation_layout 通过。
既有 intrinsic_layout 因未改动的媒体 TU 不在清单仍失败，未扩大本次范围。
构建器输入扩展要求重建 JNI 来源记录；原 NDK 的额外目录项通过只含实际 host 的本地
symlink 视图隔离，未改动工具链或 payload 校验规则；JNI 二进制哈希保持不变。

第二阶段（MulticastLock）验证：补齐根类 Object.finalize 的 API19 protected 空实现，
保留子类 super 调用；不新增自动 finalizer 调度。core-only 测试的既有 native owner
清单同步纳入 WifiManager 与两类锁，绑定真实 Android handlers，未放宽未绑定检查。
Release 受影响目标、BootDex build/check、API19 payload 校验通过；双解释器锁/value/GC
及 Object identity/clone/反射回归共 12 用例、1721 断言通过。
原 APK 无 Profile/survey、隔离沙盒观察 60 秒无新的致命报错，原 createMulticastLock
首错消失；45 秒快照含 glDrawArrays/eglSwapBuffers，随后超时取证并强制结束（总计 65.1 秒）。
只证明越过首错，未确认 FPS、黑屏、title 或 Windows/Linux 兼容；resolveService flags、
File.getAbsolutePath 的已捕获异常仍可见。证据 `.local/multicast-lock-fix/`。
