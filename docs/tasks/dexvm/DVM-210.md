# DVM-210：原生 JNI 附加线程执行归属

状态：有界实现与 macOS 定向验证完成；完整 JNI 长尾与跨平台 title 未验收。
依赖：DVM-27/50 的 execution context、VM lock 和独立 A32 执行器。

问题：原生 clone AttachCurrentThread 后回调 Java，入向桥忽略 guest TID，使用默认
context=1。主线程 native/阻塞释放 VM 锁后，两宿主线程混用帧栈/结果，导致
move-result-wide 不匹配或宿主崩溃。归属检查实跑拦截到 guest TID=2 使用 context=1。

范围：入向 Java 调用/字段 clinit/monitor 操作绑定每个已附加 guest TID 的独立 context；
最多 64 个存活原生附加 context，重复调用复用，detach 后释放。Java 出向借用该 clone
既有 CPU/SP/TLS 和嵌套 CPU 池，不创建新的宿主线程。阻塞期间保持 context 宿主归属，
禁止异宿主重入和删除活动 context。附加 Thread 身份按需发布并进入现有 VM runtime/GC
根；稳定 id/默认名称、daemon、存活、monitor/interrupt/wait/join 共用现有机制。
null context loader 与 main group 采用 API19 原生附加构造边界；不支持附加 name/group，
不宣称全部 JNI 反射执行路径或完整系统线程语义。

配套局部修复：SandboxStore 的四个语义根与 VFS 使用相同 ASCII case-fold；package/meta/
安装目录原样保留，根内既有文件拼写不迁移。入向、枚举、用量与删除使用同一根规范化，
防止混合大小写包名路径落入错误根或重复计费。

验证：Release ogplay/ogplay_tests 构建；双解释器停泊归属/活动删除拒绝、JNI 附加独立
身份与 wide 返回、daemon/重附加、monitor detach、64 context 上限及既有 OnLoad/字段/
Thread 回归；沙盒四根、重开/删除/配额/实例隔离以及 Context getDir/文件回归，共
44 用例、1270 断言通过。原 APK 无 Profile/survey、隔离沙盒复现已越过原错，下一首错
为缺少 ReentrantLock$FairSync；退出 1，进程已关闭。这是 reached-fault，黑屏未验收。
证据：`.local/tales-context-20261003/`。Windows/Linux 未实跑。
