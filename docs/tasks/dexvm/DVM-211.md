# DVM-211：进程内 PendingIntent 令牌与闹钟取消

状态：有界实现与 macOS 定向验证完成；完整游戏、Windows/Linux title 未验收。
依赖：BootDex Intent、DVM-18 execution lock、GC owner state、session teardown。

范围：仅当前 APK 创建的 service/broadcast 令牌。原版 Intent 复制/filterEquals/replaceExtras
执行值语义；操作种类、创建包、requestCode 与非查找控制 flags 构成身份。支持
NO_CREATE/CANCEL_CURRENT/UPDATE_CURRENT，保留 API19 CANCEL_CURRENT|NO_CREATE 的旧令牌
返回语义。ONE_SHOT/fill-in flags 仅保存身份，投递未实现，不宣称一次性发送已支持。
仅普通 Intent 与 BootDex Uri，selector、content provider MIME 推断及未知 flags 明确失败。

registry 为进程上下文私有弱表，活令牌 trace 快照，GC sweep 清理；闹钟条目强保活令牌。
现有 VM execution lock 串行化多 guest 线程访问，退出停止创建并清空记录。没有宿主指针或
平台系统服务依赖，不引入 Binder/system_server、跨进程授权、持久系统闹钟或 started service。

AlarmManager 只提供进程内单例与 cancel：移除相同令牌的条目，null/无匹配合法；不使
PendingIntent 失效。PendingIntent.cancel 使令牌失效并清理其闹钟条目。暂无生产注册入口，
set/setExact/setWindow/setRepeating/setInexactRepeating 与 send 均记账明确失败。

验收：双后端身份匹配/flags/快照更新、取消区别、GC/退出、两宿主线程独立 context 并发；
原 APK 同路径复现确认缺方法与 alarm 缺口消失，记录下一首错并关闭进程。完整游戏与跨平台
title 运行不在本 WU 的已验收范围。

证据：`.local/pending-intent-fix-20261003/`。

结果：macOS Release ogplay/ogplay_tests 构建成功；双解释器 2 用例、440 断言通过。
原 APK/隔离沙盒复现越过 PendingIntent.getService 与 alarm cancel，f=240 下一首错为
ReentrantReadWriteLock 缺类（FileSessionStore 构造）；退出码 1，进程已关闭。
此为 reached-fault，未证明黑屏或完整游戏兼容已修复。
