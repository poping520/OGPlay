# DVM-212：封存 classpath 资源 URL 与只读连接

状态：有界实现及 macOS 定向验证完成；完整游戏与 Windows/Linux 尚未验收。
依赖：ClassLoaderFacade、sealed BootDex/APK、严格 ZIP loader、原版 URLConnection/流。

范围：Class.getResource/getResourceAsStream、ClassLoader.getResource/getResourceAsStream 与
两个 system resource 方法共用查找源。保留 API19 libdvm 相对包名、单斜线剥离、null 参数
及 primitive 的 system loader 回退；application parent-first，bootstrap 不见 APK。

CoreIntrinsicServices 以归档 guest 路径/entry 标识查找结果，按该位置读取，不再次按 loader
查找，防止来源被替换。BootDex 的稳定资源身份为 `/system/framework/bootdex.jar`，APK 使用
context 的 `/data/app/...apk`。这些仅标识封存 backing，不允许打开宿主或任意 VFS 归档。
标准 `jar:file:...!/entry` 对路径/entry 百分号编码，可序列化文本并重建 URL；原始 entry
精确匹配，不归一化穿越路径。来源必须已登记，解压与 CRC 复用严格 ZIP loader。

URL.openStream 虚派 openConnection().getInputStream()。只读 ClasspathURLConnection 调用
原版 URLConnection 构造器，url/connected 与 input 为 guest GC 字段，无宿主引用侧表。
每个连接持有自己的真实 ByteArrayInputStream；doInput=false 抛 ProtocolException，
close/读取/Properties.load 使用原版 Java。未登记来源、损坏数据抛 IOException，缺 entry
抛 FileNotFoundException；resourceAsStream 按 API19 捕获 IOException 返回 null。
未注入 provider 记账并抛 UnsupportedOperationException，不能伪装资源不存在。

不实现动态 classpath、网络下载 JAR、完整 JarURLConnection/JarFile、资源枚举、写入或
协议 handler 工厂；普通 HTTP/HTTPS 策略保持既有范围。无宿主平台 API，不改 APK。

验收：双解释器名称/loader/URL 重建/真实流/独立游标/异常，生产 provider 对真实 ZIP 的
parent-first/CRC/Properties 读取；复跑原 APK 记录 reached-fault 与下一首错并关闭进程。
Windows/Linux 游戏运行与黑屏消失不由这些检查代替。

证据：`.local/classpath-resource-url-fix-20261003/`。

结果：macOS Release ogplay/ogplay_tests 构建成功；4 个定向用例共 658 断言通过，
覆盖双解释器、生产 ZIP provider、GC 字段保活、离线策略与连接创建不触网。
原 APK/隔离沙盒已越过 Class.getResource，f=193 下一首错为
PackageManager.getPackageArchiveInfo（广告 SDK 检查 Activity 声明）。退出码 1，进程已关闭。
这是 reached-fault 证据，黑屏仍未验收；后续 PackageManager 能力不纳入本 WU。
现有 URL 回归的 enabled openConnection“未实现”预期已过期，改为检查真实连接及无 I/O。
