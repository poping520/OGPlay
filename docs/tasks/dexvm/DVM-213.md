# DVM-213：封存 APK 的 PackageInfo 归档查询

状态：有界实现与 macOS 定向验证完成；完整游戏/跨平台未验收。
依赖：当前 APK sealed Manifest/path、guest VFS、既有 PackageInfo/ApplicationInfo 工厂。

范围：getPackageArchiveInfo(String,int) 只读当前已加载 APK。通过 VFS CanonicalPath/Stat
确认注册的只读 backing，复用启动时已解析 Manifest，不重建 PackageParser 或安装数据库。
支持 flags=0、GET_ACTIVITIES、GET_DISABLED_COMPONENTS 及组合；meta-data、权限、签名、
service/receiver/provider 等归档查询 flags 暂不支持，须记账抛 UnsupportedOperationException。

与 getPackageInfo 共用物化逻辑，但 ApplicationInfo 分 installed/archive：归档 uid=-1，
sourceDir/publicSourceDir/dataDir/nativeLibraryDir 为 null，安装/更新时间为 0，遵循
API19 PackageManager.java 的默认 PackageUserState（含 FLAG_INSTALLED），不注入安装身份。
其余已支持名称/版本/label/targetSdk/enabled 与组件字段来自 sealed Manifest。
这些是既有有界字段集合，不宣称完整 PackageParser/ApplicationInfo 属性实现。

Activity 数组按 Manifest 顺序保留 activity-alias；未请求或无声明时 null，仅有禁用项时
返回空数组，GET_DISABLED_COMPONENTS 才包含禁用项。Application.enabled 与组件 enabled
独立保留，archive 查询不引入安装态 override。每次结果/数组/子对象独立，不缓存 guest 结果。

null 路径抛 NPE。File.isFile 等价的 VFS 缺失/目录/非普通文件/路径 IO 失败返回 null；
已存在的未登记归档、缺 VFS/封存事实/请求所需 inventory 与未知 flags 明确失败，不能
伪装解析失败。路径归一化、相对工作目录及 alias 复用 VFS，不探测宿主路径或重新读 APK。

验证：双解释器查询面与字段、flags/alias/禁用项、路径和缺事实、结果快照隔离；复用
getPackageInfo 定向回归保证已安装查询语义不变。原 APK 同路径复现首错消失，记录下一
致命首错并关闭进程；完整游戏/黑屏消失与 Windows/Linux title 不在已验证范围。

证据：`.local/package-archive-info-fix-20261004/`。

结果：macOS Release ogplay/ogplay_tests 构建成功；双解释器下归档查询与既有
getPackageInfo 回归共 2 用例、576 断言通过。原 APK/隔离沙盒 f=256 已越过
getPackageArchiveInfo，下一首错为 java.util.zip.GZIPOutputStream 缺类，发生于后台
EncryptedWriter 写入事件。退出时 NativeCrypto 取消信息为清理阶段诊断，不能替代首错。
退出码 1，进程已关闭；此为 reached-fault，黑屏与完整游戏兼容仍未验收。
