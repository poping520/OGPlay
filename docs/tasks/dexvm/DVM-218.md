# DVM-218 · 有界退出清理与 native 退出控制

状态：实施中。依赖：JNI 出向调用、guest thread lifecycle、Activity teardown。
决策：[ADR-0095](../../adr/diagnostics.md#adr-0095)。

范围：owner 授权的根线程有界清理及重入；保留取消门、共享不可续期预算；
分阶段生命周期首错传播；真实 exit/exit_group 控制展开；退出后不重复 JNI/ELF
析构，Stop 失败也完成宿主资源回收且幂等。不修改游戏、不掩盖 CPU memory fault。

验收：普通帧仍取消、非 owner/阶段拒绝、预算耗尽、清理失败首错及 Stop 幂等、
exit code/origin 传播；原 APK 默认沙盒 1920×1080 菜单关闭路径一次。
证据 `.local/tales-exit-fix/`。Windows/Linux 实跑及完整 title gate 单独验收。

实施与验证（2026-10-05）：
- Release ogplay/ogplay_tests 构建通过；owner/root/阶段清理准入、重入累计预算、
  取消不污染 async failure、exit code/origin、原生 worker drain/关闭 clone 准入、
  fini 失败后 detach/Stop 幂等、双 Java 后端 onPause 首错/后续 onDestroy 共用回归通过。
- 最终定向选择 25 项：23 项通过，681 断言通过；另 2 项在退出前失败：DVM-125
  Activity 切换缺 ActivityNotFoundException，DVM-197 renderer EGL context creation failed。
  这两项不作为本次退出验证通过；未扩大范围修改其实现。证据 final-tests.log。
- 最后一次 worker JNI detach 收尾调整后，Release 重构建通过；正确筛选的 DVM-218
  定向回归 6 项/64 断言通过（final-focused-tests.log）。一次筛选参数误用导致选择范围
  扩大并在 AudioTrack 写入测试停滞；采样后已终止，未将其算作验证通过。
- 原 APK/default sandbox/1920×1080 菜单关闭：旧 teardown cancellation 不再误杀
  清理；onPause、NativeOnPause、surfaceDestroyed、onDestroy 已执行。加入 native/Java
  worker join 后，仍在 NativeOnDestroy 的原 libc exit 析构中读取 0x315f0001，退出 1。
  不重复 DSO fini、不吞 CPU memory fault，不把此次 reached-fault 当作退出兼容验收。
- trace2 对象快照及 trace3 硬件写 watchpoint：被误当 shader 遍历的地址是含
  PixelShader 的缓存节点，+32 处保留原 vtable；析构期间其首部被 guest 堆合并
  fHeap::Compact 的写入改变，写者为 root NativeOnDestroy 调用链。仍需定位缓存/
  布局/设备引用的首次失效原因，不能据此认定 double-free、宿主 UAF 或原 APK 缺陷。
- quiescent/ 保留菜单截图、结构化状态、shutdown 结果；guard 正常关闭，无遗留进程。
  退出内存故障未闭合，工作单继续在办；Windows/Linux 未实跑。

进一步定位：trace4 的硬件 watchpoint 与有界 guest 栈候选地址，经原 SO 反汇编核对为
fPool<fAllocator>::~fPool → fPoolBase::~fPoolBase/Shutdown/FreeBlocks →
fFree/fHeap::fFree/Compact，先归还含该缓存节点的内存块。随后 model layout 析构仍
遍历该区域并将缓存节点首部当 shader 数据，读取 0x315f0001。写者是根线程，且此轮
已先 join worker，因此不能再归因于 worker 尚未 join。下一步核对池与静态布局/cache
的 destructor 注册及依赖顺序；这只是有界候选栈与反汇编交叉证据，不声称完整 unwind。

trace6 在 NativeOnDestroy 入口读取原 libc 的 __atexit 两页注册表，并按其反汇编的
逆序规则解析：PixelShader 池（arg=0x3ef00c10）排在模型布局集合（arg=0x3eeaea3c）
之前，均属于同一 DSO。原 __cxa_finalize 的顺序与注册表吻合，尚未发现兼容层颠倒
该顺序的证据。此处读取 readonly 页使用 LLDB 原始 backing，避免 checked Read 的
锁重入；trace5 的 direct RW page table 无法读取 readonly 页，其空 pages 不作为缺失
注册证据。trace6/atexit.json、destructor-order.txt；再次重达同一故障并关闭进程。
下一步仍需确认退出前设备/缓存是否应先主动释放，及其未发生的调用/状态差异；不能
仅凭原版注册顺序推断原 APK 在 Android 上也崩溃，不能直接重排或跳过析构来报成功。
