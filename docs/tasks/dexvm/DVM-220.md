# DVM-220 · BootDex 传感器客户端与无设备后端

状态：有界完成。依赖：API19 BootDex、Context 服务工厂、Java/JNI 统一类目录。

范围：原版 SensorListener/SensorEventListener、Sensor/SensorEvent、SensorManager 与
必要类型；Legacy 普通字段、监听器映射和转换保留 Java，只替换 WMS 旋转查询。
具体本地 manager 提供空设备目录、注册 false 和无登记注销，不产生事件；不实现
SensorService/Binder/WMS、宿主传感器、动态设备或完整事件调度。

验收：分阶段 BootDex build/check、依赖/native/overlay 审计；双解释器接口形状与
旧/新重载、空列表/null/false/注销、GC、无回调及 OrientationEventListener 既有回归；
原 APK 关闭 survey 同路径 reached-fault。未修改的原版数学算法不作完整语义验收。

证据：`.local/wb-sensor-fix/`。

实施与验证（2026-10-07）：
- 接口阶段只增加原版 SensorListener 配方；build/check 通过，现有二进制直接加载新
  BootDex 后，原 APK 越过类层级首错，进入 Game.<clinit>；下一首错为缺 libjnigraphics.so。
- 家族阶段使用固定 API19 Sensor/SensorManager 原版源码，字节比对与本地 AOSP 完全
  一致；SDK 未公开接口由同编译单元保留，避免手写算法。SensorEvent、两代监听接口及
  trigger 值类型来自原版 framework.jar。Legacy 仅移除 WMS imports/handle 和构造器
  服务查询，替换为私有旋转边界；普通字段、缓存、LegacyListener/LmsFilter 算法不改。
- 删除旧 Sensor/SensorEvent/SensorEventListener/SensorManager intrinsic；Context
  工厂执行真实具体 manager 构造器后才发布单例，避免 Java 缓存字段未初始化。
  DEX 审计确认两个适配类只有七个明确 native 边界，未引入系统 native sensor queue。
- BootDex build/check、Release 构建、Android payload 校验通过；JNI 制品因 generator
  inventory 变化按既有工具重生成，SO 哈希未变。双解释器及 JNI 定向 3 项/1682 断言
  通过，覆盖原版接口形状、两代重载、空列表/null/false、不可变缓存、注销、输入错误、
  GC、零回调及既有 OrientationEventListener。
- 最终原 APK/外部数据、无 Profile/无 survey、隔离沙盒复跑到同一 libjnigraphics.so
  加载首错，退出 1，进程已关闭。尚未执行游戏内注册；无设备路径由定向回归验证。
  宿主传感器、动态目录、事件/旋转调度、数学算法完整语义及 title gate 未验收。
