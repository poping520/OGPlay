# DVM-225 · BootDex Java GL 接口与 native 适配

状态：有界完成。日期：2026-10-08。依赖：API19 BootDex、Java GLES 编组、EGL registry/NIO。
决策：[ADR-0107](../../adr/runtime.md#adr-0107)。

GL/GL10/GL10Ext/GL11/GL11Ext/GL11ExtensionPack 从固定 framework2.jar 导入。
GLImpl 保留 API19 源码的普通字段、构造、Buffer pointer 转发与 glGetString 转发，
仅改 allowIndirectBuffers 的系统包管理依赖为 targetSdk native 查询。删除仅有查询的
GL10$Impl 与重复接口声明。EGLContext 普通字段按实例惰性构造/持有 GLImpl，不再全局单例。

native ABI 从改编的固定 Java 源码生成，核对最终 DEX 的 descriptor/static/private；
仅注册 native，不覆盖普通方法。已有名字/重载复用 Java GLES 编组、current thread、
ANGLE 和错误事实。private pointer Bounds 检查 direct Buffer/remaining 并转发既有
client array 操作；Buffer 的 lifetime/地址归原 Java 强边与 NIO，不保存临时内存指针。
原 _nativeClassInit 的 JNI-ID cache 在直接使用 linker/NIO 的 host adapter 中不需要。

支持 direct Buffer client arrays；现代 targetSdk 的非 direct 参数按 API19 报 IAE，
旧应用允许间接 Buffer 的条件仍能查询，但实际持久映射未实现，记账报 UOE。
目录外 native 方法由既有桥接明确失败。接口形状不代表扩展能力，扩展字符串按 native
实际发布。完整 API19 JNI 检查、间接 Buffer backing、context-loss/暂停恢复及跨平台未验收。

验收：双解释器真实 invoke-interface clear/color、像素读回、Context-local 身份，
direct Buffer 在 GC 后仍能参与绘制、null/heap 参数拒绝；BootDex build/check、生成
一致性/native ABI 审计、载荷校验、相邻 EGL/GLES/GLU 与原 APK reached-fault。
证据：`.local/wb-java-gl-fix/`。
