# DVM-231 · JNI semantic 对象的真实类型登记

状态：有界完成。日期：2026-10-09。依赖：DVM-141 身份登记、共享 JNI stores 与 VM GC。

## 范围与实现

JNI NewStringUTF/NewString 创建对象后只发布引用，原 ClassOf 仅查普通对象登记表；
原生直接调用 String.getBytes(String) 因未登记运行时类而失败，方法实现本身已经存在。

ClassOf 增加显式真实类型解析接口，查表/jclass 未命中后在 registry 锁外调用。
bridge 只识别共享 store 中存活的 String、primitive/object array，在 VM 执行锁内
导入 object model 并使用 EnsureRegistered 登记真实类，与 GC 同锁；不新增 GC root。
primitive array 导入通过 interop 取得八种 kind 对应的精确数组类。未知 identity
不导入、不递归查类、不按方法 owner 猜测，冲突仍明确失败。线程停止后撤销解析器。
无 VM 后端保持原严格失败，不伪造 class；不扩展 synthetic array 的 FindClass/成员解析。
没有修改 BootDex、String 编码算法或游戏专属逻辑。

## 验证

macOS Release ogplay/ogplay_tests 构建成功；定向 8 项/417 断言通过。
新增用例在 switch/threaded 两种后端通过真实 A32 JNI thunk 创建两种字符串，并在任何
VM 发布之前调用 CallObjectMethod/V/A(getBytes)，核对 UTF-8 字节和返回 [B 类。
覆盖首次 GetObjectClass、字符串 IsInstanceOf、类型冲突、八种 primitive 数组及
String[] 实际类、global ref 跨线程查询、local frame 失效、GC 后 store/registry 清扫、
未知 identity 拒绝和 teardown 撤销；复用 DVM-141、jclass、string/array lease 回归。

既有 application-object 导入用例仍把已迁入 BootDex 的 Activity 断言为 external；
临时关闭新解析器仍同样失败，已仅维护这一条断言为 vm_instance。
