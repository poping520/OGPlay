# DVM-233 · ViewGroup 布局期间移除

状态：有界完成。日期：2026-10-10。依赖：UiTree 唯一层级、Surface holder 代际和 View 焦点。

## 实现

按 API19 ViewGroup.java 的 removeViewInLayout/removeViewInternal 语义，在 ViewGroup
提供一次 public virtual 入口，由 RelativeLayout 等继承。当前 View hierarchy 与几何
仍由 UiTree 唯一持有，不引入另一套 BootDex 子节点数组或完整 Android ViewRoot。

单个/范围移除共用实际层级和 Surface 退役流程；布局期间移除不主动调用 requestLayout/
invalidate，UiTree preserve_layout 策略只标祖先 draw dirty，不清已有布局请求、不重排
剩余缓存几何。普通 removeView/removeViews 保持布局策略，并虚派 requestLayout 后刷新。
null/非直属子 View 不改变层级，重复移除不重复 Surface 退役；detach 不销毁 View。

移除快照和焦点引用用 RootScope 保活，Surface callback 后核对 node/parent 仍一致，
不删除已经换代或转移的子树。动画、accessibility、hierarchy-change listener 不扩展。

## 验证

macOS Release ogplay/ogplay_tests 构建通过；定向 7 项/974 断言通过。
新增双解释器验证 dirty/实际像素移除、剩余几何直到 requestLayout 才更新、已存在 GONE
布局请求保持、null/非子节点/重复移除、复挂/id index、public non-final 方法形状、
普通移除虚派布局请求、焦点清除和引用保活期间 GC 安全。Surface 测试覆盖 destroyed
恰一次、复挂 created、新 parent 的 callback 重入不被外层误删；复用动态层级、
getParent、UiTree dirty/id 与 SurfaceHolder generation 回归。

现有 VisitAndroidSessionRoots 会把 ui_node_to_object 全表作为 session roots，包含
detached View，因此本次未宣称无 Java 引用后可自动回收。减少 UI registry 根需要
同时补齐 owner→children/background/holder 的真实引用边，单独收敛；本次不改 GC 所有权。
