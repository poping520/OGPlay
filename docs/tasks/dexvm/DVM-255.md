状态：规则、选择器、校准与“样本库引用类批次”完成；全部准入类受单 dex 64K 索引限制未能同批装入
（见下）。依赖 DVM-254（c4fede34）、Accepted ADR-0148/0147/0030。

## 边界

- 规则见 ADR-0148；选择器 `tools/bootdex/select_rom_java.py`（`--self-test`；默认只出报告，
  `--apply` 才写配方；`--only` 要求指定类必须被规则准入；`--scope referenced`；
  `--cha-precise` 仅作敏感性对照）。静态输入：固定 ROM 的 baksmali 缓存 + dump-surface。
- 不做：继承 intrinsic 类的准入、任何 intrinsic 行为、修 TML 的下一首错、C++ 变更（链接器无改动，
  未构建 C++，未跑 C++ 测试）。
- 本地证据 `.local/analysis/wu3/`（报告 report-*.json、冒烟 before/after、性能 baseline*/after*）。

## 选择结果（surface 基线：9,362 类 = intrinsic 265 / BootDex 2,013 / skeleton 7,084）

- 候选 7,073（skeleton 且在 ROM jar，扣除 DVM-102 审计冻结类），规则准入 5,405，拒绝 1,668。
- 拒绝主因：父类未准入 1,263（Binder/overlay 321、Enum 109、Handler 94、Exception 44 …）、
  含 native 176、虚调用目标不唯一 135、依赖被拒类 36、`<clinit>` 触达未实现目标 34、
  Binder 相关 11、缺依赖 7、反射/线程入口 3、与 intrinsic 交互 2（C++ 源码按名引用）。
- `--cha-precise` 敏感性：仅多准入 1 类，说明“不唯一即拒”的保守方向几乎没有代价。
- 预估转化（declared-unimplemented → 原版）：全部准入 2,478；本批 2,476
  （方法 1,933 + 抽象契约 326 + 字段 217）。

## 批量（关卡二）

- 全部 5,405 类 `--apply` 后 smali 汇编失败：单 `classes.dex` 引用索引超过 65535。运行时只读取
  `classes.dex`，多 dex 需改装载/链接契约，不属本 WU；因此采用 ADR-0148 第 4 条的批次范围：
  样本库引用的 478 个准入类 + 父类/`<clinit>` 必需类闭包 = 552 类（含校准 2 类）。
  BootDex 2,015→2,566 类，method_ids 29,224/65,536、field_ids 15,303、string_ids 41,833。
- 体积：DEX 2.95→4.10 MB（+39%），jar 2,957,284→4,108,400 B。
- 样本库重扫（32/32 APK）：declared-unimplemented 9,000→6,524（−2,476，与本批预估一致），
  新增 0；api19-present-missing 118、not-in-api19 21,171 不变。
- 性能（3 次中位，同 WU2b-1 方法）：TML 首帧 4.89→3.89 s（基线噪声 4.15–5.02 s），RSS 峰值
  3541→3537 MiB；PVZ 3.03→3.13 s（+3.3%），921→933 MiB（+1.3%）。均未超 10%。
