## 实施与证据

- `JavaLinkageError` 独立于 `DexVmError`，只携带类别和消息，不携带 guest 引用。两后端在
  Run 的同一出口创建 throwable 并按当前指令展开；宿主 Call、JNI 类解析和反射保留原 Java
  类型/身份。JNI FindClass 不覆盖回调已发布的 pending；注解缺类仍按 TypeNotPresentException 协议。
- 类首次触达才检查缺失层级、循环、超类/接口类别、访问和 final；失败状态阻止再次使用，
  后续 NCDFE。成功解析缓存仍检查 caller 权限，threaded 快速缓存仍检查失败类状态。
  Dalvik Class.cpp:2848 的 final-method createVtable 失败没有 pending，经 bail 抛 VirtualMachineError，
  不是任务举例中的 VerifyError；按源码实现。private 仍不进 vtable，WU7-1a 修正规则保持。
- Resolve.cpp 对应缺方法/字段为 NSME/NSFE、static/instance 与 interface 类别错配为 ICCE、
  类/成员访问为 IAE；new abstract/interface 为 InstantiationError、抽象分派为 AME。
  懒结构预检失败为 VerifyError。064 的剩余错误是 protected 反射字段先验证访问再验证 null receiver，
  对照 java_lang_reflect_Field.cpp validateFieldAccess 修正；setAccessible 仍绕过访问检查。
- 内部错误盘点：非法内部 class/method/field/unit handle、无应用 unit、slot/cache/布局破坏，
  intrinsic 声明/overlay/显式覆盖准入不一致、无法解析的 DEX 二进制/注册结构、执行预算与未支持
  native/opcode 的既有显式失败仍保留宿主诊断；不按 DexVmError 的字符串猜 Java 异常。
  FastCode 只接受预检输入，直接对损坏派生输入调用它仍是内部错误；未引入完整 verifier 数据流。
