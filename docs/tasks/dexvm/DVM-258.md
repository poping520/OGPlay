# DVM-258 · WU7-4 Dalvik 内存、finalization 与引用队列

状态：已完成（2026-10-21）。依赖 DIAG-7/WU7-3 的显式 GC 接口。

## 边界

- Runtime 内存统计、ActivityManager 内存档位与 VMRuntime 读取同一 JavaObjectModel 配置/记账。
- 原版 FinalizerReference、Daemons、PhantomReference、VMRuntime 进入固定 API19 BootDex；
  Java 队列、线程和 sentinel 协议不重写成宿主算法。不引入完整 VM/Android 系统服务。
- finalizer 守护线程真实执行 finalize，异常按原版吞掉并记录；原版 10 秒 watchdog 通过
  统一 Clock 检测，并在 guest 进程请求退出 2，不杀宿主。已有 uncaught handler 仍由原版调用。
- runFinalization 等待当前批次，包括已在执行者；后来的入队不扩展本次等待边界。
- 七目标用例、GC/内存双后端、全量基线零回归后更新、九正常场景不退于 WU7-1b；
  仅构建受影响目标，提交 main。

## 实施与证据

### 堆与 VMRuntime

- Runtime.maxMemory 对应当前 growth limit，totalMemory 至少为 allocated 的当前 heap target，
  freeMemory 为两者差。ActivityManager 的普通与 static 内存档位分别取 growth/maximum，
  单位 MiB；未使用宿主内存/固定资源档位。
- VMRuntime.getRuntime 及参数校验执行原版 Java。利用率按 Dalvik 1024 分度保存，native
  限制 0.2..0.8，直接用于既有 GC 后目标调整和增长；clearGrowthLimit 放开到 maximum。
- registerNativeAllocation/free 真实计数，水位由 initial target、利用率和 min/max free
  推导；越水位同步请求已有 STW 与当前批次 finalization，再更新水位。没有伪造 concurrent GC。
  负数与 4.4 一致抛 RuntimeException；超量 free 保持计数非负。
- trackExternalAllocation/Free、getExternalBytesAllocated、minimumHeapSize、gcSoftReferences
  在 4.4 已退役（源注释明确 Android 3.0 移除）：保留原版 true/0/空方法，不误接为新的
  native accounting。有效分配用 registerNativeAllocation/free。无 JIT 时 start/disable 无效果，
  与 Dalvik 无 JIT 构建一致。addressOf/newNonMovableArray、SDK 重配、VM 查询与 ROM 私有
  调参 native 仍记账明确失败；不扩大本单为完整 VMRuntime。

### Finalizer、引用与资源

- 固定 ROM 的 FinalizerReference、Sentinel、Daemons（含三个守护线程）、PhantomReference
  及 VMRuntime 原版类精确加入配方。实例分配 observer 经解释器调用 FinalizerReference.add，
  包含反射/JNI/clone 路径，真正覆盖 finalize 才登记；结果在嵌套分配前 root。
- GC 先按原强/软可达图清 weak/soft，再将待 finalize 的 referent 转移到 zombie、入队保活，
  复标记后才处理 phantom 和清扫。复活保留真实对象身份，finalizer 仅一次；队列入队唤醒等待者。
- 原版 FinalizerDaemon 执行 finalize，异常仅日志；watchdog 通过 System.nanoTime/Thread.sleep
  的统一 Clock 路径保持 10 秒阈值，默认只请求 guest exit(2)，不触碰宿主进程。030 输出与
  expected.txt 完全一致，超时诊断留 stderr。runFinalizersOnExit(true) 仍明确拒绝。
- 固定 ROM ReferenceQueue 为 LIFO，原版 sentinel 能先于已有 pending finalizer 执行。
  VM 在进入 runFinalization 时保留队列及 active 对象快照，原版 sentinel 完成后继续等待这批
  zombie/active 结束；后来的新批次不延长等待，InterruptedException 恢复当前线程中断标记。
- 074 同时暴露 result 根与 Thread 身份缺口：两后端进入新 invoke 前废弃旧 last_result/
  exit_result，不能让无用返回值保活弱引用；Thread runtime 根据不可复用身份区分新 Thread，
  原 host/context tombstone 仍按退出协议回收，不把 GC 复用句柄误判为重复 start。
- 自动 finalize 与既有 native owner GC 清理共存：已登记 cleanup/token 在进入 JNI、释放 VM 锁
  **之前**临时占有并清理 Java owner 字段；成功后退役，异常恢复仍未被改写的原 token。
  owner 在关闭期间 root，防止 GC/native finalizer 重复关闭，不将非法 token 当成功。
  回归在 native close 内重入 GC/force cleanup，验证只关闭一次、失败可重试。
- 原 ICU/zlib/crypto 回收断言改为 GC → 等待 finalizer → GC 后检查，不再要求异步 finalize
  在第一轮 GC 返回瞬间完成。BKS 的 HMAC 诊断原本延迟读取未 root 的数组，现持有显式 root
  并即时复制日志文本；实际密码学断言保持不变。
