## 阶段 1 实现与约束

- `runtime/jni/java_payload.h` 定义强类型 handle/borrow、typed accessor、统计和 provider 接口；
  不依赖 AddressSpace 实现、DexVM、OS，不使用全局指针或 TLS owner。
- integration 实现 `GuestJavaPayloadProvider`。默认 16 KiB slab 是可配置的夹具初始参数，
  小块上限 slab/2、8-byte packed，大块单独按宿主 backing 粒度分配；从整个有效 guest
  范围 first-fit 扫真实映射账本，不占满 1 GiB、不另设固定地址堆。零长也有独立地址。
- 每块有 owner/generation；typed view 在创建时校验范围/对齐/所有权并保活 backing。
  每元素只做视图边界检查与直接字节访问，无 AddressSpace 锁、无存活原子探测、无裸 span。
  view/pin 活跃时 Release 明确失败；最后一个 view 退役前 provider 关闭也不拆映射。
  owner 串行化 view 构造与 Release，guest 使用完/CPU quiesce 后才能释放其块。
- 配额遵循 ADR-0060 initial target → growth limit，保留 maximum 的上界验证；logical allocated
  与 committed 分计，失败不改变目标或计数。当前仅夹具独立使用，阶段 2 必须接入现有 VM
  charge/GC context，不能形成两份生产堆账本。阶段 1 pin 仅接口/夹具验证，不接 JNI 借用。
- memory 登记 owner 和完整映射，修改检查/实际变更在同一锁内；munmap/mprotect、mremap
  原区/FIXED 目标及 MAP_FIXED 替换任何重叠返回 EPERM 并记账。普通 mremap 仍 ENOSYS。
  restore 在 owner 活跃时拒绝（包括尚未分配/释放全部块），base 保持稳定；AddressSpace 和
  ledger 必须晚于全部 view，且不能在 owner 活跃时移动 AddressSpace。
- payload 和普通 RW 非 X 页正常进入两张直接表，observer 行为不变；没有新增 guest
  并发承诺。checked-only 仅保留未来有实测依据时讨论诊断开关的可能。
- `JniPrimitiveArrayStore/JniStringStore`、DexVM 对象模型、jni_guest 与 NIO 源码均未修改。

## 验证与微基准

Release 构建仅 `ogplay_tests` 及 JNI 基线实际使用的 `ogplaycore`（CLI 链接该动态库），未构建 GUI。
定向运行 memory、JNI、syscall、provider 主题：**254/254 用例、11,593 条断言通过**；
其中新增 12 个用例（含显式启用的微基准入口），普通运行不执行计时循环。
JNI `--check-baseline`：switch/threaded 各 **359/399（90.0%）**，零回归，不更新 baseline。
`tools/capabilities.py check` 通过（417 条）。未跑 dalvik 全量或游戏场景。
实际宿主页为 16 KiB、guest 页 4 KiB；邻页释放检查通过，不以此宣称 Windows/4 KiB 宿主实跑完成。

Release 微基准：65,536 个 uint32 元素（256 KiB），两个 noinline kernel 各执行 1e7 次邻元素
读取及当前元素写入，vector.at 与 typed view 使用相同索引/计算/校验和；七轮交替先后顺序，
比较各自中位数。通过统一 Clock::SteadyTimestampNs 计时；仅在
`OGPLAY_RUN_PAYLOAD_BENCHMARK=1` 时运行，不把机器耗时阈值做成易抖动的普通单测。
初版每元素重复检查存活状态比值 3.57，已在 I1 内改为 view 持生命周期、Release 拒绝活跃
view；生产阶段 2 未启动。最终七轮中位：vector **5,431,625 ns**，typed accessor **6,212,833 ns**，比值 **1.14383**，
低于 1.5 门槛（`benchmark.log`）。本阶段验收通过，不等于已授权执行阶段 2。

## 阶段 2 的输入与停止条件

1. 明确代表场景及采样窗口，再采数组/字符串数量、类型、长度分桶、峰值 live/pin/committed、
   slab 空闲/碎片和 native 热路径帧耗时，以此选择 allocator 参数；现有 state.json 没有这些数据。
2. 将现有 VM charge/GC/emergency reserve 通过显式 context 装配到 provider，统一 Java/JNI
   New/import 计量并避免双重收费；先闭合数组 active lease roots，再切 authority。
3. 明确 CPU/线程 quiescence、store/view 的销毁顺序；跨线程沿用 monitor/volatile/pthread/futex。
4. 补 Windows/4 KiB 宿主构建与定向验证。微基准超过 1.5 不进入生产迁移；本单不跑 dalvik
   全量或游戏场景，也不以空调用、FALSE 标记或删除复制语义夹具制造 pass。
