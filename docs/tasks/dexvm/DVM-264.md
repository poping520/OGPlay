## 范围与结果

- `platform_tables.h` 集中保存服务名、工厂选择与默认属性规则；运行时派发和
  `dump-surface.platform_tables` 共用该表，schema 保持 1，仅增加顶层字段。
  `system_services` 为 name → provided/unsupported，`system_properties` 为 key → 常量或来源说明。
  title_preflight、select_shapes、select_rom_java、dexvm_stub_gen 均按具名字段读取，兼容新增字段；
  消费者兼容性为静态审查，未扩大运行无关工具。
- 生成器从固定 Context.java、ContextImpl.java、System.java、ActivityThread.java 提取判据，
  入库 JSON 保存源路径和 SHA256；检查时不依赖 .local。重新生成与入库 JSON 逐字节一致。
  实际为 **44 个服务、37 个 initSystemProperties 属性键**；提示的 45 个 registerService
  包含了方法定义。user.dir 作为既有 specialProperties/VFS 工作目录额外保留。
- E1=ROM 注册但未提供的服务，E2=缺失 ROM 属性键，E3=常量值或来源规则明显矛盾；
  缺失键不再重复计 E3。来源以 `source: ...` 导出，静态声明不代替运行回归。
  检查器自测补充 E1/E2/E3、明显错误的 os 来源、非法输入及缺失平台表拒绝。
- 先导出原行为、逐键确认旧 A–D 未变化，再写入首轮 **E1/E2/E3=28/32/0**。
  这些是本单新类别的预期新增键，并非放宽旧偏差；旧基线与首轮 E 基线分别另存证据目录。
  判据身份包含 skeleton bytes 与平台 JSON，平台判据变化也受基线哈希约束。
- 最终 **A1/A2/B/C/D=0/542/183/13/2；E1/E2/E3=27/0/0**。
  check-baseline 无新增、重分类或类消失，随后 update-baseline 收紧到最终 E。
- 新增 **display**；DisplayManager.getDisplay/getDisplays 复用 WindowManager 的同一个
  managed Display。仅 ID 0；其他 ID 返回 null，presentation/未知类别为空集合。
  监听、外接/虚拟显示仍未实现；没有空壳 manager 来消除偏差。
  未注册服务返回 null；注册但未提供的服务记账 `dexvm.system_service.<name>` 并抛 UOE。
  其余 **X=27** 的逐项判断与能力依赖见 DIAG-9，不以 APK 引用频次作为 ROM 判据。

## 属性实现与来源

- getProperties 返回单一 live BootDex Properties，get/setProperty 与其共用状态；
  VM 持有 GC 根，物化后清空初始宿主 map。os.* 与 Java guest uname 共用
  NetworkPolicy.host_identity，不读取宿主 uname。Android 绑定在 Application 类初始化前
  调用实际 Context.getCacheDir()/File.getAbsolutePath() 改写 java.io.tmpdir。
- 有真实 Bionic 导出时调用 guest getuid/getpwuid，按 ARM passwd 布局读取 name/dir；
  真实查询失败明确报 Java 异常，无该来源的纯 VM/合成测试壳保留确定性默认。
  guest 环境存在时按 JAVA_HOME、LD_LIBRARY_PATH 覆盖，不访问宿主环境；
  无 environ 的合成壳保留默认。应用 class path 使用已封存的 package_resource_path。
- ICU 已加载且导出可用时，调用 guest u_getVersion、u_getUnicodeVersion、
  ulocdata_getCLDRVersion，语义对应 ROM 的 libjavacore → ICU 边界。
  原失败因模块计数与查询索引覆盖的命名空间不同，漏掉动态加载的 ICU；
  新 FindLibraryExport 按库名查询全部已加载模块，缺库/缺导出返回 optional，不隐式加载。
  native 调用按 integration 契约释放/恢复完整 VM 锁深度。
- 无 ICU 导出时使用 `data/android/19/manifest.json` 的 ICU 元数据，构建配置生成私有头文件：
  library.version ← icu.version；unicode.version ← icu.unicode_version；
  cldr.version ← icu.cldr_version。后两项补入 manifest，并由 payload validator 校验；
  **icu.data_version=51.1 是数据包版本，不能当作 Unicode/CLDR 版本。**
  C++ 不硬编码三个版本值。随附实际 guest ICU 查询结果也与这三项元数据一致。

### 默认值出处与审计缺口

以下路径均相对于固定 `.local/aosp/`；源码身份见平台判据 JSON 的 SHA256。

| 值/来源 | ROM 依据与 OGPlay 对应 |
| --- | --- |
| java.vm.version=1.6.0 | dalvik/vm/DalvikVersion.h:26–28 定义 1/6/0；native/dalvik_system_VMRuntime.cpp:183–189 格式化三段版本；OGPlay 无真实 Dalvik VM，沿用该兼容值 |
| java.home=/system | libcore/luni/src/main/java/java/lang/System.java:274–278，JAVA_HOME 缺失时的原版默认 |
| java.io.tmpdir=/tmp | System.java:280–282 的绑定前 fallback；ActivityThread.java:4153–4157 在应用绑定时取 cacheDir 覆盖 |
| java.class.path=. | dalvik/vm/Init.cpp:1223–1227，CLASSPATH 缺失时的原版默认；应用进程使用已封存归档路径 |
| user.name / user.home | System.java:315–317 从 getpwuid(getuid()) 取 pw_name/pw_dir；native/libcore_io_Posix.cpp:226–233 保留这两个字段 |
| ICU 三个版本 | System.java:328–330；native/libcore_icu_ICU.cpp:623–640 分别调用 CLDR/ICU/Unicode 查询；manifest 的 ICU revision 和数据 SHA 不变，新增语义元数据通过实际随附 guest 查询验证 |
| user.dir=/ | 原版 native/java_lang_System.cpp:76–80 从 getcwd 取值；OGPlay 纯 VM 为根目录，Android bridge 使用 guest VFS working directory |

`user.name=u0_a0`、`user.home=/data` 的纯 VM fallback 与本次实际随附 Bionic 在 guest UID
10000 下的返回值一致，双后端 native 来源测试已验证；但固定 4.4 Bionic 用户映射源码
不在本地参考树，**这两个 fallback 的独立源码行号/真机常见值出处仍是文档缺口**。
`java.library.path=/vendor/lib:/system/lib` 的无环境 fallback 同样尚缺独立 4.4 出处；
System.java:284–287 仅保证环境值存在时写入该键。依用户继续执行指示，这些来源审计缺口
不阻塞本单，不等同于完整系统属性/命令行覆盖支持。其余常量直接取自 System.java 的 p.put。
