### 夹具修正与首轮停止记录

首轮新增用例在加载断言前抛 bad_alloc；按当时停止条件记录并停止。用户续单明确
允许修正夹具后继续，未将夹具失败当作产品回归。

`MapProtectedAnywhere` 的 `FindFreeLocked` 使用宿主页作为起点对齐要求
（`src/memory/address_space.cpp:154–172/211–215`）。原 bounds 为
`[0x31000,0x32000)`，在本机 16 KiB 宿主页上没有合法起点，故抛 bad_alloc；
并非 DescribeMappings 或 DirectPageTable 容量不足。现在使用对齐的 `0x40000`，
size/bounds 均取 `BackingPageSize()`。扩展路径另需非空 namespace；夹具先成功装载
`base.so`，再动态追加，并验证既有 ELF 权限保留。

早先按测试名称宽匹配误纳入两个无显示器 EGL 失败，保留 `baseline-tests.log` 供追溯；
正式比较采用 `--source-file='*/tests/memory/*,*/tests/loader/*'`，不包含 EGL。
首轮格式工具 PATH 错误及失败候选日志同样保留；最终证据以上表为准。

## 两款 APK 的只读 ELF 推断

工具：`.local/analysis/wu11-3/run_elf_inspection.py` 与 `inspect_elf.cpp`，
链接现有生产静态库，不改 APK、不调用 guest constructor/JNI、不执行 guest。
日志：`elf-inspection.log`；探针编译日志：`inspect-build.log`。
本地新探针整体格式化、dry-run -Werror 后，用上述脚本重编译并复验；输入 APK 只读。
生产函数：ParseApkArchive / ReadApkNativeLibraryInventory / ResolveApkProcessAbi /
CollectApkNativeLibraryClosure / ParseElf32Arm / ReadElf32DynamicInfo /
ReadElf32SymbolTable / ReadElf32SymbolVersions / ReadElf32Relocations /
PreflightAndroidGuestLink / AuditAndroidNativeImports。

探针按生产依赖选择闭包、使用 BuildElf32LoadPlan 为独立 scratch 地址空间设置非重叠
load bias（从 0x30000000 起、64 KiB 对齐），经生产 Bionic namespace/符号解析完成
静态链接预检；该布局不是实跑进程布局。collector 本身只收集内容、bias 为零，故不能
直接把零 bias 输入映射预检；已在最终探针中分配合法 bias。

| APK / ARM 库 | NEEDED | 重定位类型:数量 | 首个生产链接预检错误 |
| --- | --- | --- | --- |
| DeadSpace / libDeadSpace.so | libc.so、libstdc++.so、libm.so、liblog.so、libGLESv1_CM.so | ABS32(2):465、GLOB_DAT(21):54、JUMP_SLOT(22):305、RELATIVE(23):22375 | strong ELF symbol is unresolved: glDrawTexfOES |
| SacredOdyssey / libsacredodyssey.so | libc.so、libstdc++.so、libm.so、libGLESv1_CM.so、libGLESv2.so、libdl.so、liblog.so | ABS32(2):2628、GLOB_DAT(21):6、JUMP_SLOT(22):279、RELATIVE(23):33308 | strong ELF symbol is unresolved: glBlendEquationOES |

两者所选 ABI 均为 armeabi；应用及实际依赖 guest 库均无版本表，全部重定位类型属于
当前支持的六种 ARM REL。依赖闭包的 libc/libstdc++/libm/libdl 均来自 API19 bundled
数据，图形/log 由现有 HLE boundary module 参与查找，没有发现缺库或版本问题。
因此最可能被 restore 掩盖的失败是上述 GLES1 OES 扩展强符号缺失，未修该独立能力。

静态 import audit：DeadSpace 23 条强缺口、9 条弱缺口；除了 GLES1 OES（draw texture、
texgen 等）还包括 `_Z17androidGetTmpRootv` 与 `_Z22androidGetExternalRootv`；
SacredOdyssey 1 条强缺口（glBlendEquationOES）、6 条弱缺口。
弱缺口主要为 AOSP guest 库的可选 C++ cleanup 导入，不按强失败处理。
完整列表及库 SHA-256 在日志；这些数量按包含依赖模块的 audit 统计。

以上是可复现的静态推断，不是 reached-fault 或游戏兼容验收；真实 Activity 路径和下一
运行首错由编排方在沙盒外复验。Windows 未构建/实跑。
