## 盘点与检查器

完整 HLE provider 由 `src/runtime/boundary/modules/module_catalog.cpp` 的
BuildCatalog 装配：GLES1、GLES2（含 GLES3 delta）、EGL、OpenSLES、android、
jnigraphics、log 共七库。`src/runtime/bionic/bionic_profile.cpp` 的 API19 guest
清单中 libc、libm、libdl、libstdc++、libz、libcrypto、libssl、libgabi++、
libicui18n、libicuuc、libstlport 走 bundled guest 实现，libogplay_jni 为项目编译的
ARM guest 代码；均非完整 HLE provider。libc/libdl 在 native_exports 中的条目仅为
intercept，排除其完整 SO 集合。libOpenMAXAL 不在这两份生产清单中，不算已提供。

`tools/conformance/boundary_exports.py` 读取生产命令
`ogplay-cli dexvm dump-surface` 的 `native_exports`，该字段通过
DumpAndroidBoundarySurfaceJson / BuildAndroidBoundarySymbols 取得 sealed
BoundaryCatalog 的 public function/data；private callable 不进入表。
复用已有只读接口，不扫描 C++，不新增运行时导出入口。
已知 provider 消失按整库 MISSING 处理，未知 provider 明确报错。

判据为用户指定的 NDK r25c
`toolchains/llvm/prebuilt/darwin-x86_64/sysroot/usr/lib/arm-linux-androideabi/19/`，
经 `llvm-nm -D --defined-only --format=posix` 取得函数及数据符号。
各桩库仓库相对路径、SHA-256、完整符号集合固定在
`tools/conformance/boundary_exports_baseline.json`。本地 jnigraphics 桩库含
AImageDecoderFrameInfo 等较新符号，报告保留指定判据的原始集合，不据此声明 4.4 行为。

MISSING/EXTRA 按 library/category/symbol 身份比较；新增任何偏差均拒绝，不能用
消除其他偏差抵消。更新也执行此判据，桩库身份变化明确失败。自测覆盖同数量替换
缺口、EXTRA 回归、拒绝更新时文件不变、provider 消失、intercept 排除、函数/数据和
非法输入。已参照 framework_contract 注册 `tools.boundary_exports_self_test`。

## AOSP 依据与支持边界

用户续单明确：libandroid、jnigraphics、liblog 本单只报告，后续补齐；无需以总数
是否超过 300 决定范围。初轮环境阻塞已由编排方解除，保留早先证据而不覆盖。

本地固定 AOSP：

- `.local/aosp/framework/native/opengl/libs/EGL/Loader.cpp:239–241`：没有驱动入口时
  将 GL hook 指向 gl_unimplemented。
- 同目录 `egl.cpp:332–339`：gl_unimplemented 输出错误日志后返回；不设置 GL error。
  ELF 入口存在与 GL_EXTENSIONS 分开。本轮返回确定性 A32 零并额外记账，不读取
  guest 输出指针，不修改 GL 状态，不增加任何 GL_EXTENSIONS 名称。
- 同目录 `egl.cpp:251–259`：validate_display 先校验 display，再校验初始化。
- `eglApi.cpp:1335–1371`：lock/unlock 校验 display/surface；驱动函数缺席返回
  FALSE/EGL_BAD_DISPLAY。本轮不读取无后端用途的 lock 属性指针。
- `eglApi.cpp:1529–1550`：presentation-time 校验后设置 native-window timestamp，
  忽略 setter 返回码并返回 TRUE。本轮保存 surface 的有符号 64 位生产者时间戳，
  不用宿主等待或呈现调度冒充 timestamp setter，也不发布该扩展。
- `eglApi.cpp:1554–1588`：NV 时钟缺驱动函数返回宽零并设置 EGL_BAD_DISPLAY。
  ANGLE 无 NV 时钟支持，本轮不以宿主时间替代，r0/r1 均清零；r2 保留。

以上是现有边界对 API19 ABI 的补充：MODULE 已明确导出名单不等于扩展能力；
未新增系统服务、桌面 GL 转译或第二套状态机，无需新 ADR。

GLES1/2 的缺失入口加入既有 extension IDL，稳定 thunk_id 保留，使用原 generator
生成并核对固定 ANGLE header。核心、原扩展 handler 不重编号。

| 新增 GLES 入口类别 | GLES1 | GLES2 |
| --- | ---: | ---: |
| ABI 相同 GLES1 core 别名 | 47 | 0 |
| ANGLE blend OES | 3 | 0 |
| ANGLE draw-texture | 8 | 0 |
| ABI 相同 ES3 core 条件别名 | 5 | 12 |
| gl_unimplemented | 39 | 43 |
| 合计 | 102 | 55 |

GLES 可执行/转发入口合计 75（其中 17 个 ES3 条件别名），固定 GL 回退 82。
ES3 条件别名只在 current client version=3 执行原 GLES3 handler，其余 Context 同样
走 gl_unimplemented。EGL 五入口按各自 AOSP 契约实现，其中 lock/unlock/NV 四入口的
无驱动路径记账并明确 EGL 错误；presentation-time 为有状态 setter。

Draw-texture 复用固定 shader 与 ANGLE 绘制，依据
[Khronos OES_draw_texture](https://registry.khronos.org/OpenGL/extensions/OES/OES_draw_texture.txt)。
支持 float/int/short/fixed 及向量 ABI、窗口矩形和深度映射、共享纹理 crop/尺寸、
负 crop 翻转；矩阵、顶点数组、lighting、clip、cull 不参与，保留当前颜色、纹理环境、
零距离 fog 和片元操作。内部 VAO/buffer/program/属性恢复沿用固定绘制路径。
仍限现有两个 2D texture stage，超限明确失败；未发布 GL_OES_draw_texture。
尺寸只在成功的原有 GLES1/2 level-zero 上传/复制后记录，crop 随共享对象保存并在删除
时清理。未实现完整厂商扩展或更广的固定管线能力。

## 续单：thunk 与固定数据区重叠回归

编排方外验候选主题结果为 **182/192，10 例失败**，日志
`gate/candidate-topics-outside.log`。失败共同点为首次发布 GLES 查询字符串时
`AddressSpace::Map` 抛出 `guest memory range overlaps an existing mapping`。
诊断成立：旧 arena 从 `0x70000000` 按四字节槽、4 KiB 页舍入映射，上限却是
`0x71000000`；第 1025 槽起覆盖 GLES2 字符串页 `0x70001000`。
这不是 GPU 实现错误，基点完整 catalog 尚未越过该页。

全量检索 `src/`、`include/` 的结果保存在 `layout-address-search.txt`。
原 `[0x70000000,0x71000000)` 中固定边界数据区只有前三项；邻接区一并列出，
避免把 JNI/OpenSLES 等误认为都处于原 arena 内。大小是 guest 页映射大小或池上限，
保留区大小与实际映射不同处明确区分：

| 区域 / 生产位置 | 原地址 | 实际大小 / 上限 | 修复后地址 / 保留大小 |
| --- | --- | --- | --- |
| GLES2 普通查询 / services/graphics_dispatch.cpp | 0x70001000 | 两个 guest 页，8192 字节 | 0x70020000 / 64 KiB |
| GLES1 查询 / modules/gles1/gles1_fixed.cpp | 0x70010000 | 64 KiB | 不变 / 64 KiB |
| liblog event tags / modules/log/log_module.cpp | 0x70F00000 | 按页分配，总池 1 MiB，止于 0x71000000 | 不变 / 1 MiB |
| OpenSLES static ABI / modules/opensles/opensles_abi.h | 0x71800000 | 0x3000 字节 | 不变 / 0x3000 |
| OpenSLES object arena / 同上 | 0x71900000 | 1 MiB | 不变 / 1 MiB |
| EGL strings / modules/egl/egl_module.cpp | 0x71C00000 | 一个 guest 页，4096 字节 | 不变 / 64 KiB |
| GLES3 indexed strings / modules/gles3/gles3_module.h | 0x71E00000 | 64 KiB | 不变 / 64 KiB |
| buffer mapping / services/buffer_mapping.h | 0x72000000 | 32 MiB | 不变 / 32 MiB |

OpenSLES static ABI 内 IID 值位于 `+0x1000`；六张 vtable 位于 `+0x2000`、
`+0x2100`、`+0x2200`、`+0x2300`、`+0x2400`、`+0x2500`，都在同一
0x3000 映射内。IID 常量中的 `0x70bc7b00` 是 UUID 数据，不是 guest 映射。
`kElfProgramArmExidx=0x70000001` 是 ELF 类型，也不是地址。
全仓还发现独立 headless_bionic_runner 的 TLS `0x70000000`、thread-info
`0x70001000`、preinit `0x70002000`（各一 guest 页）；该 runner 自建
AddressSpace、不装配 AndroidBoundary/thunk arena，与此进程布局互不共存。
JNI thunk 起于 `0x71000000`，属于独立保留区，本次未修改。

最小布局修复：保持 thunk 起点及既有槽地址，把其硬上限收紧为 `0x70010000`
（64 KiB / 16384 槽），仅移动发生冲突的 GLES2 查询区。所有边界固定数据区
统一从 `boundary_symbol.h` 的强类型 GuestRange 常量派生，编译期验证两两互斥。
GLES2/EGL 按页映射还检查不超过各自保留区。catalog 在分配槽前拒绝超限，arena
在乘法前拒绝零槽、超限和 size_t 极值，再校验页舍入上限；不会依赖当前槽数侥幸不碰撞。
父 MODULE 只记录布局不变量；不改变导出集合、扩展声明或调用语义。

不能用它代替实际 arena 槽数），读取 arena 实际映射元数据，
