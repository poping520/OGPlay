XML 尾部的 SAME 是审计纠正：nextNode 仅在 next≥end 时返回 END_DOCUMENT；
不足节点头的尾部碎片仍进入 validateNode/validate_chunk 并被拒绝。保留该拒绝。
其他 XML 放宽保留命名空间、属性 raw/typed 值、资源 id 和有符号事件深度；
UTF16 code units 通过 WTF-8 保存，UTF8 转换按旧实现的长度及掩码规则，字符串按访问解码。
不以 4.4 未读取某项为由删除 OGPlay 的通用 XML/布局事实。

ARSC 允许零包，仍检查实际包数与声明一致以及全局池可用；重复 bag 项按声明顺序保留，
不在 loader 中丢弃或强行去重，也不把原始 bag 改成单一 map。
DEX 扩展 header、link/data 字节范围、map reserved/零长度节按原版放宽，
同时保持节间边界；允许文件尾部存在额外字节后，所有变长 data 读取限制在声明 data 区域，
不得借尾部字节补全坏结构。dex_class_data.cpp 的变化只属该边界修正，四项待办检查不变。
Unicode descriptor 保留合法 UTF8 类身份，shorty 仍限合法字符；非最短 ULEB 仍检查截断、
第五字节及溢出。空 try 在格式读取成功后由现有方法验证阶段抛 VerifyError，
两解释后端均覆盖，不能仅删除 loader 拒绝后让执行成功。

## 后续依赖边界

编排明确授权系统注解组延期，并允许其他必须跨模块改造的机制组同样处理。
以下均保留 STRICTER，没有将“未完成”伪记为 SAFETY 或 SAME。

- **DEX 系统注解及 Signature（8）**：后续：需 loader→linker→反射事实契约扩展（延迟按查询失败）。
  `src/loader/dex.cpp` 提前把 Signature 压为 optional 字符串，系统元数据只保存有效索引；
  `include/ogplay/loader/dex.h:110/119/175` 与
  `src/runtime/dexvm/class_linker.cpp:1287` 的 ReflectionSystemMetadata 接口无法保留坏值形态，
  enclosing/member 多种反射查询还共用解析结果。Annotation.cpp:1390/1467/1554 按独立查询读取，
  必须隔离查询失败，避免一个坏注解污染无关查询。
  Annotation.cpp:1194 返回 Signature Object[]，
  `libcore/libdvm/src/main/java/org/apache/harmony/kernel/vm/StringUtils.java:38`
  在查询时 cast/拼接：单个 null 返回 null，多项 null 触发 NPE，错误对象触发 ClassCastException。
  忽略片段或置空会伪造泛型结果。MemberClasses/Throws 还须按 Annotation.cpp:565/1566/1805
  核对转换；`vm/oo/Array.cpp:494` 原版 copy 非 null 安全，不能声称普遍接受 null Class[]。
  本轮不修改反射接口。
- **ARSC 类型及 offset 表（2）**：需要区分缺失 type name 与合法空字符串；
  ArscEntry.type_name 必为 string，getResourceTypeName/getResourceName 无法表达延迟名称失败。
  offset 表可局部放宽，但按机制组保留，待事实和名称查询契约一并验收。
- **ARSC 条目、名字、值与 bag 边界（7）**：API19 在选定配置后读取，损坏候选不能直接当缺失丢弃。
  `include/ogplay/loader/arsc.h` 暴露拥有型 entries，FindById/FindByName 为 noexcept；
  `src/loader/apk_manifest.cpp` 与 `src/runtime/integration/dexvm_android/support_ui.cpp`
  还有直接配置遍历。需 loader→资源配置选择→查询事实契约扩展，保存坏候选并延迟到选中时失败。
- **DEX class_data delta/列表（4）**：DexSwapVerify 允许部分 delta=0/列表情形，
  但 `src/runtime/dexvm/class_linker.cpp` RegisterDex 按 name+descriptor 合并 own_fields/own_methods。
  直接放开会丢重复成员身份、字段布局与反射事实；instance static bit 还涉及列表分类与原始 flags 消费。
  需 loader→linker 成员身份/布局/反射契约扩展，不能用去重后的成功替代原版行为。

上一批 apk/apk_native/apk_manifest 的实现及结论未改；Profile、纹理策略 ADR-0128、
