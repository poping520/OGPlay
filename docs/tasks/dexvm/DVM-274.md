  保留 e_version、机器/端序、实际字节读取与映射边界。保留完整 dynsym，包括非规范零项。
- 共享 scalar 动态标签取最后声明，PT_DYNAMIC 取首段；NEEDED、SONAME 等事实不删减。
- PLT 在 REL 前；尺寸截断完整条目，缺失尺寸按零，RELA 仅在出现 DT_RELA 时拒绝；
  表可重叠、重复目标顺序累积，实际写入保持事务性。NONE 不读取目标/索引，sym=0 使用 S=0。
- 生命周期数组指针/尺寸独立缺省、尺寸整除，EXIDX 首段及 p_memsz/8；实际读取继续受界。

  缺失强引用仍失败；既有弱引用行为不在本轮新增拒绝。
  保留显式全符号诊断模式；预检保留未引用缺口及独立计数，只以引用强缺口判失败。

## DeadSpace 跨层结论

只读脚本 `deadspace.py` 检查原 APK：两个符号分别为 dynsym 473/646，均
STB_GLOBAL、STT_NOTYPE、SHN_UNDEF，但 **REL/JMPREL 引用均为零**。
4.4 `linker.cpp:864` 先跳过 NONE，只在 `:867` 的 sym 非零时查找；
所以两者在 4.4 装载时被保留为未引用事实，不导致失败，也没有被解析成假地址。
若有真实引用，GLOBAL 查找失败会在 `:875` 失败；只有特定弱重定位容忍缺失。

4.4 `soinfo_do_lookup:483`：非 SYMBOLIC 时先 somain、再自身；SYMBOLIC 时先自身、
再 somain；随后 LD_PRELOAD、该对象直接 NEEDED（非任意已加载库的传递全局搜索）。
somain 在普通应用进程是 app_process。现有 API19 oracle 库无这两个导出；本地缺
app_process/完整 ROM native 二进制，不能证明厂商 ROM 的全局导出集合。
本次结论不依赖这些导出或不确定性，因为根本没有触发符号查找；不引入符号名特判。
