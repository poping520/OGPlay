## 复用与差距

原 linker 的 `RegisterDexUnit` 已使用 DEX 类/层级/字段 facts，精确匹配的 intrinsic handler
保留其 MethodKind 与 implementation，同时挂上 DEX code 和 flags；没有同签名 handler 的方法
解释执行。此机制可直接承载一类中的 ROM 与 C++ 方法，但原先缺少来源审批和逐成员禁用；
旧 intrinsic 额外字段/方法、类级 clinit 回调也可能残留，实例字段顺序原先受注册顺序影响。

显式组合在注册后、Link 前核对 ROM 成员总数与完整签名/flags，拒绝额外 intrinsic 成员，
以 DEX 字段顺序确定布局；ROM 方法清除旧 handler，overlay 要求真实 handler 与逐签名审查，
失败方法清除 handler/code 并复用 ADR-0147 的记账与 UnsatisfiedLinkError 通道。
清除类级旧 clinit 回调，真实 ROM clinit 唯一执行；未选 native 只按精确失败签名容许声明装载，
不开放全类 native 准入或 guest JNI 动态绑定。旧 BootDex 默认 overlay 规则不变。

## 制品与工具契约

组合入口为 `python3 tools/bootdex/compose_bootdex.py build|check`；复用原 builder，
保留 `build_bootdex.py` 原字节（其完整 hash 是现有 JNI 制品的来源证明），不重建 JNI 或改生产 manifest。
现有 `tools.bootdex_builder_self_test` CTest 转用组合入口，执行成员机制及原 builder 全部自测。
原 builder 命令仍只用于旧配方；显式成员组合必须使用新入口。

- `tools/bootdex/member-sources.json` 是显式来源白名单，本批为空。完整 ROM 类仍需在原配方中，
  不扩充默认 selector，不启用生产 View 类，closure 增量 0。
- `member_sources.py` 校验固定 ROM JAR 与 runtime surface 输入 hash、完整 smali hash、逐方法
  flags/原始方法体 hash、逐字段类型/flags/初始化策略、形状与 clinit owner、来源互斥。
  独立校验可用 `python3 tools/bootdex/member_sources.py --check --manifest <表> --smali-root <目录>`；
  `--report <文件>` 输出规范化封存表；漏依赖、冲突、native/overlay 越权均有实际 CLI 退出 2 负例。
  `rom_input` 必须为该类原配方的固定 ROM 输入；`surface` 是受审 dump-surface 的固定文件。
- 方法来源仅 `rom` / `overlay` / `failure`。全部 ROM 声明必须显式列出；overlay 的 review
  必须列明 reason、inputs、outputs、state_owner、failure_boundary，并存在已实现 intrinsic handler。
  native overlay 另需 `platform_seam: true`；未批准 native/普通 overlay 均拒绝。
- 不改写、删减 DEX 方法体或声明；组合表作为 `META-INF/ogplay/member-sources.json` 封存进 JAR，
  metadata 记录 entry hash，表内保留输入与方法体 hash。发行 payload 校验要求封存表与受审配置逐字节一致。
  两次 DEX/manifest 生成逐字节比较。
  空表不增加 entry 或 metadata，保持既有制品字节。
- 所有被选 ROM 方法的精确成员引用都必须已实现；复用 ADR-0156 Analyzer 的父成员、不可覆写
  方法、初始化与虚分派分析。默认 selector 的全部 own 方法审计不变。
- Bridge、dump-surface 与标准 BootDex 测试装载器读取可选封存 entry，传入 RegisterBootDex。
  运行时核对精确成员身份/来源，不重新证明输入 hash；hash 和闭包属于 build/check 的信任边界。
  用户运行配置中没有组合开关。
- 仅支持 ROM clinit 或 ROM 无 clinit；不实现初始化 adapter 生成、完整系统服务或全量 ROM 收录。

## 验证

基点先复制 release CLI/tests 至 `baseline-bin/`，然后按 playbook 运行 BootDex/骨架/链接主题。
CLI 是依赖 core dylib 的启动壳；保存壳不等于冻结整个 CLI 基点，未据此宣称完整 CLI 差分。
机器判定以先行生成的 `baseline-tests.xml` 和最终相同过滤器报告为准。

受控测试 ROM 位于 `tests/dexvm/fixtures/member_composition.dexasm`，不进入生产配方。
测试制品把该类与已有 BootDex 异常闭包装进独立 JAR，再经真实 archive entry 装载组合表：
ROM clinit 把 encoded 5 改为 17，ROM 方法返回 17，获批 C++ handler 返回 29，ROM 调用两者得到 46；
未选普通方法及 native 均保留声明、记账并抛 UnsatisfiedLinkError；旧方法和旧 clinit 不执行。
两个解释后端均检查同一行为与真实 MethodKind。

最终结果和命令记录以本地 `validation.json`、日志及 hash 文件为准。
