## A / B 边界与初始化闭包

A 将固定 ROM View 纳入 BootDex，原始声明及方法体保持原字节；封存来源表选择
72 个原有 C++ handler 为 overlay、原版 clinit 为 rom、其余 571 个方法为 failure。
ROM 是唯一 class_def、完整字段布局及 clinit owner；三个非 ROM 实例字段已全部迁出。
View implemented 方法从 72 到 73，差集仅 `<clinit>()V`，原有 implemented 集合没有减少。

先前阶段按 A 的“不新增 ROM 方法体”停止，证据保留于 `initialization-blocker.json`。
编排方随后允许原版 clinit 及其常规准入依赖，本次依此继续，没有空 clinit、跳过初始化
或默认零值替代。View$4–View$13 与 FloatProperty 通过原 selector 准入并收录；
随后标准 closure 检查发现的另外 27 个可准入类也按原规则收录，不添加新 native 或系统服务，
不改 selector、不豁免 ADR-0148/0155/0156；详情在 admission/closure 报告及配方。
部分可达边来自 JAR 中保留的未选方法体，仍按现有较保守的 closure 机制收录。

B 未实施：mResources、padding、minimum 字段及其 getter/setter 尚未交由 ROM；
setPadding 仍写现有 UiTree，getResources 与 setMinimumWidth/Height 仍明确未实现。
本单不承诺 Java 遍历、Java 几何投影或游戏兼容验收。

## 逐字段可用性

manifest 中每个字段保留完整 ROM 类型、flags、原初始化策略；来源新增 failure 可用性。
构建期及 runtime linker 使用同一来源：rom 为 Java 维护状态，failure 保留准确布局但
设 `LinkedField::is_unimplemented`，guest 字节码及既有 JNI/反射通道在访问时按
ADR-0147 记账、抛 UnsatisfiedLinkError。被选 ROM 方法读写 failure 字段为依赖错误。
受审 C++ adapter 的 bound token 允许访问自身内部槽，但不授予 guest 字段可用性。

所有 ROM static 字段由 encoded value、VM 初始化及真实 clinit 维护；静态兼容 flags
再由构造 adapter 按当前进程 targetSdk 更新。完整静态字段账以 manifest 为准，不另抄常量值。

## 构造器 adapter 与 overlay review 汇总

受审构造范围为现有 `(Context)V`；额外 AttributeSet/defStyle 构造仍 failure。
widgets/inflation 复用 AssignViewContext，初始化入口不扩展完整 ROM 系统服务。

| Java 字段 | 初始化/写入来源 | ROM / AOSP 依据 |
| --- | --- | --- |
| mContext | 构造参数或 inflation 的实际 owner Context；允许既有 null 语义 | View.java:3436–3437 |
| sCompatibilityDone | clinit false；首个非 null owner 初始化后 true | View.java:698、3453、3463 |
| sUseBrokenMakeMeasureSpec | clinit false；当前进程 targetSdk <= 17 | View.java:703、3457 |
| sIgnoreMeasureCache | clinit false；当前进程 targetSdk < 19 | View.java:708、3461 |

SDK 来源是注入且封存的当前进程事实，与有界 Context 的 ApplicationInfo.targetSdkVersion
共用 provider；不扩大任意外部包/系统 Context 或自定义 targetSdk provider 的支持。
其余实例字段不可用，不执行对应 ROM 构造闭包；mViewFlags 和 mSystemUiVisibility 的既有
adapter 槽只维持原 scroll-style / system-UI 方法协议，guest 不能读取并误认整组 flags 已迁移。

每个 overlay 在 member-sources.json 按精确签名写 reason、inputs、outputs、state_owner、
failure_boundary；固定原 ROM flags、body hash，要求真实已实现 handler。汇总如下：

| 方法族 | 状态 owner / 边界 |
| --- | --- |
| 构造/getContext | Java mContext、静态 SDK flags；UiTree 初始化仍走原有入口 |
| geometry/id/hierarchy/focus/visibility/enabled/clickable/padding | UiTree；getter 经原 traversal 门面，未接 ROM measure/layout |
| LayoutParams/background/observer/listeners | integration 原引用表及 UiTree 投影；原异常/回调/dirty 协议 |
| scroll-bar style/system-UI visibility | 受审绑定槽；guest 字段 failure，不扩大 flags 语义 |
| post/postDelayed/postInvalidate | 既有 scheduler、统一 Clock、dirty 服务 |
| 输入/窗口/默认 callback | 既有有界分发及窗口事实；原默认回调实现保持 |

mOgplayWindowOwner、顶层 mOnFocusChangeListener、mOgplaySystemUiVisibilityListener
移到 integration 的 owner-attached ViewAdapterReferences；从 View trace、随 View sweep，
不以 UiNode/attach 作为引用生命周期，脱离树的活 View 仍保留引用。它们未迁入 Java ListenerInfo，
因此 ListenerInfo 字段仍 failure。ui 不读 Java 字段、不保存 guest 引用；本单未改变 UI 层契约。

完整受审依赖 surface 来自真实 `dump-surface --bootdex`，以确定性 gzip 封存并固定文件 hash；
不是修改状态的准入白名单。方法/字段归属仍由组合表及真实运行期 metadata 决定。

BootDex JAR，跑相同 CPU 过滤器：View/widget/UI 104/109、无 GPU EGL/Surface 16/22、

非 ROM 字段消失、Java mContext 与 getter 一致、宿主 mLeft 的读写均失败、原 handler 保留，
以及三个侧表引用的 GC trace/sweep。组合受控样例另覆盖静态 failure 字段读写失败。
工具自测包含非法字段来源、被选 ROM 读写 failure 字段的异常与实际 CLI 非零退出负例；
受控样例 JAR 同时保留其内嵌生产 DEX 的封存组合表，避免丢失 View 失败/native 策略。
已有 tracked member_composition.surface.json 在基点为空；补成样例真实 host surface，
使原 fixture/self-test 可从源码重新生成，未放宽验证器。

framework_contract 初次检查无新增偏差，减少 View 的 4 个 A2 与 5 个 B；仅据该精确差集更新
baseline，随后重新 check。A1 保持0，没有移除类或重分类隐藏问题。
相关 C++ 仅格式化改动行，dry-run 加 -Werror，格式化后重建重测；新文件只有 DEX 数据夹具。
MODULE 仅更新 dexvm/integration 的真实契约变化，ui 未变；能力账本更新现有组合项。
CURRENT 增量0字节。未运行全量 C++ 测试、APK 或 git commit。
