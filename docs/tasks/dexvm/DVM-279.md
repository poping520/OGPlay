# DVM-279 · View ROM measure 链（VD-04）

状态：阶段1机制与阶段2测试根/叶实现完成；GPU/九场景和 Windows 交外验。
前置：[DVM-276](DVM-276.md)、[DVM-277](DVM-277.md)、[DVM-278](DVM-278.md)。
决定：[ADR-0159](../../adr/dexvm.md#adr-0159)、[ADR-0158](../../adr/dexvm.md#adr-0158)、
[ADR-0157](../../adr/dexvm.md#adr-0157)。基点：2fa34727。
证据：`.local/analysis/vd-04/`；未提交，未启动 APK。

## 背景与阶段1：开放世界普通方法

首次候选被 clinit 级唯一目标规则拒绝：measure→onMeasure 有63个可能实现，RTL 有两个，
suggested minimum 又调用 Drawable 非唯一 getter。初次停止证据保留于
`validation-initial-stop.json`、`dependency-audit.json`。编排方随后接受 ADR-0159，解除该机制阻塞。

组合工具仅对普通方法的非唯一 virtual/interface 放宽，仍按全部可链接平台类枚举目标，
封存 `dispatch_ledger`：调用者完整签名、方法内 invoke 序号、opcode、声明签名→全部目标
签名与 implemented/failure 来源。应用覆写不在构建期集合中；failure 不获得实现信用。
调用序号基于固定 ROM body，body hash 同时封存。输入已有 ledger 时重算并拒绝失配。
运行时仍沿原失败通道，未改 selector、cha_precise 或 ADR-0156 父成员审计。

直接/static/super、同方法 new-instance 精确接收者、failure 字段和 DYNAMIC_TARGETS 仍拒绝；
clinit 使用独立严格 Analyzer，检查传递闭包，不能借普通方法摘要放宽初始化。
自测包含 virtual/interface 全目标及来源、上述全部拒绝、clinit 直接/间接非唯一调用、
篡改 ledger 拒绝、同输入及 surface 顺序变化仍确定。真实 View 配对表关闭放宽后的负对照
仍以原 Drawable.getMinimumHeight 的 `clinit-virtual-nonunique` 拒绝，见 `closed-world-negative.log`。

## 阶段2：隔离的 measure 配对

`DexVmAndroidContext` 构造时固定 const owner 与 UiTree owner，VM 创建后不可切换。
无用户配置；Legacy 是唯一生产默认，原 LayoutUiTree 行为不变。
测试夹具在注册类和创建 VM 前校验 owner/payload 配对；实验初始化还拒绝 Legacy 字段策略。
`view-measure-sources.json` 是固定实验增量配方，转换为完整成员表后沿同一组合校验封存；
未知/冲突成员拒绝。`compose_bootdex.py build|check --view-measure-test-output <jar>`
只写指定测试制品，不改生产配方。CMake 生成测试 counterpart，DEX 与生产完全相同，
仅封存成员来源不同；两次完整组装比较 DEX/表字节，check 再核对 JAR/metadata。
生产 JAR 保持原字节，发行 manifest 仅更新 composer hash。

支持非 null Context 的 plain View 及 guest DEX 叶子覆写，测试默认 LTR、无背景/滚动条；
不承诺所有 ledger 分支可运行。实验表只保留所需方法，其余 View 成员明确 failure，
不会让 Legacy 的背景/hierarchy/geometry adapter 在实验模式写入另一份语义状态。
ViewGroup/控件构造明确拒绝，attributes/style 构造未新增支持。

### 发布与支持路径

OwnerTick/ResolveOnly 在 owner 线程调用根 ROM measure，再由
`CommitAndroidMeasuredRootProjection` 经绑定 token 读取 measured/padding，检查当前 root、
generation/content revision，交 VD-02 target/epoch API。合成窗口根使用 viewport；guest frame
留空，不伪造 layout/setFrame。外部 owner 树从不进入 LayoutUiTree；其他 reason/phase 明确拒绝。
异常不回滚已执行 Java 动作，不更新已发布快照。旧 epoch/错误 root 不得发布。

测试根/叶覆盖 EXACTLY/AT_MOST/UNSPECIFIED、TOO_SMALL 及宽高 state 合并、SDK17/18/19
缓存差异（含缓存 state 保留）、相同 spec 跳过、SDK broken makeSpec、漏 setter 抛 ISE。
原版 View.onMeasure 与 guest DEX onMeasure 都在 switch/threaded 执行解释字节码，后者由计数、
MethodKind 和 method-enter trace 共同证明。宿主 measured 故意设为333×444，ROM 结果独立；
投影由 Java 字段生成，空 frame、拒绝 C++ layout、旧批次/异常保留快照均有断言。
每组末检查运行 ledger 未实现命中为0，未把静态 failure 目标当作可运行能力。
实际命中的虚派目标签名、六组原始 trace 与源表统计见 `runtime-dispatch-targets.json`、
`runtime-traces/`、`migration-ledger.json`。

## 验证与外验

基点先保存 ogplay_tests/BootDex JAR；CPU 185/200、15项既有失败。
最终差分、双后端一致性、制品身份、格式化区间及全部命令见 `validation.json` 和各日志。
compose 两种配对 build/check、机制 self-test、framework baseline（A1=0）、closure 零缺口、
traversal、capabilities 及 C/C++ 改动行 clang-format dry-run -Werror 按要求执行；格式化后重建重测。
CURRENT 增量0字节。未运行全量测试、APK、GPU 或九场景；外验精确过滤见
`external-validation.txt`。不包含 VD-05 layout/setFrame、VD-06a hierarchy 或生产默认切换。

最终结果：CPU 基点185/200，最终187/202，新增2例/1138断言通过；原15项失败逐项不变，
新增失败0。JNI switch/threaded均399/399。dalvik 主轮switch85/91、threaded84/91，
098-native-allocations threaded 超时一次，`--only` 首次复跑通过；合并后均85/91、基线回归0。
原始超时与复跑分开保留，没有修改一致性基线。两种配对 framework A1=0、无差异，closure
缺口均0；method_ids=40818、field_ids=24219。新准入与可达增量0，CURRENT增量0字节。
