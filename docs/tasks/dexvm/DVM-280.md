## 修订背景与组合证明

最初的普通方法规则只放宽非唯一虚派。真实 setFrame 被唯一 failure 目标
GLES20DisplayList.setLeftTopRightBottom 拒绝；sizeChange 的 setRight/setBottom 依赖也分别
遇到同类拒绝。初次停止、撤回及原始诊断保留在 `rollback.json`、`dependency-audit.json`。
编排方按用户授权修订 ADR-0159：未知接收者的 virtual/interface 不因目标个数获得实现证明，
均封存全目标 ledger；failure 运行期继续记账失败，不开启硬件能力。

默认 selector、精确 new-instance、direct/static/super、本类 failure 字段、DYNAMIC_TARGETS、
clinit 及其传递闭包的严格规则不变。新增 CFG 字段来源/null 写入分析保留寄存器别名、分支
汇合及保守异常边，按实际 BootDex 配方扫描所有写入者；overlay 写入者不能借原 ROM body
证明只写 null。编码非 null 初值、不可用字段、非空写入均拒绝。
自测包括未知接收者唯一 failure ledger 正例、精确接收者/clinit 反例、null/非 null/
分支/别名/跨类写入及 failure 字段；`singleton-old-rule-negative.log` 保留关闭修订后
真实 setFrame 按原 GLES20DisplayList 错误拒绝的负对照。

### 字段接收者约束逐项账

固定实验表中，以下字段均为 rom、VM 清零后真实 null，且全部 BootDex 写入者为 failure。
全量调用点/写入者见 `field-receiver-audit.json`；未按测试实例的偶然值判定不可达。

| 字段 | failure 写入者 | failure 依赖范围 |
| --- | --- | --- |
| mDisplayList | View.getDisplayList() | setFrame→setLeftTopRightBottom，setRight/setBottom→同名 DisplayList 方法 |
| mBackground | View.setBackgroundDrawable(Drawable) | optical insets、minimum、RTL/padding Drawable 虚派 |
| mParent | View.assignParent(ViewParent) | layout/text 方向父接口及父 invalidate |

getDisplayList/HardwareRenderer 创建及 GLES20DisplayList/native 方法保持 failure。
isHardwareAccelerated 执行 ROM，读取真实 mAttachInfo；不以硬编码 false 掩盖已有 AttachInfo。
mContext 必须真实非 null，不能满足 null-writer 约束；原 hasRtlSupport 由 ROM 改为受审
ApplicationInfo adapter，实际虚派 Context.getApplicationInfo 和 ApplicationInfo.hasRtlSupport，
原异常透传，不返回猜测值。

## 迁移方法/字段与 adapter review

新增19个 ROM 方法，hasRtlSupport 一个方法改为 overlay；实验方法最终
**15 overlay / 63 rom / 566 failure**，字段 **320 rom / 51 failure**。
Legacy 保持 **76 overlay / 6 rom / 562 failure**；完整差集见 `migration-ledger.json`。

```text
layout(IIII)V                 setFrame(IIII)Z
setOpticalFrame(IIII)Z        sizeChange(IIII)V
onSizeChanged(IIII)V          onLayout(ZIIII)V
getLeft/Top/Right/Bottom()I   getWidth/Height()I
setRight(I)V                 setBottom(I)V
invalidate()V                invalidateParentCaches()V
invalidateParentIfNeeded()V  isHardwareAccelerated()Z
isLayoutRequested()Z
```

新增10个 rom 字段：mLeft/mTop/mRight/mBottom、mAttachInfo、mDisplayList、mTransformationInfo、
mOverlay、mListenerInfo、mBackgroundSizeChanged。bounds 由 ROM setFrame/setRight/setBottom 写；
其余引用保留真实构造默认 null，backgroundSizeChanged 由 ROM 更新。既有 mPrivateFlags/2/3
延续 Java owner；未迁移字段继续明确 failure，不统一开放字段。

| Adapter | 输入/输出、owner 与拒绝边界 |
| --- | --- |
| requestLayout | 清真实 LongSparseLongArray；owner token/宿主线程校验。普通/首轮写 FORCE_LAYOUT=0x1000、INVALIDATED=0x80000000；第二轮缓存清除后提前返回、不写 FORCE_LAYOUT。仅当前绑定测试根入队；未附着叶只改 Java flags/cache，无伪 AttachInfo/ViewRootImpl/Binder |
| invalidate(boolean)/(IIII) | 本进程 software draw dirty；清 DRAWN=0x20、置 DIRTY=0x200000，完整失效置 INVALIDATED、清 DRAWING_CACHE_VALID=0x8000。保守整节点失效，不写几何；已有 DisplayList/变换/overlay/animation/系统 attach/accessibility delegate 或 DRAW_ANIMATION 明确记账并抛 UOE |
| updateMatrix | 只兑现原版 mTransformationInfo==null 快路径；已有对象记账抛 UOE，不伪造 identity matrix |
| accessibility 通知 | 无系统 attach/delegate 的测试根只导向当前 dirty 服务；有对象明确拒绝，不构造 AccessibilityManager |
| hasRtlSupport | 读实际 Java Context/ApplicationInfo，虚派并透传异常；不另存 SDK/RTL 权威 |

所有 adapter 逐签名输入、输出、state_owner、failure_boundary 封存在同一个
`view-measure-sources.json`；沿 VD-04 配对机制，未另建运行模式或用户开关。

## 调度、时序与发布契约

- View.java:14802–14843 的 layout 按 PFLAG3_MEASURE_NEEDED_BEFORE_LAYOUT 补 onMeasure；
  :14855–14929 的 setFrame 写 Java bounds，:14931 sizeChange 同步 onSizeChanged，再 onLayout。
  相同 bounds 不重发尺寸回调，oldw/oldh 从原 bounds 得出。getter 不调用整棵遍历。
- OwnerTick/ResolveOnly 在 owner guest token、初始化绑定宿主线程与 VM 锁下，固定 root binding、
  window generation、content revision、managed metrics，RootScope 保活，执行
  measure(EXACTLY managed W,H)→layout(0,0,measuredW,measuredH)。本批仅单 plain 测试根。
- View.java:16412 requestLayout 和 ViewRootImpl.java:1909–2041、:2045–2110 为依据：首轮
  收集请求，结束时仅当前非 GONE 且剩余 FORCE_LAYOUT 的请求有效；按原清位/重新请求顺序
  运行本帧第二次 measure/layout。已由 ROM epilogue 消费的请求不重跑。第二轮请求不置
  FORCE_LAYOUT，保留强根队列至下一 owner tick；GONE 请求不安排下一帧。
- 连续 deferred tick 超过8次抛 ISE，结构化日志和异常记录 requester/epoch、保留请求队列。
  不以静默清 flag 假装收敛；换 root/generation 重置该根 watchdog。
- Java getter 在回调中读已修改字段，integration 重入不再次执行遍历。异常保留原 throwable
  和已经发生的 Java 修改，不回滚，不提交半成品；换根、destroy/reset、binding/content/metrics
  改变取消旧发布。其他 reason/phase 尚未接生产系统，明确拒绝。
- integration 经只读 bound token 读 measured、local frame、visibility、padding，一次提交 VD-02
  epoch；C++ 不回填 measured/bounds，ExternalProjection 从不进 LayoutUiTree。
  render/hit-test 同时读同一完整快照；无额外 DispatchAndroidViewSizes 尺寸回调。

## 验收与剩余边界

双后端定向回归包含 ROM 方法 MethodKind/trace、回调顺序与旧尺寸、同 bounds、缓存补测量、
有效/已消费/GONE 请求、第二轮/下一 tick、watchdog、异常身份、换根/窗口与 metrics 失效、
非 owner token/宿主线程、几何不回填及 render/hit-test 同 epoch。
支持路径未实现命中为0；硬件状态/watchdog 为显式负对照，单独检查其 ledger，不混作支持路径。
实际运行虚派目标见 `runtime-dispatch-targets.json`，原始 method-enter trace 同目录保留。

实际定向复测3例/1640断言通过（含两后端循环），CPU基点187/202，最终188/203；15项既有
失败逐项不变，新增失败0。JNI switch/threaded均399/399；dalvik主轮switch85/91、
threaded84/91，074-gc-thrash threaded超时，`--only`第1次仍超时、第2次通过，合并均85/91，
零回归。原超时/复跑结果分开保留，不更新conformance baseline，不隐藏原始失败。

两种payload compose build/check（双组装逐字节确定性）通过；framework --check-baseline均
A1=0，无新增/移除/重分类/缺失类，closure缺口均0，method_ids=40818、field_ids=24219。
机制自测和旧规则setFrame负对照通过，改动行clang-format dry-run -Werror后重建重测通过；
traversal为1个Legacy布局调用、0绕过，capabilities check通过。生产manifest仅composer hash更新。
最终机器汇总为 `validation.json`；CPU差分见 `test-comparison.json`，具体命令见各日志/脚本。
新准入类和 closure 可达增量均0；生产 JAR 字节保持基点。CURRENT 增量0字节。
GPU/九场景和 Windows 交外验，精确过滤见 `external-validation.txt`；本单不宣称游戏兼容验收。
