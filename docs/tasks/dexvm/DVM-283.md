  View 的 measured/bounds/cache、Group 的 children/parent/params 继续按前序契约只在 Java。

## 判据与 AOSP 期望推导

定向主题 `framelayout_traversal_tests.cpp` 的同一双后端夹具使用真实 Window 根和
真实 ICU/JNI 进程，只创建进程而不执行生命周期/游戏。原 FrameLayout 构造触发
Rect.<clinit>→Pattern.compile；保留真实 ICU51/native 链，不跳过 clinit、不用成功桩。

- 根 EXACTLY 200×140；padding=(10,8,14,12)，子40×20、margin=(3,5,7,9)：
  TOP|START/LTR 为 `(13,13,53,33)`。RTL 相对 start=3/end=7 得 leftMargin=7/rightMargin=3，
  START→RIGHT，left=200−14−40−3=143；END→LEFT 得 left=10+7=17，互为负对照。
- CENTER：left=10+(176−40)/2+3−7=74，top=8+(120−20)/2+5−9=54；
  RIGHT|BOTTOM 得 `(139,99,179,119)`。直接 Gravity.apply 的 START 在 RTL/LTR 分别 left=146/10。
- foreground padding helper 对 Java 夹具输入 foregroundLeft=16：inPadding 时 max(10,16)=16，
  关闭时10+16=26；原 setter 在真实 null foreground 路径复位 padding。此输入只隔离算法，
  不宣称已有 foreground Drawable 服务。构造零 padding/default FILL/两个 Rect/ArrayList 均检查。
- INVISIBLE 保留测量、bounds，但不渲染/命中；GONE 默认不测量/布局，打开 measureAllChildren
  并显式 requestLayout 后重新测量、仍不命中。API19 setter 本身只存 boolean，不替它补 request。
- 默认参数为真实 FrameLayout.LayoutParams(-1,-1)、gravity=-1；子 bounds=(10,8,186,128)。
  通用9×6参数经 ROM check/copy 转为正确类型，bounds=(10,8,19,14)，原参数对象不被复用。
  同类复制另验证 gravity 与 margin 保留及对象身份隔离。
- 同窗口嵌套 WRAP_CONTENT FrameLayout，padding=(2,3,4,5)、叶 desired=120×90：
  AT_MOST 下容器126×98、子局部 `(2,3,122,93)`。一名 MATCH_PARENT 只测一次；
  两名使 mMatchParentChildren.size()>1，第二轮 EXACTLY 120×90，新增叶实测两次；
  原叶缓存首轮可跳过、第二轮必须执行。负对照直接使用一名子节点，未改 AOSP 的 count>1 条件。
- 缩小嵌套容器为70×50，wrap 叶可用64×42，小于120×90：宽 TOO_SMALL=0x01000000、
  高合并 state=0x00000100，叶及容器均0x01000100；较大空间同夹具 state=0 为负对照。
- 同一快照在子左边界内像素 alpha=255 且 hit 相同节点，边界外 alpha=0 且不命中；
  INVISIBLE/GONE 为渲染/输入负对照。Window addContentView/替换均保留真实根，首个内容与根身份不同。
  六个未支持容器构造失败；raw instance 的 own measure/layout 也记账失败；foreground setter
  与 AttributeSet 构造各有独立失败断言。
