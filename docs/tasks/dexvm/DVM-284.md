## AOSP 期望与负对照

期望依据固定 `android-4.4.4_r2.0.1` LinearLayout.java 的 Context 构造、measureVertical/
measureHorizontal、forceUniformWidth/Height、layoutVertical/Horizontal、getBaseline 及 LayoutParams。
未按旧 host 近似算法改写 ROM。两个解释后端运行同一夹具、同一输入及全部断言。

- Window/root 为 EXACTLY 200×140；垂直外层首子高60、尾子0dp+weight1：delta=80，
  尾子 `(0,60,200,140)`；weightSum=2 后高40，为 `(0,60,200,100)`，前值为负对照。
- 水平层0dp权重1:3，宽200：50/150；baseline 分别5/15，高20/30，TOP 对齐后
  a=`(0,10,50,30)`、b=`(50,0,200,30)`，绝对 baseline 均15。关闭 baselineAligned 后
  a.top=0。weightSum=8 按逐项截断计算25、75，余100不分配；width/state 与原例共同核对。
- 水平 START/RTL：先反转迭代，b=`(100,0,175,30)`、a=`(175,10,200,30)`；
  END/RTL 则 b.left=0、a.left=75；LTR CENTER_HORIZONTAL\|BOTTOM 则 a.left=50/top=40、
  b.left=75/top=30。垂直层宽40尾子在宽200里 START/RTL left=160，END/RTL left=0。
- baseline-index setter 不 requestLayout；刚设 index1 时旧 mBaselineChildTop=0，getBaseline=7，
  显式请求测量后为60+7=67；BOTTOM 使用140−mTotalLength100+7=47，是 API19 的原公式。
  非法 index 抛 IAE；index0 无 baseline 返回-1，非0无 baseline 抛异常；前序子有 weight 时
  原 measureVertical 抛 RuntimeException，均不经过未实现服务。
- wrap 水平层 c=WRAP×MATCH_PARENT、d=20×10+weight1：先测 c120×90，原版
  alternativeMaxHeight 排除 MATCH_PARENT 后用 d 的10，容器140×10，再 forceUniformHeight
  令 c120×10（c实测2次，d1次）。改为垂直、c=MATCH_PARENT×WRAP 后，交叉轴同理取 d.width20，
  容器20×100，forceUniformWidth 令 c20×90；同一 c改 WRAP 作负对照，水平容器高恢复90、垂直容器宽恢复120；不能沿用“总是取最大 desired”的 host 预期。
- divider 隔离输入 width2/height3，show=BEGINNING\|MIDDLE\|END：水平容器宽146，
  c.left=2、d.left=124；垂直高109，c.top=3、d.top=96。关闭 show 恢复140/100，为负对照。
  setting/drawing 调用另有明确失败断言。
- largest-child 水平 c.width80、d.width20：关闭时宽100；开启后 total=2×80=160，
  AT_MOST200 可容纳，weighted d 重测为80，bounds=`(80,0,160,10)`。垂直 largest90 时
  total180 被140截断，delta=-40，d原10被缩为0，容器高140且 height state=0x0100008c；
  关闭时高100/d高10。这里保留原版先按 largest 计总长、再基于原 measured 分配 delta 的行为。
- 缩为70×50并令 c双轴WRAP：leaf state=0x01000100，容器传播宽 TOO_SMALL；宽松原例state0。
  原 MATCH_PARENT EXACT 子测量不保留该轴 TOO_SMALL，不混用二者。
- clean 同 spec measure 不进入子实测；强制 weighted 水平父层时，baseline UNSPECIFIED 探测与
  weight EXACT spec 交替，两个子各新增一次实测。独立 AT_MOST81×61、82×62 后回到81×61
  实际命中 LongSparseLongArray，count不增加、width/height state分别为0x01000051/0x0100003d；
  requestLayout 清缓存后同 spec 增加一次实测。随后 owner tick 恢复完整窗口状态。
- 同一初始快照 a左上内像素alpha255且 hit=a；上边界外alpha0且非a。每轮比较 Java getter 与
  投影局部 frame；不允许外部 owner 进入 C++ 重排。参数默认/通用转换/同类复制及身份隔离有正反断言。
