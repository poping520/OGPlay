## 源码期望与 Legacy 差异

期望根据 `.local/aosp/framework/base/core/java/android/widget/RelativeLayout.java` 的
onMeasure:378、size/position/alignBaseline、onLayout:1045、LayoutParams.resolveRules 与
DependencyGraph.findRoots/getSortedViews 推导。两个后端运行相同输入/断言；测试不采用旧 host
拒绝作为 ROM oracle。

- EXACT 200×140：a40×20、margin=(10,8,3,4) 为 `(10,8,50,28)`；b30×15
  RIGHT_OF/BELOW a、margin=(2,5,0,0) 为 `(55,37,85,52)`；c10×10 ALIGN_LEFT/
  ALIGN_BOTTOM b 为 `(55,42,65,52)`。反序 add 证明不依赖插入顺序；移除 b 两条规则后
  b=`(2,5,32,20)`、c=`(2,10,12,20)` 为链负对照。
- 固定10×10、margin=(7,9,11,13)，同时 parent 四边和 CENTER：双边精确尺寸182×118，
  `(7,9,189,127)`；去 right/bottom 后一边仍优先，`(7,9,17,19)`；去所有边后才居中
  `(95,65,105,75)`。CENTER_IN_PARENT 与双独立 CENTER_HORIZONTAL/VERTICAL 一致；
  去居中恢复 margin 起点。源码 center 公式不使用非对称 margin，不沿用 host 猜测。
- baseline a12/b5：先按 BELOW 得 b.top37，再 baseline pass 改为8+12−5=15；移除
  ALIGN_BASELINE 恢复37。RelativeLayout.getBaseline 返回最靠上/左 baselineView 的原 baseline12。
- END parent 与绝对 LEFT 冲突时相对规则胜出；start3/end7 的 margin 在 LTR 为3/7、RTL为7/3。
  LTR e20×10 为 `(173,0,193,10)`，RTL 为 `(7,0,27,10)`；START 则 RTL left177、LTR left3。
  END_OF a 在 LTR 为 right-of（left56）、RTL 为 left-of（left124）；ALIGN_START 在 LTR
  left13、RTL right194。翻转方向重新从 initialRules 解析。兼容模式隔离输入证明绝对 LEFT
  胜过 START、且 RTL 的 START 仍当 LEFT；不宣称属性构造已支持。
- 不存在的 ALIGN_RIGHT/BOTTOM 锚点：默认 `(0,0,20,10)`；alignWithParent=true 后
  `(180,130,200,140)`。旧 host 缺锚明确拒绝；ROM 合法回退，不要求错误拒绝一致。
- c RIGHT_OF/BELOW b，b GONE 且仍指向 a：同关系穿过 b，使用 a 的边/margin 得
  `(53,32,63,42)`；b INVISIBLE 时仍正常锚定，c=`(85,52,95,62)`；移除 GONE b 的关系后
  链耗尽，c=`(0,0,10,10)`。旧 host 不提供这条 ROM 寻锚语义，Legacy 行为保持。
- 双节点横轴环与纵轴环都由原 getSortedViews 抛 ISE，消息包含
  `Circular dependencies cannot exist in RelativeLayout`；去一条边后成功布局。异常不发布，
  Java 已修改状态不回滚；不将环当动态未实现命中。Graph 忽略 self-edge 是源码事实，
  本单不将其缓存位置列为稳定语义承诺。
- 同快照 d 的边界内像素 alpha255、hit=d，边界外 alpha0 且不命中；每 tick epoch 恰增1，
  所有 bounds 对照 Java getters 与投影。参数默认/同类复制及 rules 数组身份隔离有正反对照。
