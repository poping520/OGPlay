## 属性读取与源码对照

请求集合依据固定 REPORT.json 与 ROM R.styleable，native 按 resource-map ID 匹配，
不按 fixture 的属性名称猜 ID；原 ROM 根据 getIndexCount/getIndex 及条件分支消费。

| 阶段 | 真实请求槽 | 直接对照与默认 |
| --- | ---: | --- |
| View | 69 | id、padding、minimum、visibility；其余原 switch/条件读取。三参使用 caller defStyleAttr，res=0 |
| 具体测试 ViewGroup | 11 | clip/cache/split flags、persistentDrawingCache；initFromAttributes 的 defStyleAttr/res 均0。抽象类用 HierarchyGroup 两/三参构造调用父构造 |
| FrameLayout | 4 | foreground=null，foregroundGravity、foregroundInsidePadding、measureAllChildren；super与自身都用caller defStyleAttr |
| LinearLayout | 9 | orientation/gravity、baselineAligned、weightSum、largestChild、divider=null、showDividers/padding。缺席 weightSum=-1，Context-only为0 |
| RelativeLayout | 2 | gravity、ignoreGravity；自身两参 obtain，不误用 caller defStyleAttr |
| ViewGroup.LayoutParams | 2 | width/height，getLayoutDimension(index,name)，缺席/错误类型抛异常 |
| MarginLayoutParams | 9 | width/height、统一 margin、四边/start/end；沿原 ROM 方向解析 |
| FrameLayout.LayoutParams | 1 | margin 父阶段后读取 layout_gravity |
| LinearLayout.LayoutParams | 4 | 父阶段读取尺寸/margin，自身读取 weight/gravity |
| RelativeLayout.LayoutParams | 23 | 22个 verb 与 alignWithParentIfMissing；正例逐一核 mRules，布尔规则为-1，ID锚点保持资源ID |

`theme_resources_tests.cpp` 新用例以真实 compiled XML/XmlBlock$Parser 逐元素直接驱动构造，
不经过 Legacy inflater；优先级夹具把 compiled layout 与 values styles 的 resources.arsc
放在同一合成 APK，ARSC 由生产 reader 读取。应用主题按 Manifest 已提取 ID 的进程输入注入，
Activity.setTheme 沿 ROM 应用；这不是 APK 启动或 inflater 验收。

优先级正反例为 orientation：theme=vertical；defStyleAttr 指向 horizontal；XML style
指向 vertical；显式 XML horizontal 覆盖 style；反向显式 vertical 覆盖 horizontal style。
现有 DVM-288 用例继续覆盖 defStyleRes、@null、force/copy、引用/parent/?attr 及循环。

基础主题的 scrollbar thumb 本来是不支持值，不可假装缺席。正向应用主题显式以 @null
覆盖两个 thumb；未覆盖的默认主题请求仍失败。由封存 styleable 名称/ID 建立只读 drawable
类别，Styled 选择优先级并解引用后，任何实际非空 background/foreground/divider/thumb/track
均在 Java 数组发布前记账失败，包括颜色值；无值才允许 null。scrollbars 非零由原构造调用
未启用 initializeScrollbars，明确失败。未知/未登记主题仍明确失败。
动画、光学布局、绘制/系统附着、完整 TextView 与实验 inflater 不属于本单支持路径。

## 几何对照与四类准入

XML 与代码构造的同形树共用 ContainerVm，真实 Window FrameLayout 为根，经 VD-05
EnsureAndroidUiTraversal measure/layout/单次投影；未使用 Legacy bounds 作为 oracle。
EXACTLY 200×140，父 padding=5，child LP=40×20、margin=3：三标准容器 child
边界为(8,8)-(48,28)；具体测试 Group 的测试 onLayout 故意置(0,0)-(40,20)。
两种构造的 root/child measured 与四边逐项相等，并独立断言上述源码推导值。
既有容器主题继续覆盖 AT_MOST/wrap、weight/baseline、RTL/margin、依赖规则与失败边界。
View 本身作为属性构造叶参与同一树；Group 不作为可实例化 Android 抽象类使用。

REPORT §2.2 固定四类依据最终配对真实 surface 的 implemented 状态重算，由3/4升为4/4；
WeightedLinearLayout 的属性父构造阻塞已消除。固定输入/选择器均未改；
四类仅为准入模型夹具，不表示完整 widget 能力或强制加入运行配方。
证据为 `experimental-surface.json`、`frozen.py`、`frozen-fixtures.json`；
不把配方收录数或保留的方法体误作运行/准入信用，不强行收录 closure 不可达类。
