AttributeSet 原抽象接口形状供 ROM parseInclude 的资源 getter 解析；不添加模拟成功的接口实现。
LayoutInflater 的构造、from、inflate 四重载、rInflate、createViewFromTag、onCreateView、
parseInclude、parseRequestFocus、Factory/Factory2/PrivateFactory 链、Filter 设置均保留 ROM。
Factory、Factory2、Filter 保留原接口；FactoryMerger 执行原 ROM。
View.onFinishInflate 使用原 ROM 空扩展钩子，不用宿主模拟完成回调。

固定 framework.jar/framework2.jar 均无 PhoneLayoutInflater class_def。实验 companion
[LocalLayoutInflater.java](../../../tools/bootdex/experimental-java/android/view/LocalLayoutInflater.java)
按 AOSP 4.4 PhoneLayoutInflater：widget→webkit→父 android.view 前缀顺序；复制构造保留
Factory/Factory2/PrivateFactory/Filter，cloneInContext 改 Context。独立编译，源码哈希进入
实验 manifest；不修改 Legacy guest Java 或生产配方。实验替换额外移除 Legacy LocalInflater。

Resources.getLayout adapter 只查当前 APK 已选 layout 类型，沿现有 AssetManager
openXmlResourceParser 打开真实 ROM XmlBlock.Parser；系统/非布局/缺资源明确失败。
Context 基础服务缓存进程 inflater，ContextThemeWrapper 保留 ROM 的克隆及每 wrapper 缓存。
View trace tag 接缝转结构化 debug begin/end 日志，其余 tag 记账拒绝；无系统 atrace。
ROM inflater 精确引用的 blink 构造由拒绝 adapter 记账抛 UOE，绝不构造动画对象；
其余 BlinkLayout 方法与 callback 继续 failure，不把保留字节码当实现信用。

## createView adapter 与 ROM 对应 review

ADR-0158 决定3授权的 overlay，仅替换 ROM 的动态反射接缝；ADR-0159 DYNAMIC_TARGETS
规则不变。实际仍调用 guest ClassLoader、Class 及 Constructor 的现有反射实现，不按标签建宿主 registry。

| AOSP 4.4 createView 阶段 | adapter 对应 |
| --- | --- |
| sConstructorMap.get(name) | 读取 ROM static HashMap；键仍为短 name，不另加 prefix 或宿主缓存 |
| mContext.getClassLoader().loadClass(prefix+name).asSubclass(View.class) | 真实 guest 虚派、Class 对象及类型检查，应用 APK 类可见 |
| 未缓存 mFilter.onLoadClass | 真调用 guest Filter，拒绝沿 ROM failNotAllowed 文本产生 InflateException |
| getConstructor(mConstructorSignature) 与 put | 原 ROM Class[]，只找 public (Context,AttributeSet)，缓存真实 Constructor |
| 已缓存 Filter | 原 mFilterMap 的 Boolean 三态；首次复查类并保存结果，后续拒绝不重调 Filter |
| mConstructorArgs[1]=attrs / newInstance(args) | 原 Java Object[] 与真实 guest Constructor.newInstance；反射自身建立 InvocationTargetException |
| context/attrs 恢复 | 原 ROM inflate finally 恢复 args[0]、清空 args[1]；direct createView 与 ROM 一样不另清参数 |
| NoSuchMethodException / ClassCastException | position+完整名的 ROM 文本；原异常作为 cause |
| ClassNotFoundException | createView 原样传播，ROM createViewFromTag 再包装完整 InflateException |
| Exception 通用分支 | position+clazz 名或 `<unknown>`；Filter 自身 InflateException 也按 ROM 再包一层；Error 不误包 |
| ViewStub 后处理 | ViewStub 构造为 failure，因而不进入成功后的 setLayoutInflater；未宣称 ViewStub 支持 |

普通 adapter 没有新增 native。缓存、工厂、参数和 Filter 状态归原 Java 字段，GC 沿原对象图保活。

## inflate、Window 与失败边界

XML start-tag/current attrs、应用主题优先级、父 LP、include 尺寸回退/id/visibility 覆盖、
merge 根约束及 Factory 链均由 ROM 方法决定。宿主不补尺寸或写第二份几何。
Activity 的既有委托进入 Window；View/LP 重载沿真实 Java addView/removeAllViews。
setContentView(int) 先在未发布的 FrameLayout 上调用 ROM inflate(resource,root,true)，成功后
转移完整子树至稳定 Window.mContentParent。失败不清旧根、不递增内容 revision、不发布新投影。
成功树仍由 VD-05 owner 遍历、VD-02 单次提交；render/hit-test 读取同一不可变投影。

支持五类基础容器（抽象 ViewGroup 用应用具体子类）、应用 View/ViewGroup 子类与 include/merge。
TextView/ImageView/Button/EditText/ScrollView/ViewStub 等构造明确失败，由 ROM/反射包装
InflateException；不引入完整文本控件、Drawable、动画、Binder/WMS/system_server。
原 ROM Factory 回调的用户代码及异常时序保持，不宣称回滚应用代码已发生的副作用。
