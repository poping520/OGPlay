## 范围与迁移账

仅实验 JavaTraversal 配对开放 APK PNG/JPEG、TYPE_INT_COLOR_* 与单态 ColorStateList。
无叶控件构造、测量 adapter、完整 Paint/TextView、系统资源或任意 Drawable 绘制。
Legacy 仍为生产默认；未启动完整 APK，未执行 git commit。

- 在既有十组之外登记 TextViewAppearance、TextAppearance、TextView、ImageView、ScrollView、
  HorizontalScrollView 六组 ROM 数组；REPORT 七组中的 ProgressBar 不登记。
  defStyleAttr 与 ?attr/default-style 递归消费集也逐项绑定 ROM ID，无手工猜号。
  主题三态与默认 style 闭包由固定 values 源生成；selector/未支持默认皮肤保留为不支持，
  不删默认请求，不改 defStyleAttr。单态源码颜色可解析，stateful 颜色资源继续失败。
- APK owner 向 ThemeResources 注入单 entry 配置选择与文件验证回调；引用链仍独立遍历，
  合并 configuration flags、保留最终 ID、cookie=1 与选中 density。选择算法从原
  ResolveUiResourceEntry 原样提取，Legacy 16步引用语义保持，机器去空白比较通过。
- 文件扩展名与 PNG/JPEG 编码匹配、解码范围和 npTc chunk 在六槽发布前验证。
  theme/XML/style/default 的优先级、REFERENCE0 遮蔽与 TYPE_NULL 回退沿 DVM-288；
  解析完整向量后才写数据/indices，不支持不得降为 @null。
  已知系统/应用 style bag 保持 terminal reference 供 getResourceId 消费，不误当作标量文件；
  resolveRefs=false 也不绕过已经选中文件的安全边界。
- 新组合 Drawable、BitmapDrawable、ColorDrawable 共 **142个形状成员**（121方法/21字段）：
  7个 ROM 方法、6个 overlay、108个 failure；既有组合8个方法改变来源。
  完整 flags/body/字段初始化账见
  [view-leaf-resources-sources.json](../../../tools/bootdex/view-leaf-resources-sources.json)，
  Resources/TypedArray 升级见 [view-theme-sources.json](../../../tools/bootdex/view-theme-sources.json)。
  新增/受审 adapter **9个**，新增 native **0个**。差分证据 `member-review.json`。

| 受审 adapter | 输入、结果、状态 owner 与失败边界 |
| --- | --- |
| Resources.getValue(ILTypedValue;ZZ)V | ROM 厂商重载的标量 APK 接缝；mIcons/mComposedIconInfo 必须真实 null，非空失败；调用原 AssetManager.getResourceValue，不组合系统图标 |
| Resources.loadDrawable(TypedValue,int) | 校验文件 six-slot 事实；真正分配 Java BitmapDrawable/ColorDrawable，构造成功后发布 backing；无系统资源回退 |
| Resources.loadColorStateList(TypedValue,int) | 仅 TYPE_INT_COLOR_*；实际执行 ROM ColorStateList.valueOf，不提取 selector defaultColor |
| BitmapDrawable(Bitmap) / (Resources,Bitmap) | 调 ROM Drawable 基础构造；写原 mBitmap、mTargetDensity、mBitmapWidth/Height；无 Resources 用160，有 Resources 读真实 metrics；尺寸按 API19 scaleFromDensity 舍入 |
| ColorDrawable() / (int) / setColor / getColor | 调 ROM Drawable 构造；color 唯一归对象对应的宿主值，mPaint/mState 等未启用字段明确失败；不构造空 Paint 冒充绘制 |

Drawable 的原 clinit/基础构造与 BitmapDrawable intrinsic/getBitmap 读取执行 ROM；
Resources.getDrawable(I)/(IZ)、getColorStateList、getValue三参，以及 TypedArray 两 getter
执行 ROM。实际支持分派含 Resources.loadDrawable/loadColorStateList、AssetManager.getResourceValue、
BitmapDrawable.getIntrinsicWidth/Height、ColorDrawable.getColor；运行支持路径 ledger 零未实现命中。

资源 Bitmap 不可变，源像素保留 source density；intrinsic 换算至目标 density，nodpi 不缩放。
这与 API19 BitmapDrawable(Resources,Bitmap) 的尺寸换算一致，不声称 BitmapFactory 解码重采样。
Java mBitmap 是 GC 强边；宿主 leaf_pixels 为对象拥有的不可变 backing，不进入 ui_bitmaps
全局缓存。颜色 intrinsic=-1，不伪造1×1。sweep/teardown 复用既有对象状态退役。

## 失败边界与规则裁决

selector（含看似单色）、ninepatch 文件及隐藏 npTc/npLb chunk、XML drawable、未知文件、
引用循环、动画、系统皮肤、scrollbar、background/foreground/divider 非空属性全部明确失败。
Drawable.inflate/createFromXml、StateListDrawable、NinePatchDrawable、custom draw 未准入。
失败不发布六槽/indices/新对象/backing 或 UiTree 投影；不能回滚已经执行的 guest 回调。

**按常设原则自行调整审计规则：无。** 未修改 selector/member_sources 审计，
clinit、direct/static/super/精确接收者、本类 failure 字段与 ADR-0147 规则完整保留。
固定 ROM 的 composed-icon 重载采用有界 adapter，是本单成员迁移，不是审计规则豁免。
loader 只提供已有 ARSC/ZIP 事实，契约未变，故不改 loader MODULE；integration MODULE
更新回调/对象 backing 契约。CURRENT 增加0字节。
