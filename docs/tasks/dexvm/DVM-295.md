## 迁移、adapter 与 review

完整 ROM TextView shape/clinit、原 flags/body/hash 保留；onMeasure 的来源明确为 overlay，
原 ROM TextView.onMeasure 不获实现信用。新增组合形状成员0、受审adapter34、native声明0；逐签名 adapter
及数量由 `adapter-review.json` 与 `tools/bootdex/view-paint-sources.json` 列账。

- onMeasure 复制宿主文本输入，虚派 Java compound padding/suggested minimum，调用纯叶服务，
  再真实虚派 setMeasuredDimension。无 measured/bounds/flags 写入、子树递归或 LayoutUiTree。
- setter/getter：plain String/null、px/dp/sp 字号、四样式 Typeface、纯色/单态 ColorStateList、
  绝对 gravity、singleLine/maxLines、四绝对 APK BitmapDrawable 槽；资源重载先取得全部对象。
  未支持 glyph/shaping/RTL/stateful/Drawable 请求明确记账失败，不伪造 Layout/TextPaint/Editor。
  文本只有宿主输入一份，Typeface/Drawable 身份由已有 owner trace/sweep 管理。
- setter 校验后变更输入，经真实 Java requestLayout/invalidate。失败不回滚已发生的 guest 回调，
  未成功完成遍历不得发布新快照。构造的独立 singleLine 位保留原文，测量时将 LF 转为空格；
  CR/FEFF 等未支持字形仍拒绝。setSingleLine 本身不隐式请求 ellipsize，构造属性规则保持。
- TextView 的 padding/layout/setFrame/drawable/RTL 回调执行真实 View 父协议；此有界路径没有
  Editor/Layout/相对 Drawable 状态，不执行这些未支持对象的协议；RTL 请求仍失败。
- 每输入版本保存按最终宽度区分的 immutable plan；ROM cache 恢复旧尺寸时按最终 Java
  measured width 选取对应 plan。JavaTraversal 完整 epoch 同时冻结 text/style/plan/geometry，
  presenter 不重新测量或断行。getBaseline 返回固定字形首行 baseline 与垂直 gravity offset。
  子类不调用 super 时仍正常虚派并保留 Java 自定尺寸；owner 发布阶段只按最终尺寸准备光栅 plan，
  不进入 adapter、不写几何；无叶测量时 getBaseline 仍为 -1。

## AOSP 逐方法审查与 Legacy 差异账

固定输入：`.local/aosp/framework/base/core/java/android/widget/TextView.java`。
这是固定字形的有界文本服务，不宣称实现 StaticLayout、完整 Android 字体/排版。

| 方法 / 事实 | JavaTraversal 规则 | Legacy |
| --- | --- | --- |
| onMeasure:6278–6454 width | 先按原文/顶部底部 Drawable 取 desired，加左右 compound padding，再按 EXACT/AT_MOST/UNSPEC 选宽 | 保留原 spec 扣普通 padding 的公式 |
| want:6380 | 从选定宽度扣左右 compound padding，再生成唯一 plan | 测量只扣普通 padding，renderer 扣 compound，既有差异保持 |
| getCompoundPaddingLeft/Right:1762/1775 | Java padding + 左右实际位图宽度，drawablePadding 非零仍不支持 | 原四槽尺寸公式不变 |
| getCompoundPaddingTop/Bottom:1736/1749 | Java padding + 上下位图高度；可用高度与 baseline 同源 | 原公式不变 |
| height / getDesiredHeight | 固定字体可见行高与左右 Drawable 高度取 max，加上下 compound padding 与 minimum；按 spec 裁剪 | 原 M 占位、Clamp 保持 |
| measured state | TextView 直接 min(widthSize,width)/min(desired,heightSize)，不调用 resolveSizeAndState；三种 mode 均不置 TOO_SMALL | 仍忽略纯叶通用 TOO_SMALL 输出 |
| getBaseline:5272 | 服务首行基线 + compound top + 垂直 gravity；无已完成叶测量时 -1 | 原行为不变 |
| 空串 / maxLines | 空串宽0、保留固定行高；先换行再裁可见行；singleLine 禁止换行 | 历史 M cell / maxLines 算法保持 |

DVM-291 向量（8px、HI HI、padding 1/2/1/2、左右各6×7、AT_MOST32）：
Legacy 32×11；JavaTraversal 宽32、desired43×19、plan HI\nHI；高度AT_MOST10得到32×10、state0。
不能把 DVM-291 原通用 CompoundPadding 结果25×19或通用 TOO_SMALL 冒充 AOSP TextView。
