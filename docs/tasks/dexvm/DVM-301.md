## 迁移与 adapter review

保留两 Scroll 完整 ROM shape、原 flags/body/hash、初始化和 failure 来源。新增组合形状成员0，
新增 adapter2、native0；15个已有方法升 ROM，1个已有字段升 rom 可用性。精确来源变化及源码身份见 `source-review.json`。
HorizontalScrollView 原 onMeasure、measureChild/WithMargins、四个单 child addView、onLayout、
onSizeChanged、scrollTo/clamp 与直接依赖升为 ROM；原 requestLayout/构造/属性消费保持 ROM。

- 横轴先 UNSPECIFIED；fillViewport 只在父宽度非 UNSPECIFIED 且 child 小于 measured width
  时补 EXACT，原式只扣 padding，不额外扣 margin。
- onLayout 原样调用 FrameLayout.layoutChildren(forceLeftGravity)，超宽 child 强制左对齐。
  首次 RTL 计算 scrollRange−mScrollX 后 clamp，后续布局不重复反转。非空 SavedState 恢复
  入口仍 failure；mSavedState 仅开放真实 null 的原字段供活动布局体读取，不伪造恢复成功。
  封存 surface 补录已在实验 BootDex 的 HorizontalScrollView.SavedState 原字段证明；
  严格字段审计保持，无新 class_def 或恢复协议信用。
- 两个新增 adapter：HorizontalScrollView.onInterceptTouchEvent/onTouchEvent，沿 DVM-300
  宿主有界单指作用域协议。前者真实委托 ViewGroup 父方法，后者只接受有内容的 DOWN 捕获
  及后续 MOVE/UP/CANCEL；作用域外/null/多指明确记账失败。Java 不持镜像拖动/速度状态。
  输入/输出、owner、失败边界逐签名封存在
  [view-scroll-sources.json](../../../tools/bootdex/view-scroll-sources.json)。
- 原 initScrollView/setOverScrollMode 与 idle EdgeEffect 接缝保持，不新增资源或动画信用。

## 投影与输入契约

UiProjectedNode/UiNode 增加 scroll_x，原位置参数初始化保留兼容；collector 用已有绑定 token
读取真实 mScrollX/mScrollY。screen(child)=screen(parent)+local(child)−parent.scrollXY，
两轴以64位累加、32位范围受检，同 epoch 冻结 frame/clip/raster/hit。非法/旧批次整体拒绝，
保留旧发布快照。Java 位置与 child local frame/measured 是唯一事实，无几何回填。

ScrollAndroidViewBy 接受两轴 delta（保留既有 delta_y 参数，附加 delta_x），验证 owner、
根内身份及已有完整投影后调用 Java scrollBy→scrollTo/clamp，仅发布新投影；不重测/重排。
session 在实验水平容器上使用 X slop/delta，垂直继续使用 Y；接管时向原目标发送单一 CANCEL。
HorizontalScrollView 使用独立 UiClass，原枚举数值保持；Legacy 原纵向位置写入分支保持，
静态门禁检查 session 的任一 XY 写入只能位于显式 Legacy 分支。

ui、integration、session MODULE 按契约更新；loader 的成员来源/绑定/GC 接口不变，不改其
MODULE。capabilities 维护既有 partial Scroll 项；CURRENT 增量0字节。

## 失败边界与审计决定

fling/smoothScroll、EdgeEffect 激活/绘制、scrollbar Drawable、SavedState、focus 滚动及
完整 ROM touch 分发仍按 ADR-0147 明确失败；不引入 WMS/Binder/system_server/完整控件栈。
按编排方常设原则自行决定的审计规则范围调整：**无**。direct/static/super/精确接收者、
failure 字段和 clinit 规则均未放宽。撤销构造直接依赖或 adapter review 的负例仍被拒绝。
