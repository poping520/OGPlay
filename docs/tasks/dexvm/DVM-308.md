## owner 协议与失败边界

- Start 首次 owner tick 建立完整根/快照，Surface 前完成 ROM 尺寸；global layout 在 Surface
  之后通知，回调 mutation 后再执行同 tick 屏障。Resume 完成 resume/focus 后建立 owner tick，
  再同步内容/Surface；新增工作只在 JavaTraversal 分支执行。
- StepFrame 输入前 OwnerTick，Looper/媒体/音频/switch/内容与窗口 focus mutation 批后
  BeforePresent；内容/Surface 使用 BeforeSurfaceCallbacks。后两者均不递增逻辑 tick，
  第二 pass 延期仍留到下一 tick；clean 不测量、不推进 epoch。
- Java 尺寸 phase 只调用 ROM measure/layout，onSizeChanged 由 ROM 同步派发；不进入
  Legacy 八轮通知。created/changed 在遍历后抓取本轮 pending，成功回调后消费。
- owner 发布前刷新叶图像与 producer 事实；纯绘制只冻结新投影，不再次 measure/layout。
  presentation epoch 触发纯 View/空窗口/modal 软件基帧与 intrinsic WHEN_DIRTY draw request。
  Compose 不进入 guest、不补遍历、不消费脏状态。
- 真实 lifecycle 证实 Activity 栈旧分支会附着第二个宿主窗口根；本单作为首帧必要依赖修正：
  Window 内容构造把记录关联真实 Java FrameLayout，创建前只查询空投影根，不作宿主 Attach。
  完整多窗口保留/切换仍是 DVM-310，未宣称已实现。
- owner/token/线程与输入重入拒绝保持；坐标回调只读临时投影，既不发布也不派 Surface。
  未附着坐标、TransformationInfo、硬件/动画、系统附着、状态皮肤、IME/长按 timer 服务
  保留 ADR-0147 记账与明确失败，不创建 AttachInfo/Binder/WMS/system_server 或完整 TextView。
  Surface 回调逐代次重验、输入事件事务和媒体共同 lease 收口仍属于 DVM-309/310。

integration 两级 MODULE 与 session MODULE 按调度契约更新；loader 的解析/绑定格式未变，
故不修改 loader MODULE。capabilities 维护既有 partial 组合条目；CURRENT 增加0字节。

## 常设原则审计决定

**无规则适用范围调整。** direct/static/super/精确接收者与本类 failure 字段仍严格，
clinit 规则未变；普通虚派沿既有 dispatch ledger，failure 不获得实现信用。
本次没有新增或放宽审计规则，ADR-0147 不伪造成功保持。
