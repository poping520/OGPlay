## 真实证据与可复现边界

只读 C/B 原始日志，路径与 SHA 保存在 source-logs.json。
C 的 tml/dead_trigger 越过 NativeActivity.onCreate 注册 observer 后在 CLI 兜底退出，
日志没有被吞掉的异常类型，**不能从原日志确定具体抛出成员**。
原 ROM NativeActivity.onCreate pc79 setContentView、pc93 getViewTreeObserver、pc99
注册自身；onGlobalLayout pc6 查询窗口坐标、pc11/17 查询宽高，再进 native 内容区域回调。
宿主启动在 EnsureOwnerFrame→Surface created/changed→DispatchAndroidGlobalLayout
直接调用 ROM observer；CallAndroidMethod 将 VmCallOutcome 重新抛为非 std 的
VmJavaThrow，旧 Start 只标失败后重抛，最终成为 unknown CLI failure。

新 NativeActivity 风格 Java fixture 在 onCreate 分别从 content/decor 注册 listener，
回调查询窗口坐标/宽高；两次显式注册按 ROM 语义保留两次调用。旧 decor 是脱离 Java 父链的额外 View，回调明确失败：
`Ljava/lang/UnsupportedOperationException;: Coordinates require managed attachment`；
随后 listener calls=0、动态未实现不为空。修复改为稳定 managed 根的真实身份。
原版 NativeActivity 的无窗口、无 GPU 生命周期最小 fixture 原先即通过；因此这条修复
不能被描述为已经证明真实 tml/dead_trigger 的具体异常起点，须用新增诊断外验。
另注入真实 observer 回调异常，修复前 `CHECK_THROWS_WITH_AS` 得到 unknown exception，
修复后必须是带类型/消息/阶段的 DexActivityLifecycleError，生命周期仍 failed。

C 的 lili 日志为 created→changed→destroyed→created；B Legacy 重建后有 changed。
只读 APK DEX 的 surfaceCreated/Changed 与 createEGLSurface/initEGL，证据另存 dex.txt：
主回调在 created 内初始化/重建 EGL、可能进入 native，再在 changed 消费真实尺寸。
通用触发链是 session 内容同步/owner 安全点→PumpAndroidSurfaceEvents→冻结 holder→
created→身份复核→changed；窗口 takeSurface、SurfaceView/GLSurfaceView 均经过这里。
生命周期 focus/visibility/尺寸变化改变窗口事实或触发内容/挂载更新，Legacy 保持旧分支。

已复现的漏派序列：同尺寸 destroy→create，created 中 Window.addContentView 追加无关
sibling，改变全局 content revision；原代码把仍存活的 holder 判旧，取消 changed，
下一轮还会多派 destroy/create。VD-11-6 只清尺寸缓存，没有改变此身份判定。
fixture 的原输出为两处 `events == {1,2,3,1,2}` 失败；完整 pre-fix 输出
repro-before-final.log：4项1通过3失败，110断言中12失败，双解释器。
这证明一个能生成相同漏派序列的通用时序；旧日志没有逐 holder/内容 revision trace，
**不能宣称已排他证明真实 lili 的具体 mutation 来源**，九场景外验仍必要。
