## 真实触发序列与修前复现

C/B 原始日志只读，六份路径与 SHA 在 source-logs.json。C 的 tml/dead_trigger 在
NativeActivity global layout 查询窗口坐标失败，lili 在 f=259 的 UI scheduled callback
inflate RelativeLayout 失败；不把 reached-fault 当作游戏兼容验收。

AOSP4.4 NativeActivity.onCreate 创建 NativeContentView、setContentView、requestFocus，
再从该 View 的 observer 注册自身。只读两个 APK 的 onCreate 可见：super.onCreate 后
再次 setContentView，用另一个 View 替换初始内容；都发生在首次宿主 traversal 前。
DEX 静态证据 tml-oncreate.dex.txt 为 super pc6→takeSurface(null) pc14→setContentView pc61，
native-subclass-oncreate.dex.txt 为 pc13→pc21→pc83；inflate-callback.dex.txt 在 pc21
实际调用 inflate，资源参数来自 R.layout.movielayout。
ViewRootImpl.performTraversals 首次 dispatchAttachedToWindow 先于 measure/layout，
global layout 在布局之后派发。原实现却按 Java 父链连到根就直接取得窗口 observer，
setContentView/onViewAdded 还立即合并 floating listener。因此旧内容虽然已移除，监听器
已不可逆转移到窗口，后续回调查询它的坐标时正确遭到未附着门禁拒绝。
不是投影漏节点或根身份错误，也不是应给已移除 View 伪造附着。

双后端 fixture 复用 NativeActivity 风格 ROM observer 注册与坐标查询，首次 traversal 前
替换内容；隔离 decor 的另一显式注册后，旧代码仍向已移除内容派发。
修前 repro-before.log：2项0通过，126断言10失败；附着项出现
`UnsupportedOperationException: Coordinates require managed attachment`、floating==window
及支持路径 ledger 非空。修后还直接查询已移除 View，必须继续同样明确失败。

lili APK 的 res/layout/movielayout.xml 已直接读取并解码二进制资源，完整节点、属性
与 APK/条目 SHA 在 apk-layout.json、movielayout.axml；不是仅依据反编译 XML 推测。
根 RelativeLayout：orientation=0、width/height=-1；子树为 SurfaceView 和 TextView。
入口 UE3JavaApp$13.run 调 LayoutInflater.inflate；LayoutInflater.createView 通过真实
Constructor.newInstance 调 RelativeLayout(Context,AttributeSet)，再进 ViewGroup/View
属性构造。fixture 保留这三个根属性及 Theme.NoTitleBar.Fullscreen，最小化掉尚未到达的
子树；异常发生于根构造、尚未生成子节点。
真实内层为 `UnsupportedOperationException: unsupported projected value:
@android:drawable/scrollbar_handle_horizontal`，首栈为
`Resources$Theme.obtainStyledAttributes (pc 23)`。旧诊断只输出 InvocationTargetException，
导致修前 cause 类型/消息/首栈四条断言失败（双后端）。
按任务允许的 scrollbar 边界，仅交诊断，保持失败；需要同 ROM framework-res.apk 的
资源认证，不能猜私有 ID、删默认请求、改成 null 或引入完整系统 Drawable/TextView 栈。
