## 根因与事实来源

只读指定 11-12 C stderr 第 34–55 行：producer 已在投影，Java 父链完整、逐级 VISIBLE、
测量 800×480，但 visible=0。旧诊断只到 Java content 根，未列 synthetic partition root，
不能把 `first_break=0` 解释成 UiTree 所有祖先窗口位均为真。源文件身份与摘录保存在
source-evidence.json；没有修改旧 gate。

源码闭环：UiNode 的 window_visible 默认 true；collector 原来只提交 Java visibility，
CommitProjection 从构建树复制全部 window_visible。JavaTraversal 的 Window 内容根创建
原来以“当前 Activity”推断可见，生命周期 resume 不重新发布窗口事实。
更关键的是首遍历前的 retiring handoff：旧 Activity 尚无 window_root，ActivityContentRoot
返回共享 synthetic root；retire_active 的 Legacy 写入把它隐藏。新 Activity 建立真 Java
content 根后只设置该节点为 true，共享 synthetic root 仍为 false，被每次投影继承。
既有只读 DEX 摘录还确认 ProxyActivity.onCreate pc57 startActivity、pc60 finish，
API19 路由到 NativeActivity，期间没有创建 Window 内容根；摘录身份与片段一并封存。
因此失败级别是 **synthetic partition root**，不是 Java 父链、GLSurfaceView 自身或
`takeSurface(null)`；后者只更换 window holder 代次，不写窗口可见位。

双后端 fixture 使用同一生命周期命令队列，在 launcher.onCreate 内排 launch+finish，
不先建立窗口或投影；目标仍执行既有真实 DEX NativeActivity 子类、takeSurface(null)、
容器 setContentView、resume 与 windowFocusChanged(true)，其后才 addView producer。
修前 `repro-before-both.log` 两后端均明确断言 synthetic root=false，而 Java content 根及
producer 窗口位为 true；没有人为置 false。其余 early/late 控制继续执行。
旧真实日志没有保存 C++ 内存位，实际游戏的该级写入由源码与因果 fixture 定位；新增
projection_chain 诊断会在外验中直接显示完整投影祖先位，不能用 CPU 证据替代 APK 恢复。
