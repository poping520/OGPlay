## 审计与迁移 review

`python3 .local/analysis/vd-121/audit.py` 可重算 `policy-audit.json`，两次输出逐字节一致。
输入含用户指定 policy SHA-256、四 JAR 身份、ZIP 时间/manifest、DEX 头/checksum/
signature、完整 class_def 清单。五包 manifest/DEX 打包日均为 2014-11-20、JDK 均为
1.7.0_65；无重复类。300个共享类型、919个共享方法引用及88个共享字段引用全部解析；
4229个可解析 policy 调用点的 static/instance 属性一致。

DEX ID 按符号映射，数字因包而异；flags/方法体摘要来自唯一声明。跨包没有重复
class_def，外部引用不携带 flags/方法体，不能虚构“外部方法体相等”的比较。
结论是与同批 ROM 一致；输入 SHA 锁定，不宣称密码学证明共同构建。

闭包覆盖 PhoneLayoutInflater 全部5个方法、父类/接口初始化、分配、静态字段初始化
和传递符号调用：328个成员、168个类型。38个已有 native 与8个 abstract 开放分派
终点明确列出，没有未解析终点。普通开放虚派不是任意 APK 覆写的封闭世界证明；
现有 createView 反射 adapter 与 dispatch ledger 继续约束实际支持路径。
禁止集合命中为0，因此执行替换；未选择其他 policy 类。

新增组合成员 **6**（5个 ROM 方法、1个 ROM 字段），新增 adapter/native **0/0**。
已有 Context.getSystemService adapter 改为直接构造 ROM PhoneLayoutInflater，
同步其封存 review 的输出、状态 owner 和失败边界（改变既有 review 1项）；
字段 sClassPrefixList 与原 clinit、两构造、clone/onCreateView 全归 ROM。
方法体/flags/字段初始化逐签名见 `tools/bootdex/view-policy-sources.json`。
既有 LayoutInflater.createView adapter、Java 构造缓存、Filter 和 Factory 协议不变。

selector/形状工具支持第五来源，先对完整输入查重再选择；独立 policy reference/基线
核对固定 ROM 和最终 DEX own shape，不改 API19 骨架或共享 framework baseline。
selector 的缺失 policy 候选只标未实现，不赋予实现信用；实际成员仍经原严格审计。
删除实验 companion 和 CMake/制品审查引用，配对元数据随新 DEX/成员表更新。
生产 manifest 仅更新 composer 源码哈希，生产配方与 JAR 字节不变。

integration MODULE 更新实验服务来源契约；loader/ui/session 契约未变不修改。
capabilities 既有 partial 范围和可执行入口未变，仅 check；CURRENT 增加0字节。
按常设原则自行决定的审计范围调整：**无**。未放宽严格调用、failure 字段、
clinit/native/父接口、开放虚派 ledger 或 ADR-0147。

  clone Filter 再继续原成功路径，原断言未删，最终通过。中间日志只作排查证据。
- 两域 compose build/check；实验生成器每次独立组装两遍并比较 DEX/成员表，稳定源码后
  build 与 check 重建的 JAR 完全一致。首次中间构建的宿主扫描早于最终格式化，不作
  最终确定性比较对象。配对 identity 与实际 DEX 索引见 artifacts.json。

  selector 已知误读生产索引问题按 ADR 留 VD-12-2 处理。

  与 traversal 静态负例通过；严格成员/clinit/native/父成员拒绝规则保留。
