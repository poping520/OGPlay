## 原版闭包与停止边界

实际固定 ROM 的逐方法 flags、DEX method ID、指令摘要、完整反汇编和调用 PC 在
`framework-res-audit.json.closure`；不是用 AOSP 标签或源码行号代替该 ROM 证据。
View 带非零 scrollbars 标志时，原属性构造调用 initializeScrollbars；首次密度实例的路径为：

```text
View.<init>(Context,AttributeSet,int)
  → initializeScrollbars(TypedArray) → initScrollCache()
  → ViewConfiguration.get(Context) → ViewConfiguration.<init>(Context)
  → Display.getRealSize(Point) → updateDisplayInfoLocked()
  → DisplayManagerGlobal.getDisplayInfo(int)
  → IDisplayManager.getDisplayInfo(int) [IInterface]
```

ViewConfiguration 的构造先通过 window 服务取得 Display，再调用 getRealSize；
initializeScrollbars 在此之后才调用四个 TypedArray.getDrawable。
IDisplayManager 继承 IInterface，固定 Stub.Proxy 的 getDisplayInfo 明确调用
IBinder.transact；二者都封存在同份 JSON。ScrollabilityCache 构造还分配 Interpolator、
LinearGradient/Shader/PorterDuffXfermode；这部分仅列审计，不把 native 对象当作成功空值。

新导出的 `candidate-surface.json` 无 startup_link_error；其中 ViewConfiguration.get 为原版
bytecode，而 Display.getRealSize、View.initScrollCache/initializeScrollbars 为
unimplemented-ledger。现有 Display adapter 只提供 width/height/rotation/metrics，不能
借已支持的 getRealMetrics 冒充缺失的 getRealSize。逐项事实另见 runtime-boundary.json。

此为原版调用图中的越界依赖见证，**不宣称所有虚派目标必然走 Binder**。
要截断它需要另行设计有状态的有界构造/配置接缝；本单没有将未登记 adapter 视为已有实现。
按编排方“闭包若需要 Binder/WMS/完整渲染栈则停止并只交审计”执行，不迁入 Binder，
不重写请求、不跳过构造、不伪造缓存或资源成功。这不是因组合/准入审计规则范围过严而停下。

## 编排方复核与后续决定（2026-10-26）

- 静态：`tools/capabilities.py check`、`tools/check_ui_traversal.py` 通过；本单无 C/C++ 改动；生产 BootDex SHA-256 仍为 `909a702b…acbe8`。审计工具 `framework_res_audit.py` 自检通过，5752 个 R 常量零冲突。
- 停止边界复核：Binder 依赖只在“View 带非零 scrollbars 标志 → initializeScrollbars → ViewConfiguration.get → Display.getRealSize → DisplayManagerGlobal”这条路径上；scrollbar **引用投影**本身不涉 Binder，不应随之停止。
- 编排方决定（进入 VD-11-15 / DVM-325）：(1) 先交付引用投影；(2) `Display.getRealSize`/显示信息按 ADR-0162 managed-window 同型的有界 adapter 返回 managed 显示事实，不引入 DisplayManager/Binder，ViewConfiguration 其余照常走 ROM；(3) ScrollabilityCache 所需 Shader/Xfermode/Interpolator 用有状态 adapter（保存构造参数，用于绘制即明确失败）；(2)(3) 仅在静态证明真实场景 View 带非零 scrollbars 标志时实现。
