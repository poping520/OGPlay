## 四条真实失败路径的静态判定

只读证据为用户指定 VD-12-2 四份 stderr 及原 APK；没有用新运行替换原首报告。
`dump-res.cpp` 链接现有 loader，用严格 ParseCompiledXmlDocument/ParseArsc 导出
Manifest、APK style bag、Lili 布局及 framework-res 默认资源配置。
`static-scrollbars.py` 逐父链断言；可重算结果及原始文件哈希在 `static-scrollbars.json`。
DEX 反汇编保留调用 PC、原指令/寄存器和参数来源；ROM 父构造另存 `rom-constructors.txt`。

| 原失败栈 | 构造输入与默认样式 | 构造 scrollbars |
| --- | --- | --- |
| tales View / fGLSurfaceView | Context 单参构造 pc0 置 null AttributeSet，经双参 pc5 调 SurfaceView；ROM View defStyleAttr/Res=0，无 XML style | 0 |
| wild_blood EditText | Game.onCreate pc81 调 EditText(Context)，ROM 薄构造传 null attrs 与 editTextStyle；真实 Widget.EditText→Widget 无 scrollbars，Holo/DeviceDefault EditText 继承链亦无 | 0 |
| lili RelativeLayout inflate | UE3JavaApp$13.run pc21 inflate movielayout；根仅 orientation=0、width/height=match_parent，无 style/scrollbars，ROM RelativeLayout 默认 attr/res=0 | 0 |
| angry_birds BurstlyView / LinearLayout | Activity 单参构造 pc0 置 null attrs；双参 pc2 调 LinearLayout(Context,AttributeSet)，ROM 默认 attr/res=0 | 0 |

四个 Manifest 主 Activity 均指定 Theme.NoTitleBar.Fullscreen（0x01030007）；
同时审遍 ROM 全部 Theme.* 和 EditText 默认样式继承链，均无 scrollbars，覆盖真实日志
中 Holo thumb 的主题变体。四 APK 的全部 style bag 也无 scrollbars，且所有直接 ROM
style parent 均检查过；这不是仅检查 Manifest 而忽略应用覆盖。
Widget.AbsListView/ScrollView/HorizontalScrollView/WebView/ListView.Menu 等有非零默认值，
但不在这四条原失败构造父链；不以它们为由扩展本单。
ROM View(Context) 初始化 mViewFlags=0x18000000，scrollbar mask=0x300 为0；
属性构造仅在非零 scrollbars 分支进入 initializeScrollbars（pc1362→1366）。
因此按编排方决定4不实施显示/ScrollabilityCache 条件闭包。
此结论只限四条原失败构造，不覆盖后续 setter、其他 View 或其他场景。
