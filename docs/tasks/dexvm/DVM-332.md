# DVM-332：API19 进程内 ContentObserver

范围：Java ContentResolver URI 树注册/全量注销/通知、自通知开关、ROM Handler 派发；
无 Handler 改主 Looper；System 写入有效变更后通知。query/getType 保留 integration overlay。
不含 Provider 事件、跨进程/跨用户、sync、Transport/Binder 或下一运行首错。

依赖：原版 BootDex ContentObserver/NotificationRunnable、Uri、Handler/Looper，既有
Settings.NameValueCache 进程存储及 Java 客户端与 intrinsic 精确 overlay 机制。
观察者只由 Java static 树保活，无 C++ 影子表或 session root。

验收：双解释器定向回归、BootDex build/check、受影响目标构建，以及真实启动一次确认
原 registerContentObserver 缺成员消失，记录下一首错。证据见下。

## 实现与准入

- 新有界 ContentResolver（API19 abstract Object 层级、公开观察者签名），Java static
  authority/path 树保存强引用；锁内收集、锁外原版 dispatchChange。
- private native hasHandler 只读取 ContentObserver 定义类的 mHandler，避免子类同名字段
  遮蔽；无 Handler 经主 Looper。没有 Transport/Binder 或宿主注册表。
- System 写入比较原值，实际改变后调用原版 Settings.System.getUriFor 与 resolver
  notifyChange；Secure/Global 原有失败记账保持。
- composer 扩展固定 Java 源清单并核对 ContentResolver 的三个 native 签名；原 JNI
  payload generator 未修改。query/getType 的 C++ 方法体未修改。
- 保留开始前已有 Activity.java 改动，生成 manifest 同时反映该工作区源码；除 boot_dex
  外的 manifest 顶层内容与开始时一致。
