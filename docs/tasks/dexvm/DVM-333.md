# DVM-333：JNI 对象统一经 VM 分配

状态：完成；定向用例与 JNI 一致性通过，文件内一项既有失败经对照确认。局部修复及一条跨模块不变量，无 ADR。

## 根因与改动

NewObject/V/A 原先由 JniGuestObjectRegistry 分配宿主身份，首次入 VM 时惰性导入；
intrinsic 类按既有过滤导入为 external。URL 构造器的 BoundInstanceField 写入因此缺少
vm_instance 槽表。取证：`.local/island-board-capture.log`。

- 有分配 hook 时，三个 NewObject 入口统一委托 JniEnvironment::AllocObject → bridge
  AllocateJniObject；VM 唯一负责可分配性、类初始化、布局和 OOME。
- 分配/类初始化 Java 失败返回 null，跳过构造；构造抛 Java 异常仍返回 local ref 并保留
  pending。C++ 内部失败删除 local ref，VM 对象交普通 GC，不调用 registry Forget。
- 无 VM hook 保留原 HLE registry 分配及失败回滚；方法校验、参数解码、导入过滤未变。
- InstanceSlots 错误补充可用描述符、kind 枚举值与 class id，保留 object_model_failure。
- jni_guest/jni/integration 契约记录唯一分配路径。能力范围、状态和入口未变，账本未改。

语义依据：固定 AOSP Dalvik `vm/Jni.cpp` 的 AllocObject/NewObject/V/A
（1508 行起）；NewObject 在发布 local ref 后调用构造，Java 异常不撤销结果引用。

## NewDirectByteBuffer 审计（只读）

`jni_guest_bindings.cpp` 中 NewDirectByteBuffer 使用 registry Allocate，随后 WrapDirect
登记 NioRuntime 状态。`intrinsics/java_nio.cpp` 的 DirectByteBuffer 及父链
MappedByteBuffer/ByteBuffer/Buffer 无绑定实例字段；构造及 buffer 访问使用对象 identity
读取 NioRuntime，不走 InstanceSlots。该文件的 BoundInstanceField 属于 Charset.canonicalName，
InstanceSlots 属于 FileChannelImpl.fd，均不在 direct buffer 调用路径。
因此未发现相同槽表缺失问题，本任务不修改该路径，也无需另开修复单。
