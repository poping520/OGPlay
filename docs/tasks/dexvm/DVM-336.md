# DVM-336：ROM Choreographer 与宿主呈现帧源（WU-3a）

状态：有界完成；新增 7 例通过，BootDex build/check 与闭包核对通过，原 APK 仍首错 ofFloat。基于未提交 DVM-334/335 与 getIdentifier 修复继续，不提交。

## 范围与依据

ROM Choreographer 及 $1/$2/FrameHandler/FrameDisplayEventReceiver/CallbackQueue/CallbackRecord，
DisplayEventReceiver 原版 Java 与三个逐签名 native。FrameCallback 原已在配方。
不纳入 ValueAnimator/ObjectAnimator/PropertyValuesHolder 或 View.setAlpha（WU-3b）。

固定 Android 4.4.4 Choreographer.java：原 sThreadInstance、vsync=true 默认路径、回调队列、
输入/动画/traversal 阶段、延时与移除算法全部保留；DisplayEventReceiver.java 保留 CloseGuard、
MessageQueue 强边、dispose/finalize。JNI nativeInit 对未初始化队列 RuntimeException；
nativeScheduleVsync 为一次性请求；native dispatchVsync 的 timestamp 与 nanoTime 同基。

## 帧源与所有权

每个实际 lifecycle StepFrame 在任何 owner guest traversal/projection 前调用
DispatchAndroidDisplayFrame。先消费本时刻到期消息，再冻结/清除 receiver 挂起请求并向
所属 Looper 投递一次 display_vsync 工作，再泵主 Looper 交付 dispatchVsync；ROM receiver
接着以异步 Handler Runnable 调用 doFrame。帧回调中再 post 只能请求下一宿主帧。
Start/Resume/输入后布局/只读呈现屏障不生成额外 vsync；测试/MCP 每次单步最多一脉冲。
timestamp=统一 uptime_millis×1e6（与 nanoTime 同基），builtInDisplayId=0，frame 单调递增。
不注入 debug.choreographer 属性，不走 vsync=false 定时分支，无 hotplug/同步屏障。

int token 单调分配不复用，无宿主指针。receiver 弱关联、owner-attached trace 队列/Looper，
排队事件由 scheduler 保活；dispose/sweep/进程停止撤销 token，已排队失效事件不回调。
只支持主 Looper；其他 Looper nativeInit 记账抛 UOE，未初始化/死亡队列按 JNI 抛 RuntimeException。
进程一开始停止便禁派发并清登记，scheduler shutdown 同样清理。

Application 启动前先准备真实主 Looper，供 onCreate/onResume 直接取得 Choreographer。
Handler/Message.obtain(Handler,Runnable) 与 handleMessage 虚派原已实现；新增 getQueue、
Message 异步标志、队首 LIFO，普通同 deadline 消息仍 FIFO。异步标志只保存，不改变排序。
DisplayManagerGlobal 的有界 getInstance/getDisplayInfo(0) 接缝提供注入逻辑显示事实，
refresh_rate_hz 默认 60，可显式覆盖，非法值明确失败；无 Binder/WMS/显示监听。

## 准入与 overlay 审核

新增 framework.jar 八个 class_def 按有序配方装配，Choreographer$FrameCallback 原已准入；
未增 android.animation 类。DisplayEventReceiver 三 native 的私有 static 签名/0x10a flags
加入生成器现有 native ABI 核对，不修改 ROM 方法体。DisplayManagerGlobal 原已在 BootDex：
只覆写 getInstance()Landroid/hardware/display/DisplayManagerGlobal; 与
getDisplayInfo(I)Landroid/view/DisplayInfo; 两个精确方法。理由为原 ServiceManager/Binder
显示源不可用；输入为 displayId 及 context 显示事实，输出为原 DisplayInfo 值对象；
单例由原 Java sInstance 保活、原构造器初始化 lock/cache/listener，刷新率/尺寸/density 无额外状态权威，未知 display 返回 null，
非法刷新率 UOE 并记账，其他未支持方法仍按原机制失败。DisplayInfo 构造/字段保留原 Java。

`select_rom_java --scope closure` 及最终 dump-surface/check-closure 均核对实际装配。
准入前默认筛选器拒绝 Choreographer clinit 的 ThreadLocal/Throwable 保守闭包、
DisplayEventReceiver 的 native 方法；本任务是显式有界平台接缝准入，不修改通用 selector
或降低父链约束。实际 ROM 初始化/父构造/FrameHandler 虚派由双后端测试覆盖。
