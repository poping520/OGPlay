# DVM-338：裸 guest fd 的 FileDescriptor 语义与 ROM ParcelFileDescriptor

状态：离线验收完成，原 APK 待外验。类型：新能力/架构变化（intrinsic 撤换为 ROM BootDex + IoRuntime 描述符模型扩展）。
依据：AOSP 4.4.4 `ParcelFileDescriptor.java`、`AssetFileDescriptor.java`、`android_os_Parcel.cpp`
（openFileDescriptor/dupFileDescriptor/clearFileDescriptor）、libcore `Posix.java`/`IoUtils.java`；
撤换机制沿用 [DVM-268](DVM-268.md)；媒体 FD 区间沿用 [DVM-91](DVM-91.md)、[DVM-249](DVM-249.md)。

## 触发与根因

Island Castaway 1.3 打开视频：native `kdOpenAssetFd` 以 `open(KD_APK_PATH)` 得到 guest VFS fd 及
STORED 条目区间，Java 侧 `ParcelFileDescriptor.adoptFd(fd)` → `new AssetFileDescriptor(pfd,off,len)`
→ `MediaPlayer.setDataSource(FileDescriptor,off,len)` → `afd.close()`。运行时报
`intrinsic handler is not implemented: ParcelFileDescriptor.adoptFd(I)`，游戏捕获后视频不播放。

- native syscall 与 Java `Posix.open` 共用同一 `VirtualFileSystem`，fd 命名空间唯一。
- MediaPlayer 的 `DescriptorSource` 已按 jniGetFDFromFileDescriptor 把未登记 FileDescriptor 的
  int 当 guest VFS fd 并取 dup 式租约；该段无需重写。
- 缺口：手写 ParcelFileDescriptor 只有 open/getFileDescriptor/close；PFD/AFD close 只关闭
  IoRuntime 登记的描述符，裸 fd 会泄漏；Posix close/fstat/lseek/read 对裸 int fd 抛 EBADF，
  dup/fcntl 未实现；AFD.close 未按 ROM 委托 `mFd.close()`。

## 范围

1. **IoRuntime 裸 fd 接管**：未登记且 `descriptor>=0` 的 FileDescriptor 在 Posix 入口惰性接管为
   VFS handle（不复制、不改 offset）；Posix close/dup/fstat/lseek/read 及 PFD 所需 fcntl 选择子
   支持裸 fd。GC sweep 不关闭 fd（Java FileDescriptor 语义）。
2. **ROM ParcelFileDescriptor 撤换**：BootDex 加入原版类、删除手写声明；Parcel 的
   openFileDescriptor/dupFileDescriptor/clearFileDescriptor 经 VFS 实现；宿主构造 PFD 的位置
   改经 ROM 构造器与方法，不再按 slot 读写；AssetFileDescriptor.close/getFileDescriptor 经 ROM PFD 虚派。
3. **媒体来源**：有真实 handle 的已登记描述符同样走 handle 租约；平台 `apk_entry` 描述符保持原路径。

## 不做

pipe/createPipe/createReliablePipe、socketpair/fromSocket/fromDatagramSocket、Parcel 写入/读取 fd
（nativeWrite/ReadFileDescriptor）、跨进程 comm 通道、AssetFileDescriptor ROM 撤换、
`System.runFinalizersOnExit`、视频 Surface/合成的后续缺口。以上保持记账并明确失败。

## 验收

- 定向回归（放入现有主题 `file_media_descriptors_tests.cpp`、`file_vfs_tests.cpp`、
  `file_assets_resources_tests.cpp`）：adoptFd→AFD→setDataSource→close 后 VFS fd 恰好关闭一次且
  租约仍可播放；fromFd/dup 产生独立 fd 并共享 offset；getFd/detachFd 后 close 不关闭已分离 fd；
  Posix 对裸 fd 的 close/fstat/lseek/read；PFD.open 模式按 ROM；不支持项明确失败。
- compose_bootdex build/check、closure 0 缺口、framework_contract 基线只降不升、
  dalvik/JNI 零回归、capabilities check。
- 原 APK 复现一次（编排方在沙盒外执行）：`adoptFd` 未实现消失，记录 sg_video 是否出画及下一首错。

### fcntl 逐项依据

AOSP `IoUtils.java:89–100` 的 setBlocking 只调用 F_GETFL(3) 和 F_SETFL(4)。
PFD 的使用点为 open(..., Handler, OnCloseListener):238 与 createCommSocketPair:437–438；
后两条涉及 comm/socket 的实际创建仍在既有未实现入口失败，本单不提供通道。

- fcntlVoid/F_GETFL：从 VFS DescriptorStatus 返回真实 guest Linux 状态位。
- fcntlLong/F_SETFL：仅接受与当前状态完全相同的参数，正常返回 0；
  这是实际状态未变的确认，不伪造可变 VFS 状态。改变 O_NONBLOCK/append 等及其他 selector
  均记账并抛 ErrnoException(ENOSYS)，回归确认失败后状态不变。
- F_DUPFD、FD_CLOEXEC、锁等无支持路径依据，继续未实现；dup 仅走 VFS Duplicate。

### 原断言调整及 AOSP 依据

1. AssetManager.openFd 的平台 apk_entry 没有真实 fd：原 valid()==true 改为 false，
   增加 getInt$()==-1。依据原版 FileDescriptor 的 descriptor 初始化 -1 及 valid()，
   不再将 NewIntrinsicInstance 的默认零冒充有效 fd；APK 来源/长度/偏移断言全部保留。
2. MediaPlayer 的 PFD.open 来源现持有真实 VFS handle，name 改验 `/proc/self/fd/N`，
   全文件 length 从未裁剪 sentinel 改验实际字节数。依据既有
   CaptureDescriptorAudioWindow 的 API19 jniGetFDFromFileDescriptor/文件尾裁剪语义；
   原区间、解码和非零 PCM 断言保留。
3. core_catalog 三个旧白名单成员随本单真实 native 实现移除，未放宽其他未实现成员检查。
4. FileVm 的成员来源表修复不是减弱断言：旧实现也用相同修复重建并重跑了基点。
   fromSocket 用生产 skeleton 回退验证真实记账，不能以 NoSuchMethodError 代替未实现证据。

PFD detach 行为未改 ROM：AOSP ParcelFileDescriptor.java:579–590 仅 clear fd，
随后 close():635–643 设置 mClosed；回归既验 detach 后 int=-1，也验 close 后 getFd 的 ISE。
