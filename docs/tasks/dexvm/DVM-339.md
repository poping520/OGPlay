# DVM-339：托管 SurfaceView 独立 buffer 尺寸

状态：有界完成；原 APK 外验发现的跨线程回归已返修，下一首错为视频 start 的 setKeepScreenOn。
类型：新能力（既有 Surface 生命周期/显式 boundary hooks 的扩充）。不提交，不启动完整 APK。
前置：[DVM-338](DVM-338.md)、[DVM-235](DVM-235.md)、[DVM-309](DVM-309.md)、[DVM-249](DVM-249.md)。
证据目录：`.local/analysis/dvm-339/`。不改 BootDex 配方、DEX 索引政策或 DVM-338 实现。

## 触发与根因

编排方原 APK 日志 `.local/analysis/dvm-338/apk-repro-1.log`：adoptFd 缺口消失，
MediaPlayer 发视频尺寸事件，应用调用 setFixedSize(480,320)，原实现将其与窗口 800×480
比较并明确失败，最终 scheduled callback fault。主 GL 窗口也在创建前请求 fixed buffer。
只取消 holder 拒绝会把失败挪到 EGL/呈现，必须贯通 Canvas、MediaPlayer、NDK/EGL。

## AOSP 4.4 语义对照

使用本地固定 AOSP 源码，无外部网页或新系统依赖：

- `framework/base/core/java/android/view/SurfaceView.java:432–465`：updateWindow 分别取
  mRequestedWidth/Height，非正轴回到 getWidth/Height；buffer myWidth/myHeight 与窗口
  mLayout.width/height 分开。727–742 的两个 setter 仅保存请求并 requestLayout。
- 同文件 529–586：在回调前设置 mSurfaceFrame，先 created，再 changed(format,myWidth,myHeight)；
  同尺寸不重复派发，固定请求发生在激活前也会成为初始 buffer 几何。
- **修正提示词的 Rect 判据**：529–544 的 mSurfaceFrame 取 mWinFrame.width/height；
  WindowManagerService.java:3025 返回 win.mCompatFrame，WindowState.java:481–497 的 FLAG_SCALED
  分支按 mAttrs.width/height（View 尺寸）布局。故 4.4 getSurfaceFrame 是窗口 frame，
  不强行改成 buffer 尺寸。View 为 64×32、buffer 为 480×320 时，Rect=64×32、
  changed=480×320、Canvas/NDK/EGL=480×320；以此替换原 getSurfaceFrame=480×320 判据。
- **修正提示词中的绝对表述**：281–285 的 ROM onMeasure 本身读取 fixed 请求并交给
  resolveSizeAndState。保留原版算法；不承诺所有 MeasureSpec 下 fixed 请求都不影响测量。
  EXACTLY 下 View frame 仍由父约束决定，buffer 可独立，游戏自定义 onMeasure 不替换。
- `framework/native/libs/gui/Surface.cpp:575–635`：buffer dimensions 与 scaling mode 分开；
  `framework/native/services/surfaceflinger/Layer.cpp:579、1104–1111` 消费缩放与 buffer 事实。
  进程内只实现等效 buffer→frame 合成，不引入 SurfaceFlinger/WMS/Binder/system_server。
- `framework/base/media/java/android/media/MediaPlayer.java:680、2239`：setDisplay 绑定 holder，
  MEDIA_SET_VIDEO_SIZE 经原版 EventHandler 调用 Java listener；事件、prepared 与 play 协议保留。
- `framework/native/libs/gui/Surface.cpp` 的 dequeue/queue 路径：新的 buffer 尺寸在下次 dequeue
  可见。当前 EGL 模型用 swap 末尾重新分配/绑定下一 backing；不谎报已经改变的旧 current buffer。

## 三类 producer 与实现边界

1. **holder / Canvas**：Java requested 字段仍是唯一请求来源。正轴独立，非正轴规范为 −1；
   每轴最多 4096，RGBA backing 最多 64 MiB，双轴验证先于状态写入。window holder 保持原边界。
   owner 安全点读取 buffer 尺寸，回调/NDK 注册使用同一 buffer 尺寸，稳定 Rect 按上述 AOSP 窗口 frame；同值去重，创建前请求生效。
   Canvas 的 backing、getWidth/Height、clip 和 dirty 使用 buffer 尺寸；当前每次完整重绘，
   dirty Rect 如非空扩展为全 buffer，符合 lockCanvas 可扩展 dirty 的语义。
   post 冻结 holder 像素，按 View frame 最近邻缩放；window holder 仍发布原软件基帧。
2. **MediaPlayer**：保留原版 size 事件、setDisplay 和 surfaceChanged 后 start 的链路。
   冻结呈现时先将解码帧按比例适配到已交付的 holder buffer，再把 buffer 缩放到 View frame；
   buffer 与源同尺寸不做多余缩放。VideoView 自身仍保留原 letterbox 行为。
3. **NDK/EGL**：ANativeWindow getter 读取最新 holder buffer；Java EGL holder token 与 fromSurface
   的 opaque window 使用同源几何。eglCreateWindowSurface 按 buffer 建真实 backing，
   eglQuerySurface 读取该 backing 的实际尺寸。已有 surface 在下一 swap 先发布旧 buffer，
   再分配并绑定新 backing；成功后 query 才更新，GL viewport 由 guest 自己维护。
   真实 ANGLE 分配/绑定错误继续返回真实 EGL 失败；实际 GPU 路径留外验，不声明已通过。
   ANativeWindow_setBuffersGeometry 没有扩充：只接受 reset/当前尺寸与既有格式。

alpha、media/overlay/onTop 层序、View hierarchy 与输入坐标链不改；共用既有最近邻合成采样。
EGL worker 经显式 hook 交纯像素，不获取 VM 锁，不保存 Java 引用；native 退役与发布串行。
owner 冻结像素及几何后，呈现线程只读取共同快照；销毁/移除清除 holder 像素。
未知/失效 holder、超预算请求、retired native window 继续明确失败；不新增系统级窗口能力。

## 原断言调整及依据

- `DVM-302 SurfaceView managed fixed rejection is atomic and requestLayout is real` 保留原测试名：
  原 320×241 / 321×240 / 0×241 三个“独立几何必失败”输入，改为 320×4097 / 4097×240 /
  0×4097 三个超预算输入；期待 IAE，仍逐 slot 验证请求原子性、Rect 身份与投影不变。
  AOSP updateWindow 支持独立正请求；4096 是本兼容层明确预算，不能继续断言合法独立尺寸失败。
  原 ledger 非空断言改为空：预算 IAE 是已实现校验，并非未实现能力。
- 原测量、生命周期、层序与失败断言均保留；不放宽已有错误，不删除/跳过既有 CPU 用例。
- 新回归独立检查未知 holder 的明确失败与 dexvm.surface_buffer_geometry 记账；支持路径先验
  ledger 为空，再运行该负向路径，不能用负向命中掩盖正向未实现。
- Canvas clip 原实现按 Rect 原始 slot 顺序写值，在 ROM 字段布局下错误；改用真实 Rect.set。
  该调整属于本单 buffer clip 判据的必要依赖。

## 自行决定事项

以下均为**实施方按编排方常设原则决定，待编排方复核**：

1. 保留 ROM onMeasure 对 fixed 请求的原版处理，并按 AOSP 4.4 的窗口 frame 返回 Rect；
   修正提示词中的测量绝对表述及 getSurfaceFrame=buffer 判据。
2. 统一采用每轴 4096 的软件预算（单 RGBA buffer ≤64 MiB）；真实 GPU 更低上限由实际
   ANGLE 创建/绑定失败报告。没有放宽未实现政策。
3. Canvas 每次完整重绘并扩展 dirty 至全 buffer；托管 EGL 用同步读回传递 buffer 像素，
   沿既有最近邻合成。系统 SurfaceFlinger、额外线程服务、跨模块反向依赖均不引入。
4. EGL resize 在 swap 发布旧 buffer 后分配下一 backing，query 只报告已分配尺寸；
   分配/绑定失败明确失败。GPU 像素/resize 判据保留给编排方外验，不用 CPU 查询冒充 GPU 验收。

## 编排方原 APK 外验与返修（2026-10-28）

外验（`.local/analysis/dvm-339/apk-verify-{1,2,3}.log`）：启动后 presentedFrame 停在 2，画面为闪屏加
“Not enough disk space free on this drive.”，点击 OK 无变化。诊断快照 GLES 只到 eglChooseConfig，
无 window surface/swap；lldb 断在 `NativeApiException`，来源为 `ANativeWindow_fromSurface` →
`SurfaceFromJava`，消息 `default guest execution is bound to another host thread`。

根因：`ManagedSurfaceBufferSize` 用 `CallAndroidMethod` 执行 View.getWidth/getHeight。NDK 生产线程
没有活动执行上下文，借用了已绑定 owner 宿主线程的默认执行，抛错后被转为 IAE，fromSurface 返回 null，
native 无法建 EGL window，改走通用错误提示并等待；holder 永无像素，按既有门控不出新帧，故 OK 无反应。
原 NDK 用例用模拟 hook、主线程调用，未覆盖该路径。

返修：`android_view.cpp` 新增 `ViewFrameSize`，按 ROM final getWidth/getHeight 的定义直接读
mLeft/mTop/mRight/mBottom，不进解释器；`ManagedSurfaceBufferSize` 与 `PublishSurfaceHolderFrame`
共用。Java 工作线程上的 lockCanvas 本有活动执行上下文，不受影响；呈现门控未改。
