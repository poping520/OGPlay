# DVM-347 · Canvas 纯色 PorterDuff 与 holder 格式 alpha

状态：实现与本次验证完成；下一首错及视频像素验收缺口保留。依赖：DVM-339、DVM-345。证据：`.local/gta3-canvas-color/`。

范围：Canvas 纯色18模式与 drawColor 默认 SRC_OVER、drawARGB/drawRGB、null Mode NPE；
holder 格式请求/active 生命周期、确定缓冲区初值与快照像素 alpha 合成。保留层序、出帧判定和视频解码。
纯色填充不受 clip 约束；clipRect/save/restore 仍未实现。具体格式为 RGBA8888/RGBX8888/RGB888/RGB565/RGBA5551/RGBA4444，
加三个透明度选择值；其他格式记账抛 IAE；使用 RGBA8 精度，不模拟 packed 存储或低位深量化。

公式来源：AOSP android-4.4_r1 `external/skia/src/core/SkXfermode.cpp`、`include/core/SkColorPriv.h`。
原文件下载到证据目录；固定期望值由其 modeproc 独立执行生成。API19 MULTIPLY 对应 MODULATE。
CanvasState 使用非预乘 ARGB，混合前预乘，混合后反预乘并取整；不是引入完整 Skia。

验收：macOS Release CLI/tests；双解释器定向与相邻 Canvas/surface/dialog/video，历史失败对照；
九基础场景各一次（基线6/9）；GTA3 原命令/cwd/临时MCP并精确恢复，原错消失及下一首错；
影片启动时截图。结束全文件clang-format本次C/C++、刷新审计元数据、重建并重跑定向。不提交、不跑全量。


## 实现与阶段验证

- 18模式使用Skia4.4预乘字节运算；MULTIPLY为MODULATE，保留SRC_OVER的256缩放取整。
  五组固定原始Skia oracle覆盖半透明、透明、全不透明、极低alpha及OVERLAY分支。
  drawColor(int)/drawARGB验证默认SRC_OVER，drawRGB与null Mode受检。
- holder请求与active格式分开，created/changed应用，格式相同且尺寸不变才去重；销毁保留请求，
  真正holder退役/GC清除。快照冻结alpha事实，alpha变化进入呈现去重；透明像素不能走不透明行复制捷径。
  新测试覆盖两次Surface生命周期、同尺寸格式改变、完整透明层保持下层逐字节相同、部分alpha与View alpha、
  OPAQUE clear合成黑色及非法格式拒绝/记账。DVM-345 queue事实、解码与层序未改。
- 初轮九场景发现Wild Blood原路径setFormat(4)被过窄的支持集合拒绝；证据保留于
  `scenarios-canvas-color/wild_blood/`，不作为最终验收。核对原APK源码后补齐通用RGB565、
  RGBA5551、RGBA4444的RGBA8表示，没有title分支；不模拟packed存储/低位深量化。
- 初轮相邻192项（172+20）共24项失败、58条失败断言，逐项对照
  `.local/locale-rom-java/frozen-failed-cases.xml` 的用例、表达式、展开值和异常首行一致；
  仅归一化非空宿主指针。见`adjacent-comparison.json`。最终版本复验另记录。
- 12个本次改动C/C++文件均执行全文件clang-format -i，dry-run检查通过；
  `format-final-files.json`记录最终文件清单与前后SHA。BootDex仅刷新宿主审计配对元数据，未改配方或Java算法。
