## 范围与事实来源

固定 API19 ROM shape/方法清单见 `tools/bootdex/view-surface-sources.json`；语义核对本地
`.local/aosp/framework/base/core/java/android/view/SurfaceView.java`（setVisibility、updateWindow）。
父 View 的可见性和布局算法仍由 ROM Java 执行；窗口可见性复用 View.getWindowVisibility
背后的现有 owner/window 事实，不建立第二套窗口状态。mWindowVisibility/mViewVisibility/
mRequestedVisible 是派生的 ROM 字段；owner 对账刷新，setVisibility 先精确调用 View vtable。

## 重写及公开控制入口清点

| ROM 入口 | 本次处理及支持边界 |
| --- | --- |
| 三个构造器、getHolder | 保留现有 View 初始化、−1 请求和稳定 holder；不提前创建 Surface |
| onMeasure、isFixedSize | 保留原版 Java；已有双解释器尺寸/测量矩阵覆盖 |
| setVisibility | 新增精确 View 父调用；刷新 visibility/requested；requested 改变时 requestLayout，标记既有对账 |
| onWindowVisibilityChanged | 保留 View 父调用，补窗口事件可见性与同一 holder 对账 |
| setFrame | 保留精确 View 父调用和原返回值；尺寸效果仍由现有 owner 对账完成 |
| onAttachedToWindow | 复用 managed attach/observer 合并、刷新可见性并排队对账；不伪造 AttachInfo/WMS session/token/listener |
| onDetachedFromWindow | requested=false，经现有事务退役；不伪造 View AttachInfo/系统 session 清理 |
| draw、dispatchDraw | 委托 View vtable；开孔由既有 compositor 完成。当前父 View 两方法仍为 failure，调用先记账，再传播真实父异常；没有宣称 Java Canvas 绘制可用 |
| gatherTransparentRegion | media/overlay、willNotDraw=true、region=null 时按 requested format 的 alpha 返回 opaque；非空 Region、自绘或 onTop 所需的 Region/父 View gathering 尚不存在，记账抛 UOE |
| setZOrderOnTop、setZOrderMediaOverlay | 保留既有 UiTree 层序，无 WMS 窗口重建 |
| setWindowType | 1000 PANEL、1001 MEDIA、1004 MEDIA_OVERLAY 映射既有层序；其他类型记账抛 UOE |
| setSecure | false 不请求保护；true 所需安全显示/截屏排除尚不存在，记账抛 UOE |
| updateWindow、handleGetNewSurface、getSurfaceCallbacks、init、access$000 | 私有/内部 WMS 及匿名 holder 路径保留 failure；不进入系统窗口生命周期。公共生命周期使用既有 managed 事务 |

透明度查询使用既有 managed 请求格式（未显式请求时沿用 RGBA_8888），不改变既有 producer 的默认格式；ROM 原构造默认 RGB_565 的差异保留。

新接缝的缺失能力统一记入 `dexvm.surface_view_lifecycle`。不更改 GLSurfaceView、VideoView
自己的重写；核对继承 setVisibility 的 vtable 仍指向 SurfaceView，邻接测试检查现有行为。

## 时机和 ROM 差异

- 普通 owner setVisibility 隐藏时，返回前仅对该 holder 调用 DispatchHolderCallbacks(destroyed)。
  不调用全树 Pump，不提前为其他 holder 创建。DestroyScope 保留回调期间 Surface 有效、回调后
  native 退役顺序；DVM-345 queue/pixels、DVM-347 active/callback format 清理完全复用。
- 重新显示只排队；下一 owner 安全点刷新投影后依次 created、changed，同值不重复。
- Surface 回调、Java layout、输入 presentation lease 或非 owner 执行上下文中不重入同步销毁，
  延后到下一 owner 安全点；与 ROM updateWindow 的同步销毁时机存在这一明确差异。
  created 回调中隐藏会使随后 changed 的 current 检查失效，下个安全点再销毁。
- ROM requested 仅为 mWindowVisibility && mViewVisibility。SurfaceOwnerCurrent 另要求发布投影
  IsVisible（包含祖先）、owner/root/generation/mount 一致；created 也检查 live UiTree.IsVisible。
  因而祖先隐藏仍销毁 holder，即便 View 自身仍 VISIBLE；祖先重新显示再创建。保留既有规则。
- 有界 attach/detach 接缝不引入完整 dispatchAttachedToWindow、View AttachInfo 或 WMS；实际挂载
  权威仍为既有 mount/window 对账，不以调用一个 callback 冒充真正挂载/拆卸。
