# DVM-349 · 独立进程 Service 按不可解析回答

状态：实现完成，验证结果见下。依赖：[DVM-202](DVM-202.md)。
范围决定：[ADR-0170](../../adr/runtime.md#adr-0170)。
证据：`.local/dvm349-secondary-process/`；场景证据 `.local/evidence/dvm349-{wild-blood,dead-trigger}/`。

## 范围与 AOSP 判据

仅当前包显式、应用及声明均启用的 Service：process 与应用默认进程不同或
FLAG_ISOLATED_PROCESS（0x0002）时，startService 返回 null、bindService 返回 false。
共用清单解析，后项声明优先，应用未指定 process 时取包名。bind 先完成既有目标校验，
不可托管判定早于主线程/BIND_AUTO_CREATE 校验；仍先登记 connection，解绑正常移除。
无构造、生命周期或连接/断开回调，每次命中记账 dexvm.service_resolution，
结构化 warn runtime.service.secondary_process 带 api/component/process，first_and_count 限流。
PackageManager 保留清单事实；不改变其他组件，不新增 quirk，不实现同进程 started 生命周期。

AOSP 4.4.4 本地源码 `framework/base/services/java/com/android/server/am/ActiveServices.java`：
startServiceLocked 第 299–301 行与 bindServiceLocked 第 691–694 行，
retrieveServiceLocked 返回 null 后分别返回 null、0。只沿该失败通道回答，不实现 AMS。
