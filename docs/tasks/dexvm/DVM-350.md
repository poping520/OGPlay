# DVM-350 · ZipFile 读取 guest VFS ZIP32

状态：实现、macOS ZIP 定向验证与首启 reached-fault 完成；扩展回归仍有非 ZIP 失败。
证据在 `.local/dvm350-zipfile/`。

范围：ROM ZipFile(File/String) 的 entries/getEntry/size/getInputStream/close，stored/deflated
条目及 CloseGuard 既有行为；ZipEntry、ZipInputStream 整体撤换为固定 API19 ROM。
不支持 ZIP64、OPEN_DELETE、JarFile 签名校验或宿主路径，不扩展原版异常边界。

## 准入及状态所有权

以当前 CLI dump-surface 为输入，`select_rom_java.py --replace-intrinsic` 两类联合准入通过；
配方只增加两类，无新增 native。ModifiedUtf8、PushbackInputStream、JarEntry、Attributes
已在配方中；Memory.peekInt/peekShort(byte[], int, ByteOrder) 已覆盖，无需补实现。
删除手写声明、ZipRuntime helper 和普通方法 overlay；Java entry/stream 状态全部归 ROM。
准入报告：`admission.json`，输入：`surface.json`。

## 文件输入判据

对照 `.local/aosp/libcore/luni/src/main/native/java_util_zip_Inflater.cpp`：seek 到指定 offset，
循环读满或 EOF，返回实际字节数。FileDescriptor 的 descriptor 字段只作平台句柄事实，
复用 Posix 的 IoRuntime.ResolveDescriptor/SetFileOffset/ReadFileStream，不建立新 fd 表。
与现有 Posix read/lseek 一致，采用同步 IoRuntime 调用约定，无额外 VM 锁协议。
读取后经 VM 调用接收者 private native setInputImpl，guest zlib 独占 token 状态。
无效/关闭 fd 与 seek/read 错误转 IOException，消息含 errno；负 byteCount 抛 IAE。

核对 DVM-214 当前源码：输入快照没有独立固定字节上限，使用 jint 长度和 Java byte[] 的
VM heap 上限；本实现先分配受同一堆预算约束的 byte[]，再分配宿主临时快照，不另创限制。
AOSP 短读仍设置 avail_in=len；这里仅传实际读取数，避免旧尾部参与解压。
合法 deflate 流包含完整压缩字节，不依赖 EOF 后旧数据，因此不受影响。

DVM-214 的原 FD UOE 断言改为 null FD 的 NPE；ZipInputStream 既有断言保留。
