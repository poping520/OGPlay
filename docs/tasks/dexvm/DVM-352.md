## ROM 准入与 AOSP 判据

View 的 setBackgroundColor(I)V、invalidateDrawable(Drawable)V、verifyDrawable(Drawable)Z
加入 view-measure-sources 的 rom_methods；保留固定 API19 ROM 字节码、flags 与 hash。
首次组合 build 通过，未新增 native/handler，未变更子类 verifyDrawable 来源或准入规则。
开放世界虚派仍按 ADR-0158/0159 封存，failure 目标真实执行时失败。

AOSP View.java：首次背景构造 ColorDrawable；再次设色 mutate().setColor() 并清资源 ID。
invalidateDrawable 通过 verifyDrawable 检查背景身份，按 bounds + scroll 调 invalidate(IIII)。
ColorDrawable.setColor 与 Drawable.setVisible 的 invalidateSelf 通过真实 Java callback 回调。

## 实际前提差异

- view-leaf-resources-sources.json 的 ColorDrawable 构造、getColor/setColor/getOpacity 仍为
  overlay，mutate 为 failure，mState/mPaint/mMutated 为 failure 字段。class_additions
  只保证进入组合输入，不能推导为整类执行 ROM。首次 DVM-352 动态回归在第二次设色命中
  `ColorDrawable.mutate()` 未实现；这也说明原有 setColor overlay 不会触发失效回调。
- UiNode.background_color 与 DrawSolidRect 使用 RGBA，ui_renderer 按最低字节读取 alpha。
  请求的 ARGB 直接写入会导致黑色透明、半透明红色变色；需要边界转换后才能正确绘制。
- DVM-329 bringToFront、DVM-285 旧夹具直接写宿主背景、Java background 为 null；正确的
  null 清理会清除该测试注入。它们需要迁到 Java setter，并保持原像素断言。

## 投影规则（实现中）

owner 屏障读取 Java 背景，保留 ROM skin 的叶 bitmap/alpha。
ColorDrawable（含子类）每次虚派 getColor，不缓存；颜色 alpha 为零/null 清空；
background_resource_id 清零、background_alpha=1，避免旧颜色或重复 alpha。
其他非空 Drawable 不绘制、不抛异常，RecordUnimplemented("dexvm.view_background_draw")；
事件 ui.background.unreviewed 为 warn，携 drawable 类描述符，以 first_and_count 限流。
标脏沿既有 ROM setter/callback → invalidate，不新增协议。
