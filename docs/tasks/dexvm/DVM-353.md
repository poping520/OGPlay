# DVM-353 · 生命周期停摆期间统一时钟按真实流速推进

状态：实现及定向验证完成。决策：[ADR-0171](../../adr/runtime.md#adr-0171)。
证据：`.local/dvm353-clock-pacing/`。

## 根因与范围

既有插桩：watchdog ctx=6 sleep 10000，now=62000；主线程进入 HAL native main 后，
watchdog advance 10000，约 2 ms 后触发 Pattern.finalize 超时并 exit(2)。
root 限时等待和 SystemClock.sleep 直接补到 deadline 存在相同问题。
现以同一 blocking observer 跟踪生命周期停摆，并转发原 EGL driver-blocked 行为；
注入 RealtimeClock 毫秒源，所有等待者串行收敛到起点 uptime 加真实流逝时间。
SystemClock.sleep 循环 ThreadRuntime.Sleep 并恢复被吞掉的 interrupt。

## 改写既有用例

- vm_monitor_tests：root timed wait、worker blocked-driver wait 改用假真实时间逐轮补时。
- thread_intrinsic_tests：root parkFor 纳秒向上取整、root Thread.sleep、root timed join、
  worker blocked-driver sleep 改用假真实时间；保留非停摆 worker 不补时检查。
- unsafe_tests：原有 Unsafe park 使用注入假真实时间，仍覆盖许可、中断与超时。
- 新增双后端：并发等待者不叠加/恢复停止补时；ROM Daemons 3 秒不误报、10 秒真实超时
  仍 exit(2)；Runtime.exit hook 的 SystemClock.sleep 3 秒仍等待、10 秒完成。
