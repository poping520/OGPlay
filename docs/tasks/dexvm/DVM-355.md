## 最终实施

同 ROM edit_text 闭包加四个确切 scrollbar thumb，名称/ID 双重校验、单一 .9.png 叶子，
配置、SDK、PNG/npTc 过滤不变；仍沿 Resources.loadDrawable→MakeRomSkin→NinePatchDrawable。
没有 accelerated_anim2 或其他新皮肤，也不从 APK 同名资源兜底。

| thumb | ID | ROM 原尺寸 / 密度 | 设备160 / 240 / 320下固有尺寸 |
| --- | --- | --- | --- |
| scrollbar_handle_horizontal | 0x0108052a | 37×13 / 320 | 19×7 / 28×10 / 37×13 |
| scrollbar_handle_vertical | 0x0108052b | 13×37 / 320 | 7×19 / 10×28 / 13×37 |
| scrollbar_handle_holo_dark | 0x01080528 | 30×30 / 480 | 10×10 / 15×15 / 20×20 |
| scrollbar_handle_holo_light | 0x01080529 | 30×30 / 480 | 10×10 / 15×15 / 20×20 |

两后端测试实际加载并检查类、资源 ID、固有尺寸和像素尺寸。未封存的
scrollbar_handle_accelerated_anim2（0x01080527）与 btn_default 在 loadDrawable 接缝抛出
`unreviewed ROM drawable load` 并记账；前者未被主题需求投影，外层 getDrawable 会更早拒绝身份，
因此负例直接给加载接缝传入 ROM 真实 ID，而未修改主题或发放资源支持信用。

原始缺口证据保留：[audit.py](../../../.local/dvm355-scrollbars/audit.py)、
[audit.json](../../../.local/dvm355-scrollbars/audit.json)；它们描述修改前制品，不作当前通过入口。
当前封存与停止审计见 [current-audit.json](../../../.local/dvm355-scrollbars/current-audit.json)。
生产 JAR/主题投影与 manifest 同封存；当前配方由 build/check 验证。

View.initializeScrollbars/initScrollCache/resolvePadding、mScrollCache、完整 ScrollabilityCache、
ScrollBarDrawable 状态、ViewConfiguration/get/getters/构造器均执行固定 ROM；Display.getRealSize
从现有显示配置填入真实 Point。ScrollView/HorizontalScrollView 的 init/touch/fling overlay 不变，
initializeFadingEdge、ScrollBarDrawable 的像素 draw 仍 failure。

internalSetPadding/setPadding 改为 ROM，删除旧 overlay 和 dexvm.view_measure_scrollbar_padding 记账。
setPadding 仅维护 user/resolved padding 并转调 internalSetPadding；真实 flags、scrollbar 厚度、
RTL、mPrivateFlags2 和 ApplicationInfo.targetSdkVersion 决定 inset，不硬编码 LTR。
只有实际 padding 变化才 requestLayout，mUserPadding 保留未加偏移的输入。
getLayoutDirection/isLayoutRtl、两轴 scrollbar 尺寸 getter 及依赖按严格组合审计补 ROM。
selector 修正 iget/sget 覆写目标寄存器后残留 new-instance 类型的分析错误，新增精确回归；
未降低依赖、字段、clinit、native、overlay 规则，详见 selector-selftest-final.log。

固定 framework.jar 的 sHasPermanentMenuKey* 是 private 实例字段，静态写入违反 ROM 形状。
constructor_inputs 在原 Context 构造器进入 ROM 前，只写这两个字段并置 Set=true：
Resources.getInteger(0x010e0049) 为1/2直接决定；其余值读 Resources.getBoolean(0x01110044)，
经现有 SystemProperties.get(qemu.hw.mainkeys) 的1/0覆盖后取反。异常透传；不改 flags、
构造器本体、设备快照，也不创建 Binder/WMS 代理，ADR-0111 不变。
固定 APK 的 ARSC showNavigationBar=0xffffffff（true）、override=0、mainkeys 为空，故默认永久菜单键=false。
原预期 true 来自源码 config.xml 基础值，未考虑出厂 ROM overlay，已更正。

Interpolator 六个 native 维护真实关键帧、2.14 cubic、Result、repeat/mirror/reset；仅取参数时间。
LinearGradient/Shader、PorterDuffXfermode/Xfermode 以强类型句柄保存真实参数；Paint 原 Java
mShader/mXfermode 引用参与 GC，finalize/sweep 释放对象状态。含这些状态进入已支持 Canvas 绘制
在修改像素前记账 dexvm.canvas_draw 并抛异常；其他绘制入口保持原失败边界。
可见 scrollbar 投影只记 dexvm.view_scrollbar_draw，不抛异常、不改像素。
ROM awaken 和 cache.run 使用 Handler/统一时钟；无 AttachInfo 的 managed 窗口在实际投影时
将 ROM fade deadline 转发至既有 ViewRoot Handler runnable 队列，不伪造 AttachInfo；FADING 采样遵循 ROM 插值状态。
绘制测试显式 invalidate 请求绘制屏障，原 ROM postInvalidateOnAnimation 在无 AttachInfo 时不调度。

## 真实 reached-fault 与已知差异

GTASA 原命令一次，180秒 subprocess 上限；实际5.10秒退出1，无残留进程组、不清沙盒。
closure-gtasa-console.log 与 closure-gtasa-current.log 只记录本次（库 last-run.log 为追加日志，
完整副本保存在 closure-gtasa-last-run.log）。initializeScrollbars 原错不再出现；下一首错为
RectF.set(RectF)，调用点 ContainerLayout.updateLayoutParams pc12，andView.createView 已到pc27。
记录到1个呈现计时样本，median=7.200750ms；不足以证明游戏帧或稳定 FPS，不把前端f125当作呈现数。
后续 null andView/JNI无效引用是连锁错误，不作为下一独立首错。
已知差异登记但不修：有导航栏时 Display.getSize 应扣除导航栏而小于 getRealSize；
OGPlay 当前两者均返回完整显示尺寸，本单不改显示尺寸。

DVM-280/283/290/300/301/330 像素夹具原先直接写宿主 background_color，被 DVM-352 Java
背景投影清空；改为 Java setBackgroundColor，原逐像素、hit、measure/layout 判据保留。
DVM-283 未支持容器负例移除早已由 DVM-351 准入的 AbsoluteLayout；不改 padding 期望，
其正向构造/测量/布局仍由 DVM-351 验证。AOSP AbsoluteLayout.java:42 的 Context 构造仅委托
super(context)，其 onMeasure/onLayout 已在 DVM-351 按 ROM 准入，旧拒绝预期与既有配方不符。
没有为了 ROM padding 修改既有回归期望。
