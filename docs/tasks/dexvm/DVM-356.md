# DVM-356 · RectF 整类回归 ROM 纯 Java 值语义

状态：实施、macOS 定向回归与 reached-fault 完成；Paint 主题保留一项既有失败。证据 `.local/dvm356-rectf/`。
依赖：[DVM-293](DVM-293.md)、[DVM-350](DVM-350.md)、[DVM-355](DVM-355.md)。

## 根因与范围

已复核 `RegisterBootDex` 的成员来源规则：failure 清空 implementation/code，故旧 catalog
中的 RectF handler 被遮蔽。实际固定清单为 RectF 40 方法，其中原来 2 rom、38 failure；
不是背景估计的 41 方法。ROM 实例字段为 bottom/left/right/top，旧 handler 的固定
slots[0..3] 假设 left/top/right/bottom 不成立，不能靠恢复 handler 修复。

沿 ADR-0154 的 `select_rom_java.py --replace-intrinsic` 入口做只读撤换审计，不 apply 整类配方。
默认 dump 已将 RectF 合并为 BootDex，不能直接作为 intrinsic 撤换输入；本地 C++ probe
用生产 BoundCoreIntrinsicCatalog/AndroidIntrinsicCatalog 导出合并前声明，再仅将真实
RectF 声明替换回完整生产 surface 供 selector 审计。未修改工具或放宽准入规则。
`admission.json` selected_classes 仅 RectF，retained_native_bindings 为空。
此入口检查整类替换/初始化闭包，普通方法的实际准入以 compose 全成员审计为准。

`view-paint-sources.json` 将 35 个 RectF 方法和 RectF$1 的两个 newArray 改为 rom。
覆盖三个有参构造、全部 set/几何查询/包含/相交/平移/合并/排序/round、相等/hash、
字符串/PrintWriter 输出和 describeContents；没有新增类、native、overlay 或外部依赖。
RectF 最终 37 rom/3 failure，RectF$1 为 3 rom/2 failure。
保留 readFromParcel、writeToParcel、两个 createFromParcel failure（不提供 Parcel 协议），
以及 roundOut failure（FloatMath native 未准入）；不引入 FloatMath。

## 旧声明与装配

删除 `Declare_android_graphics_RectF` 及 catalog.cpp/catalog.h 注册。
该类没有 overlay；生产 DexVmGuestBridge 先注册 catalog 再装载 BootDex 成员来源，
RectF 形状、字段、初始化与方法全部由 BootDex 装配。
测试中直接引用 RectF 的只有 paint_measure 与 android_resources_bitmap：前者 ContainerVm
加载 view-measure.jar，后者 AndroidValueVm 绑定生产归档并经 AndroidTestRuntime 装载 BootDex。
公共 RegisterBootDex、BootDexLibraryVm 和其他共享 Android 夹具也装载 BootDex；
没有发现调用 RectF 的无 BootDex 夹具或声明函数的直接调用。
`android_widget.cpp` 的 ImageView helper 只 EnsureClassInitialized、分配实例并调用 ()V 原构造，
不调用已删除声明，也不依赖字段顺序；无需修改。
MODULE 没有 RectF 专属旧契约，现有“普通 Java 字段/算法归 BootDex”仍准确。

## 被 failure 遮蔽的 C++ handler 只读盘点

以修改前生产 JAR 的全部 member-sources failure 行，与同一生产 catalog 的合并前方法
声明按 owner+完整签名求交，限定 implemented/intrinsic/handwritten（排除纯声明、
guest-native、rom 和 overlay）。原始清单 `shadowed-handlers-before.json`。
probe 不加载 BootDex，缺 Serializable 层级会产生 startup_link_error；本盘点只读注册完成的
自身方法表，不把该探针当作执行或链接通过证据。全配方逐类求交，不只搜索 RectF。

修改前共 **1 类、15 方法**，全部属于 `Landroid/graphics/RectF;`：

| 方法 | 方法 |
| --- | --- |
| `<init>(FFFF)V` | `<init>(Landroid/graphics/Rect;)V` |
| `<init>(Landroid/graphics/RectF;)V` | `centerX()F` |
| `centerY()F` | `contains(FF)Z` |
| `contains(FFFF)Z` | `contains(Landroid/graphics/RectF;)Z` |
| `height()F` | `isEmpty()Z` |
| `offset(FF)V` | `set(FFFF)V` |
| `set(Landroid/graphics/Rect;)V` | `set(Landroid/graphics/RectF;)V` |
| `width()F` | — |

本单删除这些旧实现后剩余 0 类/0 方法。Matrix 等 wrapper 虽可能间接调用 failure native，
但其本身 source=rom，不属于本盘点的“同签名 failure handler”交集；未扩大修复范围。

## GTASA reached-fault

原命令 `build/release/ogplay-cli library run com.rockstargames.gtasa` 一次，不清沙盒，
180 秒上限；实际 **4.41 秒退出 1**，未超时、无残留进程组。
累计 last-run.log 按运行前字节前缀截取，本次 `gtasa-current.log` 没有 RectF.set 原首错。

下一首错为 `Landroid/view/View;.postDelayed(Ljava/lang/Runnable;J)Z` 未实现，
直接调用点 **`Lcom/rockstargames/hal/andThread$DelayedNativeRunnable;.post pc9`**；
上层 andThread.runOnMainThread pc12、ActivityWrapper.runMain pc59。
后续 andScreen 初始化失败、null andView/JNI 无效引用是连锁错误，不作下一独立首错。
仅有 1 个呈现计时样本，不声称稳定 FPS 或完整布局挂屏；这次是 reached-fault，非游戏兼容验收。
证据 `gtasa-result.json`、`gtasa-console.log`、`gtasa-current.log`。
不修改 Matrix、PointF、Canvas；无全量测试、正式 title gate 或 Windows 验收。
