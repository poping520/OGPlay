# DVM-357 · 恢复 View.post/postDelayed（ADR-0162 回归）

状态：实施完成，验证结果见下。证据 `.local/dvm357/`。
依赖：[DVM-135](DVM-135.md)、[DVM-331](DVM-331.md)、[DVM-355](DVM-355.md)、[DVM-356](DVM-356.md)。

## 根因与改动

复核 `e5a210e1`：ADR-0162 删除 View 的两个 posting handler，但 JavaTraversal 配方既未选
ROM，也未登记 overlay，成员装配因此发布 failure。`PostViewRunnable`、单一 ViewRoot
Handler、pending 转入和 GC roots 尚在；DVM-135 旧测试在 FrameLayout 构造时因未绑定 owner
线程退出，未触及 post。scheduler 能力 note 仍沿用此前支持声明。

两个 public virtual 方法恢复为五项 review 齐全的 overlay，直接复用 `PostViewRunnable`。
API19 View.java 的 attached→Handler、detached→线程 RunQueue 协议在本项目对应既有
session scheduler/pending_view_actions：null Runnable 抛 NPE，负 delay 截为零，始终异步。
不创建 AttachInfo、ViewRootImpl、RunQueue、线程或 Timer。

原 FindViewUiNode/IsAttached 读取上次投影，不能识别首次投影后才加入 Java 父链的子容器。
将 observer/token 已有的 Java 父链窗口查询抽为 `ManagedViewWindowRoot`，posting 复用它：
须到达当前、Activity stack 或未移除 application window 的根，且窗口调度附着代次非零。
不读取投影几何或 parent。其他 observer/token 调用仅更名共享，判据未变。
`FlushPendingViewActions` 的窗口存在条件同样改用此查询，仍只转入当前 guest token 的
pending，延迟从转入时的统一 uptime 起算。生产生命周期先建立窗口遍历，再在 safe point 泵送。

pending/scheduled 仍由 `VisitAndroidSessionRoots` 保活，shutdown 仍清空两者，无新根表。
removeCallbacks、postOnAnimation、postInvalidateDelayed 均保持 failure。
MODULE 只补 posting 附着与转入契约；能力账本修正 note/验证入口。

构建审计还依赖固定 runtime surface。用新 catalog 的只读 probe 导出真实声明，只更新
最终有效的 `view-scrollbar.surface.json.gz` 中 View 的 post/postDelayed 两项，并同步引用
该快照的 scrollbar/paint 配方 SHA；不升级其他方法。生产 JAR/manifest 和测试 JAR
由既有 composer 生成。

## ADR-0162 删除项只读盘点

范围为该提交的 android_view.cpp（View/ViewGroup）、android_widget.cpp 和 support_ui.cpp。
将删除的逐签名注册（含构造/DirectMethod）与当前生产 member-sources 求交；另手工核对
TextView color_methods 动态注册及 support_ui 的投影/回调 helper。原始证据为
`removed-failure-candidates.json`、`deleted-view-lines.txt`、`deleted-widget-lines.txt`、`audit.py`。

## GTASA reached-fault

原命令 `build/release/ogplay-cli library run com.rockstargames.gtasa` 一次，180 秒上限，
不清沙盒；3.48 秒退出 1，无超时或残留进程组。日志按运行前字节前缀截取，
`gtasa-current.log` 不含原 postDelayed 未实现错误。

下一首错为 **`Landroid/view/InflateException;`**，消息为
`Binary XML file line #2: Error inflating class android.widget.LinearLayout`；
日志显示 cause 为 `Ljava/lang/reflect/InvocationTargetException;`，未展开更深 target，
不臆测具体未实现构造依赖。记录到的首个 framework 抛出位置为
**`Landroid/view/LayoutInflater;.createViewFromTag pc80`**，调用链（由内向外）：

`LayoutInflater.createViewFromTag pc80 → inflate pc270 → inflate pc12 → inflate pc3 →
andScreen.createLoadingScreen pc80 → ActivityWrapper.runMain pc59 → GTASA.AfterDownloadFunction pc109 →
WarMedia.localHasGameData pc29 → WarMedia.onCreate pc459 → GTASA.onCreate pc195`。

后续 andImageView 的 NoClassDefFoundError、JNI 无效对象是连锁错误，不作为独立问题修复。
证据 `gtasa-result.json`、`gtasa-console.log`、`gtasa-current.log`；仅 reached-fault，非兼容/FPS 验收。
