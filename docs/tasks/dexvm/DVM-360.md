# DVM-360 · Paint FILTER_BITMAP/DITHER 状态位

状态：实现、macOS 定向验证与 reached-fault 完成；Paint 全文件保留一项既有失败。未提交。证据 `.local/dvm360/`。
依赖：[DVM-293](DVM-293.md)、[DVM-355](DVM-355.md)、[DVM-356](DVM-356.md)、[DVM-359](DVM-359.md)。

## 根因与 flag 语义

GTASA PackedImage.<init> pc52 调用 Paint.setFilterBitmap(true)，成员来源为 failure，
抛 UnsatisfiedLinkError。Paint 是 ROM shape/clinit，ADR-0161 的每对象 PaintMeasureState
承载有界 flags；原校验仅接受 0x501。

共同校验改为 0x507：ANTI_ALIAS=0x01、FILTER_BITMAP=0x02、DITHER=0x04，
DEV_KERN_TEXT/EMBEDDED_BITMAP_TEXT=0x500。默认 flags=0x500；Paint(int) 按 API19
将输入与 0x500 合并，setFlags 则直接替换。其他位仍按 dexvm.paint_measure 记账并抛 UOE。
两个 native setter 改为具备五项 review/platform_seam 的 overlay，只设置或清除对应位，
复用 state() 的未构造 ISE 检查；没有新状态。isFilterBitmap/isDither 为原版 ROM final Java，
按 `(getFlags() & FLAG) != 0` 查询已有 overlay；compose 准入通过，无需查询 overlay。

本地 API19 Paint.java:637/651/746/759 与 core/jni/android/graphics/Paint.cpp:149..157
已复核。native filter setter 在该版本以 none/low filter level 表达开关，DITHER 为独立位。

## 绘制边界与无影响论证

现有接受 Paint 的 Canvas.drawBitmap(Bitmap,FF,Paint) 对有限坐标向下取整，随后按
source.width/height 逐像素复制至目标，越界裁剪；没有缩放、插值、颜色降精度或边缘覆盖。
因此 FILTER_BITMAP/DITHER/AA 位均不改变此整数对齐 1:1 拷贝的结果。
RequirePlainCanvasPaint 仍在改像素前拒绝 shader/xfermode。
MODULE 与 setter review 明确：将来新增缩放/采样绘制必须消费 FILTER_BITMAP，不得忽略。
