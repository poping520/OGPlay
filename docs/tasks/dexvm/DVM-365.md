# DVM-365 · ROM ProgressBar 与 WebView 构造配置

状态：实现、macOS 双后端定向、关闭反证、制品检查与 reached-fault 完成；未提交。证据 `.local/dvm365/`。
依赖：DVM-326/355/357/358/362/363/364、ADR-0174。
当前 ADR 文档无 ADR-0156 独立锚点；相同父成员准入规则见 ADR-0148。本单沿严格成员审计，不放宽规则。

## 准入与边界

ProgressBar 状态、构造、测量与刷新使用固定 ROM；没有宿主 progress/max 副本。
仅封存 progress_medium_white → spinner_white_48；AnimatedRotateDrawable 原版 inflate 与尺寸/状态，
Animatable.start/帧调度、guest onDraw 保持失败，不报告正在动画。
系统 anim 仅封存 linear_interpolator 原始 XML，沿 ADR-0174 身份/配置/引用/内容 SHA 校验。
未封存 horizontal/Small/Large 构造明确失败。必要父方法和拒绝接缝逐签名审计。

WebView 沿既有禁用加载、无历史模型保存 initial scale/wide viewport；前进永远不可用且无历史变更，
检查构造线程与存活状态。原版 API19 WebView.setInitialScale 只 checkThread 后原样转发 int，
没有 Java 范围异常；0 为自动尺度，保存请求不授予缩放渲染。
WebView 附着转发 ROM ViewGroup 父协议，不创建 AttachInfo/系统服务。

## 准入审计与实现细节

- ProgressBar 四构造、init、状态/钳制、refresh/doRefresh、RefreshProgressRunnable/post、
  测量、drawable state、附着/分离/可见性及 startAnimation/stopAnimation 执行固定 ROM。
  startAnimation 只设置待 onDraw 启动标志；AnimatedRotateDrawable.isRunning 始终为 false，
  实际 start/run/nextFrame 和 ProgressBar.onDraw 保持未准入。
- 默认 rotate/bitmap 以真实 XmlBlock.Parser 进入原 inflate；BitmapDrawable 原 BitmapState/Paint
  补齐 filter/anti-alias 与 bounds 所需纯 Java 方法。没有新增 native。
  任意嵌套 drawable XML、tileify 的 layer/clip/shape 与 AnimationDrawable 构造/setOneShot
  以逐签名受审失败接缝保留原 ROM 分支；AnimationDrawable 只获 ROM 形状及明确失败入口。
- 父 View 的 postInvalidate/延迟失效、分离清理/缓存清理/必要字段与纯 Java helper 按 ROM 准入。
  removeCallbacks 取消现有 Handler/当前 guest 线程待转移 Runnable；null 不取消其他 work。
  unscheduleDrawable 先经 ROM verifyDrawable，再取消既有 Runnable，不制造帧调度或 AttachInfo。
- 默认 medium-white、spinner bitmap 与 linear interpolator 各自封存，未知引用/损坏 XML
  的生成期反证见 seal-negatives.json；身份与内容信用分开，不扩大系统 XML 加载域。
- 构造阶段已逐项核对原 andWebViewImp：父构造、setId、client、三项 settings、initial scale、
  wide viewport。原覆写的 super 附着经 ROM ViewGroup/View；随后 loadUrl 仍服从既有禁用模型，
  null URL 保留 NPE，不伪造加载/完成回调。前进与后退共用空历史依据：没有成功加载或历史生产者。

## 验证

- ProgressBar 双后端覆盖四构造、默认字段/插值器、indeterminateOnly 的 ROM 语义、
  progress/max/secondary 钳制与增量；确定性地切换 ROM only-indeterminate 字段以覆盖 determinate
  分支，不以未封存 horizontal 样式获取支持信用。非 UI guest Thread 入队后，检查 refresh list/
  posted 字段，主 Looper pump 后列表与标志清空；null removeCallbacks 不取消刷新。
- AbsoluteLayout wrap_content 和 EXACTLY 投影、padding、反复 draw-dirty 后内容只记账一次；
  attach/detach/visibility 不启动伪动画；horizontal/Small/Large 与未封存系统 anim 明确失败。
  WebView 完整配置序列、正/零/负/大尺度原 int 保存、宽视口独立往返、无前进历史、销毁与
  跨线程检查、真实 guest override 的 invoke-super 均覆盖。
- 13 个新增接缝与 3 个封存根逐个关闭，共 16 项全部退出 1，并检查对应入口/资源 ID 的错误。
  方法使用临时测试 fixture 在链接后清空精确 handler，资源只修改隔离 fixture JAR 并重算 pairing。
  finally 逐字节恢复 fixture 源码和 JAR；negative-proof.json 记录恢复与哈希，最终构建移除注入。
  第一次 spinner 根反证错误为明确的 unsupported projected resource reference，已按精确资源 ID
  修正判据后完整重跑；不将脚本判据错误作为通过。
- BootDex 最终由同 composer 的 fixture build 生成并同步默认载荷；独立默认 check 重算一致。
  证据 build-review.log、bootdex-check-final.log、payload-final.log、final-pairing-proof.json。

  只构建 ogplay_tests/ogplay-cli（final-build.log），无全量测试或 Windows/title gate。
- 首轮错误 parser 的 getDepth ULE、BitmapDrawable bounds 缺口与 clean redraw 返回值测试误用
  均保留在早期日志；分别修为真实 XmlBlock.Parser、纯 ROM bounds 闭包和正确的绘制复用判据。
  相关分支已重新通过。最终定向与真实 APK 结果见后文。

## GTASA reached-fault

最终构建与配对载荷下，保留原沙盒，仅运行一次：
`build/release/ogplay-cli library run com.rockstargames.gtasa`。
60 秒观察预算后向进程组 SIGTERM，60.39 秒退出 0，无残留进程组；
gtasa-result.json 的 timeout=true 是主动观察预算到期，不是 guest fault。未清沙盒。
控制台记录 26 个呈现帧；不据此推断画面或 FPS 合格。

原 `ProgressBar.setIndeterminate(Z)V` ULE 不再出现；gtasa-current.log:90 的一次
`ui.content.unreviewed ProgressBar drawable content is not drawn` 及随后主树 projection committed
提供同路径确已构造并投影的正向证据，不把无旧日志单独当作通过。

下一首条 runtime.dexvm threw 位于 gtasa-current.log:76：
`Lcom/rockstargames/hal/andLabel;.setText` 抛
`Ljava/lang/UnsupportedOperationException;: text outside bounded service`。
紧邻日志记录 modified UTF-8 输入 1193 个 UTF-16 units；这里只记录事实，不在本单诊断或修复文本边界。
栈：`andLabel.setText pc6 → ActivityWrapper.runMain pc59 → GTASA.AfterDownloadFunction pc109 →
WarMedia.localHasGameData pc29 → WarMedia.onCreate pc459 → GTASA.onCreate pc195`。
同类异常再出现一次，随后 JNI ExceptionClear；主生命周期继续 onStart/onResume 并呈现，不能将其
描述为进程立即崩溃。此前 external-font UOE 被游戏捕获打印；离线 DNS/Play 提示不计作新框架实现。

未观察到下一 ListView/WebView 未实现调用，不声称原 APK 已完成全部 HAL 控件链；
WebView 构造配置与附着链的信用来自上述双后端测试。只记录 reached-fault，
不作 title gate、画面、FPS、长期稳定性或 Windows 兼容验收。后续依赖保持未实现。
