# DVM-366 · 固定字体统一长度边界、LightingColorFilter 与 TextView 触摸

状态：实现、macOS 双后端定向、关闭反证与 reached-fault 完成；未提交。证据 `.local/dvm366/`。
依赖：[DVM-293](DVM-293.md)、[DVM-355](DVM-355.md)、[DVM-362](DVM-362.md)、[DVM-365](DVM-365.md)。

## 背景

GTASA 显示 Social Club 登录界面后，`andLabel.setText` 收到 1193 个 UTF-16 单位的文本，
被 TextView 有界文本服务以 `text outside bounded service` 拒绝，游戏弹出 "Exception" 对话框。
1024 单位是早期为限制固定字体计算量定下的预算，API19 TextView 本身没有长度上限。
登录界面的所有按钮都是 andButton，ACTION_DOWN 会 `new LightingColorFilter(-6710887, 0)`，
这是修好文本后点击任何按钮的必经路径，因此一并处理。
首轮真机点击 OFFLINE 先撞上 `TextView.onTouchEvent` 未实现（andButton 的文字 TextView 叠在 ImageButton 上），
它是按下验收的必要依赖，作为 C 节一并纳入。

## A. 统一长度边界

原先 1024 分别硬编码在五处：MeasureFixedText、TextView 构造/XML 校验、TextView setText 校验、
Paint 文本范围检查、Editable 替换；EditText 构造另设 `max_length = 1024`。

- `ui::kMaxFixedTextUnits = 65536` 定义在 `ui_leaf_measure.h`，所有消费方只引用这一个常量。
- MeasureFixedText 按字形单位（不含 `\n`/`\r`）计上限，总长度允许到两倍上限。
  原因：WrapFixedText 生成的换行计划最多给每个字形插入一个换行；旧实现按总长度计数，
  接近上限的文本一旦换行，后续测量或光栅就会失败（1024 时代即有此隐患）。
- 溢出：最坏情况为上限文本、128px（scale 16）、粗斜体、每行一个字形。
  宽 (65536×11−1)×16 ≈ 1.15e7，高 (131073×8−1)×16 ≈ 1.68e7，均远小于 int32；
  原有宽度溢出检查保留。
- 渲染成本：UiOverlayRenderer 只在树代次、尺寸、plane 或 draw dirty 变化时重建，
  内容不变的长文本不会逐帧重新光栅化；本单不引入新的缓存。
- EditText 不再设默认 `max_length`（ROM 没有默认上限，真实长度语义来自 DVM-362 的 InputFilter）；
  Editable 替换超出统一上限时仍以 `text exceeds bounded edit service` 记账失败。
- 超限、字号越界、缺字形仍记账并明确失败；配方 review 中引用 1024 的说明同步改为统一上限。

## B. LightingColorFilter

- ColorFilter、LightingColorFilter 以 ROM 形状、构造与 finalize 加入 JavaTraversal 组合
  （`view-colorfilter-sources.json`，类加入 `java-traversal.json` 的 framework.jar 追加集）。
- 三个 native 走受审 platform_seam，沿用 DVM-355 GraphicsStateStore 的 Xfermode 模式：
  `native_CreateLightingFilter` 分配句柄并保存 mul/add；`nCreateLightingFilter` 只接受已存在且参数一致的
  Skia 句柄，返回独立的 HWUI 句柄，否则抛 IAE；`finalizer` 与 GC 清扫回收两个句柄。
  finalizer 与 Xfermode 一致，对已回收或未知句柄幂等，不额外报错（GC 清扫与 finalize 的先后不固定）。
- 不做颜色运算，不被 Paint/Canvas/ImageView 绘制消费；PorterDuffColorFilter、ColorMatrixColorFilter 未准入。

## C. TextView.onTouchEvent

ROM 方法体依赖 Editor、MovementMethod、Spannable、IMM，严格审计无法准入，改为受审 overlay。
OGPlay 中 Java mEditor/mMovement 恒为 null、mText 非 Spannable，此状态下 ROM 语义正是返回
View.onTouchEvent：非编辑 TextView 原样转发 View 的结果（不消费时事件继续落到下层按钮）；
EditText 或带 movement 的 TextView 触摸需要光标、链接与 IME，记账并以 UOE 明确失败。

## 缺口与后续依赖

- Social Club 界面的 Logo、复选框、按钮底图都在游戏覆写的 onDraw 中经 PackedImage.Draw
  （Canvas.drawBitmap(Rect,Rect,Paint)、BitmapDrawable.draw/tile、Paint.setColorFilter）绘制；
  guest onDraw 不执行，是下一阶段绘制 ADR 的主要动机。
- EditText 触摸（点输入框）仍明确失败，需另立 Editor/光标/IME 的有界方案。
- 外部 OTF 字体（createFromAsset）、固定字体行高（descent=0 致标题与正文贴边）、
  ListView/ExpandableListView 不在本单范围。

## GTASA reached-fault

保留沙盒，以 `run-apk game.apk --external-dir … --installation-id com.rockstargames.gtasa --mcp` 运行
（`library run` 不接受 `--mcp`，参数与 library 条目一致）。

- 登录界面不再出现 "Exception" 对话框，标题、两段说明、Email/Password、Remember Details、
  Forgot Password、SIGN IN/SIGN UP/OFFLINE 文字完整投影，无 runtime.dexvm threw（sc-before.png）。
- 首次点击 OFFLINE（800×480 坐标 700,387）暴露 `TextView.onTouchEvent` 未实现 → 纳入 C 节。
- C 节完成后再点 OFFLINE：按下路径无 Java 异常，游戏离开登录界面进入 SurfaceView 创建、
  EGL/GLES2 初始化、OpenAL 启动；32.95 秒退出 1，无残留进程组（gtasa-result.json、gtasa-console.log）。
- 下一首错：渲染线程 `swapBuffer wait` 之后 `frontend.run_apk.fault JNI reference is invalid for this thread`。
  属 JNI 线程本地引用的独立问题，本单只记录不修；不作 title gate、画面或 FPS 验收。
