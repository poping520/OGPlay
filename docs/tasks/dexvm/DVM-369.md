# DVM-369 · Unity 输入复制、启动显示方向与工作 Looper

状态：已可操作至第二章；退出 SDK 异常保留，未做 title gate。2026-11-05；基于 9ab2ccd0。

## 范围

以 Monument Valley 原 APK 触达路径推进到可操作，复核原有 JNI class mirror、Proxy、
NEON、Bitmap、Dialog、spinner 与非主线程 Choreographer 改动；只跑受影响主题和既有基线。
不实现外部 SDK 后端，不做正式 title gate。

入口 Activity 的 portrait/sensorPortrait/reversePortrait/userPortrait 只调整继承全局/默认尺寸；
命令行或游戏级任一显式尺寸固定整组宽高。建窗前统一解析，窗口/指标/Surface/触摸同源。
未实现运行时 setRequestedOrientation、多 Activity 方向切换；正方形尺寸交换不改变长宽比。

## 实现与真实到达点

- MotionEvent.obtain(MotionEvent)：按固定 API19，null 抛 IAE，完整复制所有 pointer/axes/offset/历史，
  独立对象及快照，可独立 recycle。Unity injectEvent 原先查不到该重载，注入后无反应。
- Display.getRefreshRate 与 Choreographer 的注入刷新率同源。非主 Looper 接收自己的 vsync，
  跨线程队列仍失败。
- UnityMain NEXT_FRAME 在每次处理后立即重投；原 PumpLooperDue 的 10,000 次预算把正常长期
  生产者杀掉。工作 Looper 单批用完后释放锁并继续，主线程生命周期泵的预算保护保留。
- 上一会话修复：BootDex forceLayout/drawable 准入、Bitmap 缩放/alpha、JNI Class[] mirror、
  Proxy（DVM-259）、ASIMD、Dialog custom view、Log.println、缺席服务列表、spinner 投影。

首次显式 720×1280、关闭 survey 的 MCP 实测：点击行走，拖动曲柄改变桥面，再点击终点，
完成序章并进入章节选择。证据 .local/mv/portrait-{scene,walk,rotate,crossed,goal,next}.png。
第二章选择阶段曾遇到上述 Looper 预算异常；初次 SIGINT 随后因已死 UnityMain 的 pause 等待失败，
此结果不作为退出通过证据。第一次音频采样因脚本解释器丢失 dyld 环境未取得 PCM；最终直接启动已取证。
