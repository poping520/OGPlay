# DVM-375 · SAX 文本流解析

## 根因

Sacred Odyssey 1.1.0 安装器从 APK 的 `res/raw/gi_settings.xml` 读取设备和纹理配置。
`XMLReader.parse(InputSource)` 原先抛 UnsupportedOperationException，安装器吞掉异常，
随后在 `installer.utils.f.b`（pc 11）读取未初始化的配置对象，抛 NullPointerException。

## 范围

复用固定 API19 KXml、ROM SAX 接口、DefaultHandler、XMLFilterImpl、AttributesImpl 和 LocatorImpl。
由 BootDex Java 把文本 XML 事件传给应用 handler。每个 SAXParser 通过 guest 字段持有同一 reader，
reader 的 handler 由 Java GC 追踪，删除 integration 的宿主侧表。
支持显式字节/字符流，字符流优先，选中的流按 API19 ExpatReader 的协议关闭。
DTD 和只有 system ID 的输入明确拒绝，验证、外部实体和处理指令事件在范围之外。

## 验证

- macOS Release 定向构建 `ogplay-cli`、`ogplay_tests`。SAX、XML Pull 与 core catalog
  共 3 个用例、1,378 条断言通过，SAX 覆盖双解释器的 BOM、namespace、属性、文本回调和错误传播。
- 同一持久沙盒从原 `ogplay-cli library run` 入口复跑。安装器空指针消失，游戏加载纹理并到达
  原生 Splash 状态。下一首错在 `f=708` 的 `GameRenderer.nativeRender()V`，
  A32 PC `0x309b0660` 读取未映射地址 `0x0`，退出 1。游戏可玩性和 Windows 未验。
- BootDex build/check、能力账本和差异静态检查通过。日志位于 `.local/sacred-odyssey-debug/`。
