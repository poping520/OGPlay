# DVM-376 · Android Time

## 范围

从固定 API 19 ROM 收录 Time，保留字段、构造器和 Java 方法。通过 native 签名
转发到 guest Java，复用 Calendar、TimeZone、原版 ZoneInfo 和固定 guest tzdata。
当前时间从 System.currentTimeMillis 取得。format 使用原版 LocaleData 和系统格式资源。

## 验收

- BootDex build/check、native 签名与资源映射检查、payload 和能力账本。
- 用固定 Clock 验证 GMT+8 跨日、地区 DST、字段读写、转换和 RFC 2445/3339。
- 复跑割绳子和保卫萝卜原 APK，记录下一首错。若割绳子到达生命周期注册缺口，
  复用原版 Application 回调协议，并验派发顺序。

## 实现边界

- 11 个 native 入口委托 guest Java。GMT 偏移和地区时区与 Java TimeZone 共用查找，
  具名时区读取固定 2014a 归档。转换按 API 19 的有符号 32 位 epoch 秒和秒级精度处理。
  时区全量枚举、归档更新和所有历史转换未验收。
- format 使用 API 19 的转换符与常见修饰符，未知转换符抛 UnsupportedOperationException。
  月、星期、AM/PM 和数字从原版 LocaleData 获取。三个系统格式模板来自默认资源，
  未投影其他 locale 的模板变体。原生行为参考 [Time.cpp](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-4.4.4_r2/core/jni/Time.cpp)
  和 [strftime.c](https://raw.githubusercontent.com/aosp-mirror/platform_bionic/android-4.4.4_r2/libc/tzcode/strftime.c)。
- Application 注册、注销和派发使用 ROM 方法。Activity base 回调在 super 调用点派发。
  保存状态回调可显式调用，会话没有自动保存/恢复调度。

## 验证结果

- macOS Release 定向构建 `ogplay-cli`、`ogplay_tests`。格式化后重新构建，
  5 个用例、570 条断言通过。Time 和生命周期用例均覆盖双解释器。
  固定 Clock 验证 GMT+8 跨日、纽约 DST 跳跃与重复小时、字段、规范化、毫秒往返、
  格式化与解析。生命周期用例覆盖注销、启动顺序、切换、Bundle 透传和销毁。
- 与固定 ROM 反汇编对照，Time、Application、ZoneInfo 定义一致。核对三项系统字符串
  资源 ID 与 ROM ARSC 一致；compose 构建审计 native 签名。
- 两款原 APK 沿 `ogplay-cli library run` 复跑，退出码均为 1，呈现帧均为 0。
  - 割绳子 2.3.8 先越过 Time 缺类，随后越过 Application 注册缺口。
    下一首错为 FragmentActivity.onCreate（pc 28）调用缺失的
    `getLastNonConfigurationInstance()Ljava/lang/Object;`。
  - 保卫萝卜 1.1.0 越过 Time 缺类并进入 Cocos2d nativeInit。
    首个 Java 异常为 `Paint.getFontMetricsInt()Landroid/graphics/Paint$FontMetricsInt;`
    未实现。随后记录 Build 类初始化失败及 A32 读取 0x0。
- 证据位于 `.local/dvm-376/`，每款游戏的原始日志在
  `.local/analysis/attention-2026-11-09/fixes/<package>/dvm-376-verified/`。
- BootDex build/check 和 444 项能力账本通过。完整 payload 校验通过 BootDex 阶段，
  随后在既有的 `libogplay_jni.so` 生成器 SHA-256 不一致处失败。HEAD 中的
  manifest 和生成器已存在同样的不一致。Windows 与游戏可玩性未验收。
