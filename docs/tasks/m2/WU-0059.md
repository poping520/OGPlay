# WU-0059 · Bionic ELF 命名空间与 HLE 符号

目标：把 Bionic profile 的真实 guest 库、选择性拦截与 HLE 边界装配到同一个 ELF 链接命名空间。

依赖：WU-0050、WU-0052、loader/runtime 模块契约。

验收：

- [x] guest ELF 依赖顺序与符号查找继续使用统一 `Elf32LinkNamespace`，不另建旁路链接器。
- [x] 声明的 libc 热点由 provider 的绝对 HLE thunk 抢占，其他 libc 符号仍解析到真实 Bionic。
- [x] HLE 边界库只生成 provider 已注册的导出符号，不装载依赖系统服务的真实 Android `.so`。
- [x] thunk 地址限制在 `0x70000000–0x70ffffff`，重复名称、重复地址和越界地址明确失败。
- [x] HLE provider 同时实现 guest 地址反查，可直接接入结构化日志与 `sym.resolve`。
- [x] 缺失 HLE 符号、未知依赖及混入 guest 的边界库均明确失败，不伪造成功。
- [x] macOS AppleClang `dev` 预设构建与全量 CTest 通过（108/108）。
