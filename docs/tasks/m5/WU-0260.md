# WU-0260 · GLES1 clear depth boundary

目标：让 GLES1 `glClearDepthf` 逐位解码 guest `GLfloat` 并更新当前 ANGLE context 的真实 depth-clear state。

依赖：WU-0259、`src/gles/MODULE.md`、`src/runtime/integration/MODULE.md`。

验收：

- [x] `AngleFrame` 新增最小 `ClearDepth(float)`，直接调用 ANGLE/GLES2 `glClearDepthf` 并检查错误。
- [x] GLES1 core dispatch 新增且只新增 `glClearDepthf` handler；`glClearDepthx` 与 `glClear` 继续保持未绑定。
- [x] guest 32-bit 参数必须以 `GLfloat` 位模式解码，不得做整数数值转换或宿主侧伪状态缓存。
- [x] 无当前 ANGLE frame 或原生 GLES 错误必须明确失败。
- [x] 机器测试覆盖无 current frame、真实 ANGLE 调用成功，以及相邻 `glClearDepthx` 仍未绑定。
- [x] exact-APK `run-apk` 越过 `glClearDepthf` 并暴露下一精确边界。
- [x] macOS/arm64 + ANGLE warnings-as-errors 构建及全量 CTest 通过。

非目标：本 WU 不绑定 GLES1 `glClear`、`glClearDepthx`、depth test/write state，也不批量实现其他 fixed-pipeline 状态入口。

机器证据：

- `Android boundary publishes GLES1 core without silent handlers`：1/1 通过。
- exact-APK `run-apk` 已越过 `glClearDepthf`，精确停止于未实现 GLES1
  `glClear`（thunk 8）。
- macOS/arm64 以 `OGPLAY_ENABLE_ANGLE=ON` 全量 CTest 402/402 通过。
