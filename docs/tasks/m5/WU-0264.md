# WU-0264 · GLES1 lighting/material/fog state batch

目标：按 GLES1 规范批量闭合目标导入的 lighting、material 与 fog 固定管线状态入口。

依赖：WU-0263、`src/runtime/integration/MODULE.md`。

验收：

- [x] GLES1 core dispatch 一次新增 fog、light-model、light、material 共 7 个 handler。
- [x] 所有 vector 参数按 pname 求精确长度，并从强类型 guest 地址完整读取 little-endian
  `GLfloat`；坏地址、非法元素数与非有限值明确失败。
- [x] fog、8 盏 light、light-model 与 material 保存 GLES1 规范默认值，并随 context reset。
- [x] fog density、spot exponent/cutoff/attenuation 与 material shininess 范围受检。
- [x] `glMaterial*` 标准路径只接受 `GL_FRONT_AND_BACK`，不为目标静默放宽规范。
- [x] 机器测试覆盖全部 7 个显式 handler、默认值、提交、reset 与非法输入。
- [x] exact-APK smoke 进入首个 handler，并将目标的 `GL_FRONT` 规范差异暴露为下一 quirk
  边界。
- [x] macOS-arm64 + ANGLE warnings-as-errors 构建及行为测试通过。

非目标：本 WU 不实现 Profile quirk、eye-space light transform、fixed-pipeline shader、
client array 或 draw 转换；保存状态不伪造绘制成功。

机器证据：

- `GLES1 lighting material and fog state validates and resets`：1/1 通过。
- `GLES1 lighting material and fog handlers are explicit`：1/1 通过，且 `glAlphaFunc` 仍未绑定。
- macOS-arm64 + ANGLE 全量 CTest 的 404 个行为/工具测试通过；唯一初次失败为既有
  `CURRENT.md` 超过滚动快照上限，随本 WU 状态收尾压缩后重跑通过。
- exact-APK 已越过未实现 `glMaterialfv`，精确停止于目标传入 GLES1 规范不接受的
  `GL_FRONT (0x0404)`；下一 WU 必须以可关闭 Profile quirk 处理。
