# WU-0277 · Java SoundPool lifecycle handlers

目标：以真实、可查询的 SoundPool 生命周期闭合 exact-APK frame call 9 的 missing handler。

依赖：WU-0276、`src/audio/MODULE.md`、`src/runtime/integration/MODULE.md`。

范围：`audio.destroy_sound_pool`、`audio.init_sound_pool_array`。

验收：

- [x] 调试器在失败点确认首个 implementation 为 `audio.destroy_sound_pool`。
- [x] destroy 将会话 SoundPool 从 active 推进到 inactive，重复调用幂等。
- [x] 真实调用链暴露的配对 init 将 inactive 恢复为 active，重复调用幂等。
- [x] 两个 handler 进入统一 invocation engine；未安装时仍明确报告 missing handler。
- [x] 状态不发布 loaded/playing，也不伪造资源解码或宿主音频输出。
- [x] exact-APK 2 帧 smoke 正常退出；120 帧越过 frame call 9 后才在 shutdown 停止。
- [x] macOS-arm64 + ANGLE warnings-as-errors 构建及全量 CTest 通过。

非目标：本 WU 不实现 load/play/pause/resume/stop、解码、混音或宿主音频输出。

机器证据（macOS-arm64）：

- `Android guest Java audio handlers own SoundPool lifecycle` 定向测试通过。
- exact-APK `--exit-after-frames 2` 输出 `stopped after 2 presented frames`，状态 0。
- exact-APK `--exit-after-frames 120` 的下一精确边界为 shutdown call 11 内
  `audio.stop_all_sounds`。
- `cmake --preset dev`、`cmake --build --preset dev -j 8` 与全量 CTest 411/411 通过。
