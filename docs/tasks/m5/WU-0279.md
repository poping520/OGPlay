# WU-0279 · JNI missing-handler diagnostics

目标：让统一 JNI 调用引擎在 handler 缺失时保留可操作的 implementation 身份。

依赖：WU-0278、`src/runtime/jni/MODULE.md`。

范围：`JniInvocationEngine` 的 missing-handler 错误与相关契约测试。

验收：

- [x] 已解析方法缺少 handler 时，错误包含其规范 implementation ID。
- [x] 错误原因继续为 `missing_handler`，不改变参数和返回值验证顺序。
- [x] invocation、framework 与 Android guest session 契约均锁定新诊断。
- [x] exact-APK 的下一缺失实现可精确定位。
- [x] macOS-arm64 + ANGLE warnings-as-errors 构建及全量 CTest 通过。

机器证据（macOS-arm64）：

- exact-APK 将原不透明错误精确化为 `audio.is_sound_loaded_big`。
- `cmake --preset dev`、`cmake --build --preset dev -j 8` 与全量 CTest（411/411）通过。

## 后续诊断补强（2026-08-30）

- JNI guest `GetMethodID`/`GetStaticMethodID` 的未声明方法错误增加 registry class name，
  统一输出 `class=<binary-name> method=<name><descriptor>`，不再丢失方法 owner。
- instance/static 精确文案由各自 binding 测试锁定；方法查询、异常类型和失败顺序不变。
- Tales Release 关闭 survey 实跑将原歧义缺口明确定位为
  `class=java/lang/Thread method=getContextClassLoader()Ljava/lang/ClassLoader;`。
