# WU-0285 · GLES1 two-stage texture-unit draw

目标：让通用 GLES1 fixed renderer 按实际启用的纹理单元绘制，不把状态配置游标误作绘制输入。

依赖：WU-0284、`src/runtime/integration/MODULE.md`。

范围：最多两个启用纹理单元的选择、逐级组合、对应 texture-coordinate array、每单元
texture matrix、texture object base format 与 texture environment 状态。

验收：

- [x] active texture 与 client active texture 继续只决定后续状态写入位置。
- [x] draw 从启用 `GL_TEXTURE_2D` 的单元选择 sampler、坐标数组、base format 和环境状态。
- [x] active/client 游标停在其他单元时，已启用单元的绘制状态不被替换。
- [x] 两个启用单元按编号逐级组合，`GL_PREVIOUS` 读取上一 stage 输出而非 primary color。
- [x] 两个 stage 分别消费自己的坐标数组、sampler、base format、环境状态和 texture matrix。
- [x] 超过 GLES1 最低保证的两个启用单元仍携带 renderer 上限明确失败。
- [x] lighting 只计算 RGB，输出 alpha 取 diffuse material alpha，不受 ambient/light alpha
  累加影响。
- [x] 状态测试与真实 ANGLE draw/readback 覆盖游标分离及双纹理场景。
- [x] 真实 ANGLE blending/readback 覆盖 lighting + 零 diffuse alpha 的完全透明绘制。
- [x] exact-APK 人工确认启动 logo 与主界面 3D 纹理恢复；残余遮挡错误另由 WU-0286
  的默认 framebuffer depth/stencil 修复闭合。
- [x] macOS-arm64 + ANGLE warnings-as-errors 构建及全量 CTest 通过。

非目标：本 WU 不实现第三个及后续纹理 stage、GL_DECAL、GL_BLEND 或 matrix-palette
skinning。

机器证据（macOS-arm64）：

- 状态测试覆盖 active selector 与启用单元分离，并验证每单元 capability/base format 查询。
- 真实 ANGLE draw 同时启用 unit 0/1，分别上传 texture/coordinate array 后成功级联，并从
  输出帧读回预期红色像素；单元 0/1 texture matrix 状态保持隔离。
- lighting + alpha blending 回归先清为蓝色，再绘制 diffuse alpha 为零的黑色三角形；
  readback 全帧保持蓝色，证明光照未把透明材质错误提升为不透明。
- 用户确认 exact-APK 主界面车身纹理、反射与 UI 已恢复；后续黑色遮挡物经逐批 draw
  隔离，证明不属于双纹理阶段并转入 WU-0286。
- `cmake --preset dev`、`cmake --build --preset dev -j8` 与全量 CTest（413/413）通过。
