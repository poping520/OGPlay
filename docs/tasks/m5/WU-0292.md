# WU-0292 · Debug frame-path allocation removal

目标：消除 Debug exact-APK 帧路径中的重复同步、行翻转、临时分配与 GLES1 整状态复制，
且不改变渲染结果或 guest 可见语义。

依赖：WU-0291、`src/gles/MODULE.md`、`src/runtime/MODULE.md`、
`src/runtime/integration/MODULE.md`。

范围：ANGLE top-left readback、拥有型帧存储归还、Bionic 小块内存操作暂存，以及 GLES1
legacy setter 的验证/提交边界；Android boundary 符号目录仅作等价拆分以满足文件长度约束。

验收：

- [x] ANGLE 支持时以 reverse-row pack 直接生成 top-left RGBA8，恢复原 pixel-store 状态；
  不支持时保持确定性宿主行翻转，且 readback 前不再额外 `glFinish`。
- [x] 1x managed surface 只接受布局完全匹配的归还帧并复用 RGBA8 存储；机器测试验证连续帧
  序号、像素布局和存储地址复用，2..4x resolve 语义不变。
- [x] Bionic `memcpy`/`memmove`/`memset`/`memcmp` 的受限 4 KiB HLE 搬运使用固定栈暂存，
  保持 guest 地址预检与重叠语义。
- [x] GLES1 legacy state 禁止复制；高频 setter 在 current-frame 前完成验证，再窄范围提交，
  非法输入或缺少 frame 不得部分改变状态。
- [x] 用户在同一 Debug exact-APK 主菜单确认最高 22.2 FPS，达到游戏自身封锁帧率；上一
  已验收基线为约 13.7 FPS。
- [x] macOS-arm64 + ANGLE warnings-as-errors 配置、构建及全量 CTest 420/420 通过。

非目标：不绕过游戏锁帧，不缓存 guest 顶点/帧内容，不引入 title-specific 分支，也不改变
SDL present 的第三方实现。
