# WU-0378 · Dungeon Hunter bounded loading budget and run-apk progress logs

目标：恢复第二个 exact Profile 的有界运行，并让耗时 guest call 在不改变执行语义的前提下
持续输出可诊断进度。

依赖：WU-0318、WU-0377、`src/frontend/MODULE.md`、
`src/runtime/execution/MODULE.md`、`src/session/MODULE.md`。

范围说明：本次修复经用户明确解除单次会话 10 文件和单源文件 800 行限制；仍只修改
Profile 预算契约、通用 A32 observer、run-apk 日志及其直接测试和文档。

验收：

- [x] 将预算耗尽 PC/LR 映射到 exact root library，确认命中 guest 自带 PVRTC 解压循环；
  APK 不导入 `glCompressedTexImage2D`，宿主 GLES 压缩纹理 fallback 不是该路径入口。

  有界完成；Profile、schema、C++ 强类型上限和 Python/C++ 校验测试保持一致。
- [x] A32 slice observer 发布当前调用的实际累计 tick；SVC 安全边界同样报告累计值，
  前端不得再以 observer 回调次数估算工作量。
- [x] `run-apk` 默认输出 Profile、bootstrap、JNI/lifecycle、首帧/每 60 帧、长调用和
  teardown 的结构化日志；长调用每累计 10 亿 tick 最多报告一次并在完成时收口。
- [x] 按本次会话要求接纳仓库已有的 CMake ANGLE 默认启用变更；仍保留显式关闭选项。
- [x] exact APK 120 帧和 240 帧均以退出码 0 返回；120 帧日志在第 75 帧记录约
  96.99 亿 tick 的有限 PVRTC 调用并继续提交到第 120 帧。
- [x] Windows/MSVC warnings-as-errors 全量 build、full CTest 497/497、MODULE/CURRENT/
  capabilities 与 `git diff --check` 通过。
