# WU-0379 · Asphalt 6 mixed GLES buffer-state diagnosis

目标：把 Asphalt 6 `nativeInit` 的 `required guest pointer is null` 收敛为可复现、
可机器判定的通用混合 GLES 状态问题。

依赖：WU-0377、WU-0378、`src/gles/MODULE.md`、
`src/runtime/integration/MODULE.md`。

范围说明：本次会话经用户明确解除 10 文件和单源文件 800 行限制；本 WU 只增强通用
失败诊断并冻结根因，不在尚未确认相邻状态契约前实现同步修复。

验收：

- [x] Android boundary guest transfer 失败保留原异常类型，并附带 `module!symbol`、r0-r3、
  SP、LR 与 guest thread。
- [x] GLES2 client attribute staging 失败报告 index、pointer、bytes、size、type、stride，
  以及最近 definition/enable 的 guest LR。
- [x] 混合 GLES1 draw 转入 GLES2 时，失败报告两套 transfer state 的 array/element
  buffer binding；focused 测试固定“GLES1 已绑定、GLES2 仍为 0”的失配现场。
- [x] exact APK 稳定定位到 `libGLESv1_CM.so!glDrawArrays(0, 0, 1)`：attribute 0 为
  `pointer=0,size=3,type=GL_FLOAT,stride=12`，但同时
  `gles1_array_buffer=1,gles2_array_buffer=0`。
- [x] guest 静态地址映射到 `CProgrammableGLDriver::setupArrays`：enable LR
  `0x1090f5ac`、definition LR `0x1090f618`；draw LR `0x109183ac` 位于
  `drawPrimitives`。
- [x] Windows/MSVC warnings-as-errors build、full CTest 497/497、MODULE/CURRENT/capabilities
  与 `git diff --check` 通过。

结论：guest 的 pointer `0` 是已绑定 VBO 的 offset 0，不是 client null。共同
`glBindBuffer` 经 GLES1 dispatch 更新真实 ANGLE 与 GLES1 transfer state，却未同步 GLES2
transfer state；后续 `glVertexAttribPointer` 因看到 GLES2 binding 0 保存成 client pointer，
混合 draw 重定向最终误报 null。后续修复应统一同一 ANGLE context 的共同 buffer binding
事实，不能把 pointer 0 特判为有效 client 内存。
