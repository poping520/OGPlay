# WU-M8-006 · JNI Monitor

目标：让 MonitorEnter/MonitorExit 使用真实、可重入且可中断的 runtime/jni monitor semantic。

依赖：WU-M8-001、统一 JNIEnv reference/thread attachment、Android guest session teardown。

验收：

- [x] MonitorEnter/MonitorExit 两槽进入 environment 拥有的 monitor table，成功才返回 JNI_OK，
  null/unknown object 与非法状态不伪造成功。
- [x] 每个 object identity 保存 owner guest thread、recursion、waiting threads 与 condition
  wakeup；同线程两次 enter 后需两次 exit 才释放。
- [x] T2 在 T1 owner 期间真实等待，T1 release/detach 后 T2 获得 ownership；非 owner exit
  抛出明确错误。
- [x] JavaVM DetachCurrentThread 经 environment 释放该线程持有的全部 monitor ownership。
- [x] monitor shutdown 为 sticky interrupt，wake all 当前 waiter 并拒绝后续 enter；session
  Stop 与 InterruptBlockingWaits 在 join 子线程前同时中断 futex 与 monitor wait。
- [x] aggregate contract 最终为 JNIEnv/JavaVM 212/4；Windows/MSVC warnings-as-errors 构建、
  reentrant/contention/invalid-exit/shutdown/guest-binding focused 与全量 CTest 通过。

非目标：不实现 Binder/system_server monitor，也不把 host mutex pointer 暴露为 JNI handle。
