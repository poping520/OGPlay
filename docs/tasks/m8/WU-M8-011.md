# WU-M8-011 · Dungeon Hunter analytics 调用族 handler

目标：修复 Dungeon Hunter 封面点"继续"后 `analytics.track_first_run` 无注册 handler
导致的会话停止，按调用族一次闭合 analytics 组三个通用 implementation id。

依赖：现有 profile Java handler 目录（M5 WU-0208 机制）与
`AndroidGuestPlatformState`。不新增 JNI 槽位。

背景：DUNQ profile 引用的 impl id 对账发现 16 个在 `src/` 无 handler；游戏能到封面
是因为尚未命中。本 WU 只闭合语义无歧义的 analytics 族（统计服务属 ADR-0001 排除
范围，诚实终态为记账 + 返回），其余组见非目标。

验收：

- [x] `analytics.track_first_run` 注册为与 `analytics.track_launch` 同口径的 offline
  tracking 记账 handler，返回 void；不接触任何网络或宿主统计服务。
- [x] `analytics.increase_launch_count` / `analytics.get_launch_count` 以
  `AndroidGuestPlatformState` 线程安全启动计数实现真实计数语义（增一/读取），
  不伪造固定值。
- [x] 机器测试覆盖三个 handler：first-run 记账计数递增、launch 计数 0→2 可读。
  `tests/runtime/android_guest_framework_platform_tests.cpp` 扩展 fixture。
- [x] `src/runtime/integration/MODULE.md` 与 `capabilities.toml`
  （`runtime.android_legacy_platform_identity`）同步描述。
- [x] focused 平台 handler 测试与全量 CTest 通过（GLES boundary 4 项失败确认为
  沙箱无 GPU 环境因素，非沙箱复跑通过）。

非目标：不实现 `license.*`（6 个）、`billing.launch`、`browser.open`、`online.*`
（2 个）、`activity.paused`、`audio.is_media_playing`——返回值影响游戏行为，需先取得
反编译证据，未命中前保持 missing-handler 明确失败；不改 DUNQ profile；启动计数
不做跨会话持久化（如后续证实游戏依赖持久计数再接 MODE_PRIVATE preferences）。
