# WU-M9-014 · JNI 出向编组（解释器→A32 native）

## 目标（一句话）

`DexVmGuestBridge` 实现 `NativeMethodBridge`：解释器命中 native 方法时按
descriptor 编组 A32 soft-float 调用帧（r0=JNIEnv、r1=receiver/jclass、
64 位偶对齐），经存量 `AndroidGuestCallSession` 执行器调用 guest 机器码。

## 依赖

- WU-M9-007..013（内核）、`runtime.a32_guest_call_executor`、
  `runtime.jni_guest_native_registration`、`runtime.jni_native_export_names`
- 设计：`docs/design/dexvm/04-integration.md` §1 出向编组表

## 变更

- `AndroidGuestCallSession` 新增公共访问器：`Invocations/Strings/Arrays/
  SoundPoolState/SoundPoolMixer/Filesystem` 与 `FindNativeExport`
  （short→long JNI 导出名在已装载命名空间逐模块解析）。
- `runtime/integration/dexvm_bridge.{h,cpp}`：出向解析顺序 =
  RegisterNatives 映射 → `Java_` 导出名 → 记账 + UnsatisfiedLinkError；
  引用实参经 root 线程 local ref 表发布（native 与解释器同一对象）；返回
  值按 shorty 解码（J/D 返回暂记账明确失败——pilot 的 native 面无宽返回）；
  调用后 pending JNI exception 转为解释器 Java 异常。

## 验收（机器可判定）

- 与 WU-M9-015 共用 `tests/dexvm/bridge_tests.cpp`（入向合同可无 guest 验证；
  出向端到端由 pilot gate 验证）；full CTest 无回归。
