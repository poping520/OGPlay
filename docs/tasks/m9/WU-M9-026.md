# WU-M9-026 · Asphalt 6 启动作用域 exact gate

## 目标（一句话）

用已 provisioned external 数据经入口覆盖与必要 preset 推进 Asphalt 6，并固化首个真实边界。

## 验收

- 去掉 entry 或必要 preset 后在原商业外壳边界失败。
- exact Scenario 至少三轮确定性；达到主界面后才把能力标为 ready。
- DRM 消费点若进入引擎数据链，继续明确失败并另立真实实现 WU，不得中性化。

## 结果（已完成）

- DexVM intrinsic 平台类与缺失方法现可通过同一
  `JniClassRegistry` 被 native `FindClass` / `GetMethodID` 看到，既有 session
  类不被替换；`Intent` / `Bundle` / SAX 构造链、有界方法反射、
  `Stack`、`Thread.getId/getName/setName` 均以通用契约补齐并有机器测试。
- production Profile 的 exact Scenario 三轮一致停在
  `Ljava/lang/Object;->wait()V`：渲染 `GLThread` 已启动，但现有协作式
  `Thread.start()` 把 `run()` 一次跑完，不具备释放 monitor、挂起、
  另一宿主线程 notify 后重新竞争的 wait-set 语义。证据为
  `.local/automation/asphalt6-entry-scope-dev19-20260812` 至 `dev21`（不入库）。
- 删除必要 `sbStarted` preset 的负向 exact 会真实切换至
  `installer/GameInstaller`，并在商业外壳的 `Intent.setPackage` 缺口明确失败；
  未进入 DRM 消费链。APK manifest launcher 本就是 `GLGame`，因此
  entry override 对该 exact 标题与 manifest 事实等价，不宣称它是必要 quirk。
- 未产生首帧/主界面，`profiles.asphalt6_glstore_v132` 保持 `partial`；
  不用空 `wait()` 伪造成功。后续阶段 4 分解见 WU-M9-027..030。
