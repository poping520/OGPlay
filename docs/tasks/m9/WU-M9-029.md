# WU-M9-029 · monitor wait-set 与 Object.wait/notify

## 目标（一句话）

按 AOSP `vm/Sync.cpp` 语义把 DexVM monitor 接入统一 owner/recursion/
wait-set，实现 `Object.wait/notify/notifyAll` 的真实跨线程配对。

## 依赖

- WU-M9-028。

## 验收

- wait 校验 owner，保存 recursion→全量释放→入 wait-set；被 notify/超时/
  interrupt 唤醒后必须重新竞争并恢复 recursion 才返回或抛异常。
- 无所有权抛 `IllegalMonitorStateException`；`notify`/`notifyAll`、超时、
  interrupt generation 和 Shutdown 均有确定机器测试。
- 所有超时通过统一 Clock，不读宿主 wall clock。

## 交付（完成）

- `dexvm::VmMonitorTable`（`vm_monitors.h/.cpp`）：session 级 owner/recursion/
  wait-set，owner 是 execution context token。`Enter`/`Exit` 提供真实跨线程
  互斥；争用时释放执行锁停泊。
- `Wait` 逐步对照 AOSP `vm/Sync.cpp` `waitMonitor`：校验 owner → 入 wait-set
  → 保存并清零 recursion → 全量释放 → 停泊 → **先重获 monitor 并恢复 recursion**
  → 才返回或抛 `InterruptedException`（并清除中断位，符合 JLS）。
- 唤醒源：`notify`（wait-set 头）、`notifyAll`、Clock 超时、`Interrupt`、
  `Shutdown`。无所有权一律 `IllegalMonitorStateException`。
- 超时只用注入的统一 Clock（`SetTimeSource`，前端接
  `DexVmAndroidContext::uptime_millis`）；没有时间源的 timed wait 记账
  `dexvm.monitors.wait_without_clock` 并明确失败。条件变量轮询间隔只是调度
  唤醒，不参与截止判定。
- `Object.wait()V` 首次声明；`notifyAll` 从与 `notify` 共用 handler 拆开。
  线程结束时 `ReleaseAll` 释放其仍持有的 monitor 与 wait-set 成员资格。

## 验证

- `tests/dexvm/vm_monitor_tests.cpp` 9 个确定性多线程用例；关闭即失败的形态：
  recursion 恢复用例在唤醒后连做三次 `monitor-exit`，深度没恢复就会抛
  `IllegalMonitorStateException`；interrupt 用例在 catch 之后 `monitor-exit`，
  没重获 monitor 就会失败。
- macOS/arm64 CTest 609/609。
- Asphalt 5 exact 回归逐位持平：468 帧 / 468000 tick、SHA-256 `9ee57323…`、
  无 fault、clean shutdown。
- Asphalt 6 exact：`Object.wait()` 边界消失，整轮**无 guest fault**、clean
  shutdown。`GLThread` 现在正确停泊在 `GLThreadManager` 守卫循环上等待
  surface 通知。新的真实边界由 WU-M9-030 固化。
