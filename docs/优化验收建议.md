# WU-OPT-CLOSURE-01 · Guest GL Context / HLE 优化验收闭环

## 目标

在 **一个 Work Unit 内**完成当前 `GuestGlContext` / mixed GLES1+GLES2 / HLE 热路径优化的最终闭环。

本 WU 不再进行架构扩张，也不新增图形功能。目标是修复上一轮统一 Context 后仍存在的状态分裂与 guest-visible 语义问题，并完成剩余两个明确的 hot-path 性能收尾，使本轮优化可以正式验收结束。

完成后应满足：

* GLES1/GLES2 在同一个 guest EGL context 下不存在已知的 shared-state 分裂。
* GLES2 能力不能被 GLES1 的能力子集错误限制。
* supersample 等 host implementation detail 不泄露到 guest query。
* 高频 GL state mutation 不复制整个 `SharedGlState`。
* GPU trace 默认记录路径不再竞争 Android boundary 的全局 mutex。
* 已完成的 dense HLE dispatch、sealed dispatch、A32 bulk arguments、CString page scan、GuestTransfer generation ticket 不发生回退。
* Asphalt 6 exact 不退回已解决的 mixed GLES buffer/client-pointer 故障。

---

从 commit `48d0a920` 开始，项目已经完成：

* 单一 `GuestGlContext`

# 必须解决的问题

## 1. 统一 active texture 与 GLES1 texture matrix unit

### 当前问题

`SharedGlState` 已经拥有统一的：

```cpp
active_texture
```

但：

```cpp
AndroidBoundaryGles1MatrixState
```

仍单独保存自己的：

```cpp
active_texture_
```

当调用顺序为：

```text
GLES2 glActiveTexture(GL_TEXTURE1)
GLES1 glMatrixMode(GL_TEXTURE)
GLES1 glTranslatef / glLoadMatrixf / ...
```

时，shared active texture 已经是 `GL_TEXTURE1`，但 GLES1 matrix state 可能仍然操作 `GL_TEXTURE0`。

这是统一 Context 后残留的第二份 authoritative state。

### 要求

删除这种状态分裂。

最终必须满足：

> 当前 texture matrix unit 必须由统一 guest context 的 active texture 决定。

允许的实现方式：

* `AndroidBoundaryGles1MatrixState` 直接使用 shared active texture；
* matrix API 显式传入当前 texture unit；
* 或其他不产生第二份 authoritative active-texture state 的实现。

### 禁止

不得通过：

```text
GLES2 glActiveTexture
→ 手工额外通知 GLES1 matrix object
```

建立两个需要同步的 shadow state。

应该从数据模型上保证只有一个权威值。

### Regression Test

必须新增 cross-API test：

```text
GLES2 glActiveTexture(GL_TEXTURE1)
GLES1 glMatrixMode(GL_TEXTURE)
GLES1 修改 texture matrix

切换 GL_TEXTURE0
查询/验证 texture0 matrix 仍为 identity

切回 GL_TEXTURE1
验证修改存在
```

必须覆盖：

```text
GLES2 entry → GLES1 matrix consumer
```

不能只测试 GLES1 自己调用 `glActiveTexture`。

# 2. Shared texture binding 必须支持 GLES2 target

## 当前问题

当前 shared texture binding 本质上类似：

```text
texture unit → texture object
```

并且 shared validation 只允许：

```text
GL_TEXTURE_2D
```

这使：

```cpp
glBindTexture(GL_TEXTURE_CUBE_MAP, texture)
```

会在 shared shadow 层失败，即使这是合法的 GLES2 state。

统一 Context 的 shared state 不能采用 GLES1/GLES2 中能力较小的一方作为公共模型。

### 要求

texture binding key 至少改成：

```text
(texture unit, target)
```

或语义等价的数据结构。

至少必须支持：

```text
GL_TEXTURE_2D
GL_TEXTURE_CUBE_MAP
```

GLES1 API 自身仍然只能接受其合法 target。

也就是说：

```text
SharedGlState
    = GLES1/GLES2 state union

GLES1 handler
    = GLES1 API validation

GLES2 handler
    = GLES2 API validation
```

不能：

```text
SharedGlState
    = GLES1 capability subset
```

### 同时检查

以下逻辑必须按 `(unit,target)` 工作：

* BindTexture
* BoundTexture
* DeleteTextures
* TextureBaseFormat
* generate-mipmap metadata

如果 metadata 只适用于特定 target，应明确编码 target，而不能隐式假设 `GL_TEXTURE_2D`。

### Regression Tests

至少增加：

```text
GLES2 bind GL_TEXTURE_2D object A
GLES2 bind GL_TEXTURE_CUBE_MAP object B
两个 binding 相互不覆盖
```

以及：

```text
GLES1 修改 GL_TEXTURE_2D
不得影响同 unit 的 GLES2 GL_TEXTURE_CUBE_MAP binding
```

以及 cross-delete：

```text
delete B
只清除指向 B 的 binding
不得破坏同 unit 的 A
```

# 3. viewport / scissor query 返回 guest logical state

## 当前问题

在 supersample factor > 1 时：

```text
Guest glViewport(0, 0, 320, 480)
```

native ANGLE 实际可能收到：

```text
0, 0, 640, 960
```

当前代码已经把 logical viewport/scissor 保存进 `SharedGlState`，这是正确方向。

但 GLES query 路径仍可能直接读取 ANGLE native state。

这样：

```cpp
glGetIntegerv(GL_VIEWPORT)
glGetIntegerv(GL_SCISSOR_BOX)
```

可能向 guest 返回 scaled host state。

这是 host implementation detail 泄露。

### 要求

以下 guest query：

```text
GL_VIEWPORT
GL_SCISSOR_BOX
```

必须从统一 guest-visible shared state 返回 logical value。

无论 query 从：

```text
libGLESv1_CM.so
```

还是：

```text
libGLESv2.so
```

进入，结果必须一致。

### 原则

需要区分：

```text
Guest logical GL state
Native ANGLE implementation state
```

supersample scaling 只能发生在 native call boundary。

不得把 native scaled value重新作为 guest-visible authoritative state。

### Regression Test

必须使用：

```text
supersample_factor = 2
```

测试：

```text
GLES1 set viewport
GLES2 query viewport

GLES2 set scissor
GLES1 query scissor
```

预期必须返回调用时的 logical 数值，不得返回 x2 后的数据。

# 4. 删除高频 SharedGlState 全量复制

## 当前问题

部分 GLES2 mutation 当前为了做到：

```text
validate
native mutation
commit shadow
```

采用类似：

```cpp
auto next = context.Shared();
next.SetXXX(...);

frame.XXX(...);

context.Shared().SetXXX(...);
```

但是 `SharedGlState` 已经包含：

* transfer state
* texture bindings
* texture metadata
* generate-mipmap metadata
* framebuffer/renderbuffer
* capabilities
* raster state
* current program

其中还包含多个动态容器。

因此：

```text
glActiveTexture
glBindTexture
glBindFramebuffer
glBindRenderbuffer
glEnable/glDisable
```

这样的高频调用不应复制整个 shared state。

### 要求

消除 GL hot path 上对整个 `SharedGlState` 的 copy。

建议采用以下任一模式。

### 模式 A：Validate + Commit

```cpp
ValidateBindTexture(target, texture);

frame.BindTexture(target, texture);

CommitBindTexture(target, texture);
```

### 模式 B：窄 candidate

```cpp
const auto candidate = shared.PrepareBindTexture(...);

frame.BindTexture(...);

shared.Commit(candidate);
```

candidate 只能包含该 mutation 所需的少量标量。

### 模式 C：pure validation helper

若 setter validation 本身无副作用，则拆为：

```cpp
SharedGlState::ValidateXXX(...)
SharedGlState::SetXXX(...)
```

### 禁止

不得通过：

```cpp
auto copy = SharedGlState{};
```

或者：

```cpp
auto next = context.Shared();
```

继续复制所有 map/vector，只为预检一个 GL enum。

### Correctness Requirement

仍必须保持：

```text
validation
→ ANGLE mutation
→ shadow commit
```

不能为了性能变成：

```text
shadow mutation
→ ANGLE failure
→ shadow 已污染
```

# 5. GPU raw trace 不得继续竞争 boundary 全局 mutex

## 当前状态

raw trace ring 已经删除原先 hot path 中的：

* `std::string`
* argument map
* `std::to_string`
* 大量 heap allocation

这一部分保留。

当前仍存在的问题是：

```cpp
RecordGpuCall()
```

每个：

```text
EGL
GLES1
GLES1 extension
GLES2
```

调用都需要竞争 `AndroidBoundaryHle` 的公共 mutex。

这把锁同时保护其他 boundary state，例如：

* input queue
* frame publication
* GPU stats
* render target state

trace 不应扩大这些路径的锁竞争。

### 要求

将 raw trace synchronization 与 Android boundary 主 mutex 解耦。

最低接受方案：

```text
独立 trace mutex
```

推荐方案：

```text
fixed ring
atomic monotonically increasing write sequence/index
```

如果实现 lock-free ring 会明显增加复杂度，可以使用独立 mutex。

本 WU 的目标是：

> GL call recording 不得再获取 `AndroidBoundaryHle::mutex_`。

### Trace 行为必须保持

* capacity = 2048
* 满后覆盖最旧项
* `Trace(filter, limit)` 返回时间顺序正确
* filter 行为保持
* 参数格式化仍然发生在查询阶段
* descriptor/name 不重新复制到 raw entry

### Thread Safety

若改用独立 trace mutex：

```text
RecordGpuCall
Trace
```

必须只使用 trace mutex。

不得同时持有：

```text
boundary mutex
trace mutex
```

形成新的 lock-order dependency。

```text

+
```

---

## CStringLength

必须保留：

```text

```

```text

Read8
```


不能为了修其他问题恢复双重 `Validate + Write validate`。

  `Java_com_gameloft_android_GAND_GloftAPHP_GameRenderer_nativeInit` 中
  `CallStaticIntMethodV requires a valid class reference`。
- 未重新出现 mixed GLES buffer-state split、`required guest pointer is null` 或 VBO
  offset 0 被误判为 client pointer。

Correctness changes:

- `SharedGlState::active_texture` 成为 GLES1 texture matrix unit 的唯一权威来源，GLES2
  `glActiveTexture` 可直接选择后续 GLES1 texture matrix。
- texture binding 改为 `(texture unit,target)`，shared state 支持 2D/cube-map，GLES1
  target 校验仍保留在 GLES1 handler；base-format/generate-mipmap metadata 携带
  object/target，delete 清除 object 的全部 unit/target 引用。
- GLES1/GLES2 viewport/scissor query 从统一 logical shared state 返回，不泄露
  supersample native 坐标。

Performance changes:

- `glActiveTexture`、`glBindTexture`、`glBindFramebuffer`、`glBindRenderbuffer`、
  `glEnable`、`glDisable` 改为 validate → native call → in-place commit，不再复制整个
  `SharedGlState`；GLES1 matrix query 也不再复制 matrix state。
- `RecordGpuCall()` 与 `Trace()` 只使用独立 trace mutex；2048 项 raw ring 继续只保存
  descriptor id 与四个寄存器，boundary 主 mutex 不再参与记录。

Known remaining issue:

- Asphalt 6 的 `CallStaticIntMethodV` static class reference 发布/解析仍待后续独立 WU
  处理；本 WU 未修改 JNI。
