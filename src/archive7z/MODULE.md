# 模块：archive7z

构建 7-Zip 动态库（`lib7z.dylib`、`lib7z.so`、`7z.dll`），供游戏库只读解码 ZIP、RAR（旧格式解码器 RAR1–3 与 RAR5 解码器）和 7z。
7-Zip 26.06 固定于 `third_party/7zip`。使用上游 C/C++ 读取器、解码器和过滤器，
含 RAR3 的 E8、E8E9、Itanium、Delta、RGB、Audio 及 7z 的 BCJ/BCJ2 和分支过滤器。
RAR3 历史 Upcase 和任意 VM 程序超出上游 26.06 的过滤器范围。构建清单位于
[`cmake/SevenZip.cmake`](../../cmake/SevenZip.cmake)，不选汇编、压缩器、UI 或控制台。
ZIP 的写入接口保留只读构建所需的虚表入口，调用时拒绝。ZIP PPMd 共用编译单元中的编码函数
由链接器剔除。部分加密实现由上游处理器直接引用，用密码回调中止加密头识别，导入前拒绝加密条目。

[`archive7z.h`](archive7z.h) 是唯一导出 ABI，无 OGPlay 模块依赖。输入长度和按偏移读回调由调用方提供，
不经宿主路径访问。句柄按条目索引提供名称、大小、目录、加密与分卷标记。7z/RAR5 名称转 UTF-8，
ZIP/RAR4 同时保留旧编码字节和归档提供的 Unicode 名；上层决定 GBK 回退和路径安全规则。
调用方持有输入回调上下文直到关闭，同一归档句柄串行调用。流式按序解出一组索引，
solid 块只保留编解码器的字典和流缓冲。写入、字节进度和取消由回调传递。
C++ 异常、STL 和 COM 不跨 ABI，错误以状态码和 UTF-8 文本返回。分卷及加密拒绝，
不请求密码，不打开其他卷，不在动态库内创建任何目标文件。

[文件名补丁](patches/) 只增加 ZIP 和 RAR4 的名字属性，按处理器自身的解压索引取值。
CMake 将上游文件复制到构建目录后应用补丁，任一失败即停止配置。升级 7-Zip 时检查补丁上下文、
原始名字长度和字节、UTF-8 标志、Unicode 字段有效性及解压索引一致性，再比对 GBK、非 ASCII RAR
和反斜杠路径样本。同步核对解码构建清单、平台导出符号、许可证和附加许可。
